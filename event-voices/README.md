# 感想ひろば（体育大会・宿泊研修・文化発表会）

学校行事の感想（各105人分）を、その行事らしい背景の中で動き回る「イラスト人間」として
表示するページ。タップすると本人の感想がふきだしで出て、×で閉じる。ログイン等はなく、
**推測困難なURLだけを頼りにQRコードで配布する**運用（quiz/reflection-sheetと同じ信頼モデル）。
名前・出席番号は一切持たない＝誰の感想かは表示されない。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `taiikusai.html` | 体育大会版（グラウンド・トラック・テント／応援・走る・ぼーっと） |
| `taiikusai-data.js` | 体育大会の感想データ |
| `shukuhaku.html` | 宿泊研修版（波戸岬少年自然の家／5ゾーン：宿泊室・体育館・オリエンテーション室・憩いのひろば・ウォークラリー） |
| `shukuhaku-data.js` | 宿泊研修の感想データ（実データ・71人分） |
| `bunkasai.html` | 文化発表会（準備）版（ステージ＋緞帳・制作テーブル2か所／リハーサル・小道具運び・制作） |
| `bunkasai-data.js` | 文化発表会（準備）の感想データ（**サンプル**。準備が完了していないため実データ未反映） |
| `xlsx-to-data.py` | Googleフォーム等の集計xlsxから直接 `*-data.js` を生成するスクリプト（**推奨**） |
| `make-data.mjs` | 「1行1件」のテキストから `*-data.js` を生成するスクリプト（xlsxが使えない時用） |

現在 `taiikusai-data.js` / `shukuhaku-data.js` は「みんなの感想.xlsx」（体育大会・宿泊研修・
文化発表会の3問アンケート、71人分）から実データを流し込み済み。**文化発表会の準備**は、
準備自体がまだ完了していないため `bunkasai.html` はレイアウト確認用のサンプル（プレース
ホルダー文言）のまま。準備が終わって感想が集まったら、体育大会・宿泊研修と同じ手順で
すぐ実データに差し替えられる:
```bash
python3 xlsx-to-data.py "みんなの感想.xlsx" --col 4 --out bunkasai-data.js
```

## 実データを入れる（xlsxから・推奨）

Googleフォームの集計結果（1行＝1人の回答）をそのまま使う場合:
```bash
python3 xlsx-to-data.py "みんなの感想.xlsx" --col 3 --out taiikusai-data.js
python3 xlsx-to-data.py "みんなの感想.xlsx" --col 2 --out shukuhaku-data.js
```
`--col` は対象列の番号（1始まり。A列=1, B列=2, ...）。**必ずこの「行単位」の方法を使うこと**
——セル内に改行で複数人分の感想が結合されている行があり、単純に「1行ずつテキストに変換」する
方式（`make-data.mjs`）だと、そのセルが誤って複数人分としてカウントされ、人数が回答者数より
多くなってしまう（実際に76人・78人に水増しされたことがある）。

## 実データを入れる（テキストから・xlsxがない場合）

1. 集めた感想を「1行1件」のテキストファイルにする（例: `raw-comments.txt`）。
   このとき、1人の回答の中に改行が入らないよう先にセル内で改行を消しておくこと。
2. 変換スクリプトを実行:
   ```bash
   node make-data.mjs raw-comments.txt taiikusai-data.js
   node make-data.mjs raw-comments.txt shukuhaku-data.js
   ```

いずれの方法でも、人数は自動調整される（105でなくてよい）。反映後はブラウザで該当の
`.html` を開いて見た目を確認する。手動で `*-data.js` の配列を直接書き換えてもよい。

## ローカルで確認する

Claude Code なら `event-voices` プレビュー（`.claude/launch.json` 登録済み）で起動できる。
手動なら:
```bash
python3 -m http.server 8783 --directory event-voices
```
→ `http://localhost:8783/taiikusai.html` / `http://localhost:8783/shukuhaku.html` / `http://localhost:8783/bunkasai.html`

## 公開（デプロイ）

quiz/reflection-sheet と同じ仕組み。`public/` 配下は Vite のビルド時にそのまま `dist/` へ
コピーされ、GitHub Pages で配信される。

1. `public/event-voices/` に `event-voices/` 配下の完成版ファイル一式をコピー（実データ版を反映）
2. `npm run deploy`（vite build → gh-pages）
3. 公開URL: `https://dora9991.github.io/math-dialogue/event-voices/taiikusai.html`
   （宿泊研修は `.../shukuhaku.html`）
4. このURLからQRコードを作り、配布する（URLは校内限定で共有し、外部には出さない）

## 宿泊研修版の背景について

実際の研修先「唐津市波戸岬少年自然の家」で行った活動（キャンプファイヤーではなく、
2段ベッドの部屋・体育館・オリエンテーション室・憩いのひろば・ウォークラリー）をもとに、
敷地を見下ろす「キャンパスマップ」形式で描いている。奥の海・灯台・松林は立地イメージ
（波戸岬灯台をモチーフにしたもの、正確な再現ではない）。

5つのゾーンに105人を均等に振り分け、それぞれの活動に合わせて動かしている：
- **🛏 宿泊室**：2段ベッドと畳スペースのある部屋でのんびり（すべて実データ人物、ベッドの上の
  横向きの子はゾーンごとの演出用でタップ対象ではない）
- **🤸 体育館（長縄）**：長縄のロープの周りでジャンプ（バウンス）
- **📋 オリエンテーション室**：スクリーンに向かって机の列に整列（授業を受けている様子）
- **🗣️ 憩いのひろば**：砂利の広場にゆるく整列して集会
- **周回コース（ウォークラリー）**：敷地の周りをぐるっと歩いて回る

キャラクターのポーズ・アニメーションは3種類（バウンス／円形やコースに沿って動く／
その場でゆっくり揺れる）の使い回しで、ゾーンごとに配置パターンだけを変えている。

## 文化発表会（準備）版の背景について

ステージ（緞帳・スポットライト）と、左右2か所の制作テーブル（色紙・はさみ・のり）を配置した
講堂・体育館っぽい室内シーン。天井にはバンティング（三角旗）と「文化発表会」の看板。

3タイプに振り分けている（体育大会版と同じ3ポーズの使い回し）：
- **ステージでリハーサル**：発表・演技の練習（バウンス）
- **小道具・看板を運ぶ**：ステージと制作コーナーの間をぐるっと歩いて回る
- **制作コーナーで飾り・看板づくり**：左右のテーブル周りにのんびり集まる

準備の実態（何をどこで作っているか等）が分かれば、テーブルの中身やゾーン配置を
実際の準備内容に合わせて調整できる。

## さらに他の行事への展開

同じ仕組みで新しい行事のページを増やせる：

1. 既存の `.html` を複製
2. `<svg>` 内の背景を行事に合わせて描き直す
3. データファイル名とスクリプトの読み込み先を新ファイルに合わせて変更
4. 見出しのテキスト（`<h1>`）を差し替える

キャラクターの3タイプの動かし方（その場でバウンス／円形やコースに沿って動く／
ゆっくり揺れて静止）や、ふきだしの表示ロジックは共通なのでそのまま流用できる。

## 運用メモ

- 感想文はそのまま公開される。個人が特定できる固有名詞（友達の名前など）が
  紛れ込んでいないか、投入前に目視で確認するのが望ましい。
- レイアウトは日付を種にした疑似乱数で固定しているため、開くたびに配置が変わらない
  （毎回同じ「顔ぶれ」で安定して見える）。
- スマホでの閲覧を想定し、画面いっぱいに1シーンが収まるようレイアウトしてある
  （キャラクターが画面外に出て押せなくなることはない）。
