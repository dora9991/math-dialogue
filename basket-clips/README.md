# バスケ得点クリップ

バスケの試合動画から、**点を入れた場面**と**点を入れられた場面**を、それぞれ **5秒ずつ** 切り出すブラウザアプリです。
切り出した場面は、その場で続けて再生したり、1本の動画（MP4）に書き出したりできます。

「バスケ分析スタジオ」（個人スタッツ・場面別集計・アドバイスまで出す多機能版）の、**いちばんよく使う機能だけ**を取り出したシンプル版です。
得点を見つけるしくみ（解析エンジン）は、バスケ分析スタジオのものをもとに、リングに当たってから入る得点を落とさないよう、ゴールの追跡などを少し直したものです（下の「確かめたこと」）。

- インストール不要・通信なし。**動画はその端末の中だけで扱い、どこにも送りません**
- 公開ページ：**https://dora9991.github.io/math-dialogue/basket-clips/**
- 1ファイル版：`public/basket-clips/index.html`（ダブルクリックでも開けます）

## 使い方（4ステップ）

1. **🎬 動画を選ぶ**（スマホで撮った MP4 / MOV。ドラッグ＆ドロップでも）
2. **どっちの色が自分のチームか**を選ぶ（相手の色も。チーム名は入れなくても大丈夫）
3. **ゴールを教える**（最初の1回だけ。ゴール1つにつき、ドラッグ2回）
   - 映像の下のバーを動かして、ゴールが大きく映っている場面で止める → 「このゴールを指定する」
   - **バックボード（板）全体**をドラッグで囲む → 拡大されるので、**リングの左端から右端まで**なぞる
   - 「**動画のはじめに、このゴールを攻めているのは？**」で、自分か相手かを選ぶ（もう片方のゴールは自動で逆になります）
   - 1本の動画に前半と後半の両方が入っているときは、後半が始まる場面で止めて「いまの位置から後半にする」
4. **⚡ 得点シーンを探す** → 終わると、
   - **🏀 入れた**（自分の得点）／**🛡 入れられた**（相手の得点）のタブに、場面が並びます（小さな絵つき）
   - **▶** で1場面ずつ、**▶ 続けて再生** でまとめて見る
   - **🎬 動画にする** で1本の動画に（「入れた 3/12」などの文字入り。外せます）。各場面の **⬇** で、その場面だけの動画にもできます
   - 1場面の長さは「入った瞬間の **前4秒＋後1秒**＝5秒」。前・後の秒数は変えられます

同じ動画を開き直すと、色・ゴールの指定・結果・手直しが戻ります（このブラウザに保存。動画そのものは保存しません）。

### 直す・足す

| こんなとき | すること |
|---|---|
| 自分と相手が全部逆になっている | 「⇄ 入れ替える」（解析のやり直しは不要） |
| 1本だけチームが違う | その場面の「⇄ 入れられたへ／入れたへ」 |
| 得点ではなかった（笛で取り消し など） | 左のチェックを外す（再生・書き出しに入らない） |
| リングに当たって弾んでから入った得点が見つからない | 一覧の下の「🤔 入っていたかも？」を開く。そのチームが打って「外れ」と判定したシュートが並ぶので、▶ で確かめて「入っていた」（間違えたら一覧の「↩」で戻せる） |
| それでも見つからなかった得点がある | ボールがリングを通った瞬間で止めて「＋ 入れた」「＋ 入れられた」 |
| ハーフタイムのあとが逆になっている | 後半の始まりを設定する（解析のあとに「シュートが1本もない長い時間」を見つけると、ハーフタイムの候補として教えてくれます） |

## どちらのチームの得点か、の決め方

ボールが入った **ゴール** で決めます。バスケは前半・後半それぞれで、チームが攻めるゴールが決まっている（ハーフタイムで入れ替わる。延長は後半と同じ向き）ので、
「動画のはじめに、そのゴールを攻めていたチーム」と「後半の始まり」が分かれば、全部の得点のチームが決まります。

ユニフォームの色を映像から見分ける方法は使っていません。ゴール下では両チームの選手が重なり、照明や影で色も変わるため、得点ごとに色で判定すると間違えやすいからです。
選んだ色は、画面の表示（タブ・一覧・タイムラインの印）と、書き出す動画の文字の色に使います。

## できること・できないこと

- ○ ボールがリングを通った場面（得点）を、動画の最初から最後まで自動で探す。手持ちカメラのパン・ズームにもついていく
- ○ 三脚で固定してコート全体を撮った映像（360°・広角）にも対応（③ のチェックを入れる）
- △ **ゴールが画面に映っていない間の得点は見つけられません**（「＋」で手で足せます）。結果の下に、ゴールが映っていた時間の割合が出ます
- △ 審判の判定（笛で取り消された得点など）は分かりません。2点・3点・フリースローの区別もしません（どれも1場面）
- △ オレンジ〜茶色のボールを想定しています
- △ カメラ側のリングに当たって、ネットの手前（カメラ側）へ真下に落ちた外れは、映像ではネットを通ったように見えるので、「得点」と数えることがあります（合成映像で 7 本中 7 本）。入っていない場面が混ざっていたら、チェックを外してください
- △ リングに当たって弾んでから入った得点は、「外れ」と判定されることがあります。一覧の下の「🤔 入っていたかも？」で確かめて「入っていた」を押してください
- 書き出しは実際の長さの時間がかかります（10本なら1分ほど）。書き出し中はタブを表示したままにしてください

うまく見つけるための撮り方：ゴール（リングとネット）が画面に入るように、高めの位置から少し引きぎみに。横 1280 画素（720p）以上で。

## 確かめたこと（正直な範囲）

- **合成の試合映像**（バスケ分析スタジオのサンプル試合を 1280×720・30fps の動画にしたもの）で、画面を実際に操作して確認（`tests/e2e.cjs`）：
  - 150 秒の映像の得点 7 本（フリースロー1本を含む）を **7/7 で検出**、入れた／入れられたの振り分けも **7/7 正しい**、正解にない得点 0
  - 前半の頭＋後半の頭をつないだ映像で、後半の始まりを設定すると、前半・後半の得点 7 本がすべて正しいチームに分かれる
  - WebM（直接読めない形式）は、再生しながら探す互換モードで同じように見つかる
  - 続けて再生（5秒たつと次の場面へ）、書き出した動画の長さ・中身が動いていること、保存ボタン、開き直したときに結果が戻ること
- **リングに当たってから入る／外れるシュート**（`tests/rim-check.cjs`）：本物の試合で「リングに当たってゴタゴタしてから入った得点」を見落とすと分かったため、
  サンプル試合のシュートの一部を、リングで弾んでから入る形（手前・奥・転がる・1周近く回る・ボード）／弾んで外れる形に変え、ゴールの見え方も本物に近づけた（輪の中のボールは手前のリングとネットの陰・リングが揺れる）800 秒の映像で確かめた：

  | | 得点 35 本 | 外れ 32 本 |
  |---|---|---|
  | もとのエンジン | 31 本を得点と判定（見落とし 4） | 見つからない 6 本・得点と誤る 6 本 |
  | いまのエンジン | **35 本すべて**を得点と判定 | 見つからない **0 本**・得点と誤る 7 本（すべて「カメラ側のリングに当たってネットの手前に落ちた」形） |

  見落とし 4 本の原因は、リングで弾んだことそのものではなく、**ゴールの追跡**だった：ゴールが画面の端から出たあと、探し直しが「リングが画面の外になる位置」の少し似ているだけの物を捉え、
  そこではリングの色で確かめられないので、40 秒間そこに張り付き、戻ってきた本物のゴールを探し直さなかった（その間の得点を落とす）。
  画面の外になる位置は、よく合うときだけ捉え、長く張り付いたら手放して探し直すようにした（`auto.js` の TH_ACQ_EDGE・TH_KEEP_EDGE）。
  あわせて、ボールがリングに重なって輪の色が崩れたコマも捨てない（OCCL_MAX）、ネットの下から現れたボールの条件を少し広げた（bornYMax・bornGap）。
- 実際の試合の動画での精度は、解析エンジンのもとになった「バスケ分析スタジオ」で測ったものがあります（体育館の2階から iPhone 手持ちで撮った 11 分半の試合で、得点 9/9）。**上の直しを入れたあとの版は、まだ本物の試合動画で通していません。** 見落としや誤りがあれば、「🤔 入っていたかも？」「＋」やチェックで直せます
- 確認したブラウザ：Chromium（Playwright 同梱・画面なし）。Safari・iPhone では未確認（エンジンと動画まわりの部品は、バスケ分析スタジオで Safari のエンジンでも確認ずみのもの）

## ファイル構成

```
basket-clips/
  index.html        開発用（js/ と css/ を読み込む）
  build.mjs         1ファイル版を作る → public/basket-clips/index.html
  css/app.css
  js/core.js        名前空間（BS）・時刻の書式など
  js/vision.js      ┐
  js/auto.js        │ 解析エンジン（バスケ分析スタジオ 9331ba6 がもと。ゴールの追跡・ボール・得点の判定。追跡などを一部直した）
  js/auto-engine.js │ （Worker でも画面側でも同じコードが動く）
  js/mp4.js         ┘ MP4 / MOV の読み取り（こちらでは VP9・AV1 の MP4 も読めるように足した）
  js/clips.js       得点 → 入れた／入れられた・5秒の区間・ハーフタイムの提案（DOM なし）
  js/store.js       ブラウザへの保存（動画ごと）
  js/media.js       動画の再生（Safari の癖への対策つき。バスケ分析スタジオから）
  js/export.js      動画の書き出し（Canvas ＋ MediaRecorder）
  js/ui.js          画面の部品
  js/app.js         画面（色・ゴールの指定・解析の実行・結果・続けて再生）
  tests/unit.cjs    回帰テスト（node だけで動く）
  tests/e2e.cjs     画面を通した確認（Playwright の Chromium）
  tests/rim-check.cjs   リングに当たってから入る／外れるシュートを、形ごとに数える（合成映像で。判定の調整用）
  tests/rim-replay.cjs  rim-check.cjs が保存したコマごとの記録を、シュートの判定にかけ直す（動画を読み直さずに試せる）
  tests/node-run.cjs    動画の一部を ffmpeg で読み、解析エンジンを node でそのまま動かす（trace でコマごとのゴールの追跡を表示）
  tests/tools/make-video.cjs  テスト用の合成試合動画（VP9 の MP4）と正解を作る
  tests/tools/fixtures/       合成映像の描画（バスケ分析スタジオのサンプル試合。テストだけで使う）
                              rimplay.js：シュートの一部を、リングで弾んでから入る／外れる形にする（ゴールの見え方も本物に近づける）
```

## 開発

```bash
node basket-clips/build.mjs              # 1ファイル版を作り直す（公開するのはこれ）
node basket-clips/tests/unit.cjs         # 回帰テスト（44件。ffmpeg があれば MP4 の読み取りも）
node basket-clips/tests/e2e.cjs built    # 画面を通した確認（44件・約5分。初回は合成動画を作るので +3分）
node basket-clips/tests/e2e.cjs dev      # 開発版で同じ確認
node basket-clips/tests/server.cjs       # 開発用サーバー → http://127.0.0.1:5192/

# リングに当たるシュートの見分け（合成映像を作って → 形ごとに数える。800 秒の動画で、作るのに約6分・調べるのに約5分）
node basket-clips/tests/tools/make-video.cjs /tmp/rim800.mp4 0-800 30 4 rim
node basket-clips/tests/rim-check.cjs /tmp/rim800.mp4 dev /tmp/rim800.log.json      # OCCL=0 で、リングが隠れたコマを使わない（もとの動き）
node basket-clips/tests/rim-replay.cjs /tmp/rim800.log.json /tmp/rim800.mp4          # 判定だけをかけ直す（数秒）
```

- e2e は Playwright（`npm i -g playwright` など）と、その Chromium を使います。合成動画は `WORK`（既定は一時フォルダの `basket-clips-e2e/`）に置き、次から使い回します。
- テストの Chromium は H.264 を扱えないため、合成動画は VP9 の MP4 にしています。ふつうの Chrome・Edge・Safari では、スマホの H.264 / HEVC の動画を同じように直接読みます。
- 解析エンジン（`vision.js` `auto.js` `auto-engine.js` `mp4.js`）を直すときは、バスケ分析スタジオと同じ直しを入れると、両方がそろったままになります。
  いまは `auto.js` に、バスケ分析スタジオ（9331ba6）にまだない直しが入っています：画面の外になる位置のゴールの捉え方（TH_ACQ_EDGE・TH_KEEP_EDGE・OUT_MAX）、
  リングが隠れたコマを捨てない（OCCL_MAX・OCCL_NCC・設定の rimOcclusion）、ネットの下から現れたボールの条件（bornYMax・bornGap）。向こうにも同じ直しを入れると、そろいます。

## 公開

`public/basket-clips/index.html` は、ふだんの `npm run deploy`（Vite のビルド → gh-pages）で一緒に公開されます。
アプリだけを直したときは、`node basket-clips/build.mjs` のあと、`gh-pages` ブランチの `basket-clips/index.html` を差し替えても公開できます。
