# バスケ得点クリップ

バスケの試合動画から、**点を入れた場面**と**点を入れられた場面**を、それぞれ **5秒ずつ** 切り出すブラウザアプリです。
切り出した場面は、その場で続けて再生したり、1本の動画（MP4）に書き出したりできます。

「バスケ分析スタジオ」（個人スタッツ・場面別集計・アドバイスまで出す多機能版）の、**いちばんよく使う機能だけ**を取り出したシンプル版です。
得点を見つけるしくみ（解析エンジン）は、バスケ分析スタジオのものをもとに、リングに当たってから入る得点・ゴールの裏から撮った映像に強くなるよう、ゴールの追跡などを直したものです。
ゴールの指定は、動画を開くと自動で探します（見つからないときだけ、リングをタップ）。くわしくは下の「確かめたこと」。
得点は **「入った」「🤔 たぶん入った（確認して）」「外れ」の3段**に分けます。ボールの動きと**ネットの揺れ**の両方で確かめられたものだけを「入った」にし、
片方しか確かめられなかったものは、人が ▶ で見て決めます。**📋 記録**のタブでは、ゴールに来たシュートを全部（外れも）並べ、
2点・3点・フリースロー、打った人・リバウンドを取った人の番号を付けて、集計と CSV にできます。

**「バスケ タップ記録」で試合中にタップした記録**（📲 タップ記録）を読み込むと、記録した場面（シュート・リバウンド・パスミスなど）を、**チーム・プレー・選手ごと**に切り出すこともできます（下の「📲 タップ記録（バスケ タップ記録）から切り出す」）。
**「スポーツ タップ記録」**（`sports-tap/`。サッカー・バレー・フットサル・ハンドボール・テニス・野球・ラグビー・水泳）の記録も、同じように読み込めます（下の「📲 スポーツ タップ記録から切り出す」）。

- インストール不要・通信なし。**動画はその端末の中だけで扱い、どこにも送りません**
- 公開ページ：**https://dora9991.github.io/math-dialogue/basket-clips/**
- 1ファイル版：`public/basket-clips/index.html`（ダブルクリックでも開けます）

## 使い方（4ステップ）

1. **🎬 動画を選ぶ**（スマホで撮った MP4 / MOV。ドラッグ＆ドロップでも）
2. **どっちの色が自分のチームか**を選ぶ（相手の色も。チーム名は入れなくても大丈夫）
3. **ゴールを確かめる**（動画を開くと、**ゴールを自動で探します**。数秒〜十数秒）
   - 見つけたゴールは、拡大した絵に **黄色の線（リング）** を重ねて見せます。リングにぴったり重なっていれば、そのままで OK
   - 「**動画のはじめに、このゴールを攻めているのは？**」で、自分か相手かを選ぶ（もう片方のゴールは自動で逆になります）
   - 見つからない・ずれているときは「このゴールを教える」／「ちがう・直す」→ 映像を、そのゴールが映っている場面で止めて、**リング（輪）のあたりをタップ**。
     リングを見つけられないときは拡大されるので、**リングの左端から右端まで**なぞる（バックボードを囲む必要はありません）
   - ゴールの裏（バックボードの斜め後ろ）から撮った映像でも同じです（ガラスのボード越しに見えるリングをタップ）
   - 1本の動画に前半と後半の両方が入っているときは、後半が始まる場面で止めて「いまの位置から後半にする」
4. **⚡ 得点シーンを探す** → 終わると、
   - **🏀 入れた**（自分の得点）／**🛡 入れられた**（相手の得点）のタブに、場面が並びます（小さな絵つき）
   - **▶** で1場面ずつ、**▶ 続けて再生** でまとめて見る
   - **🎬 動画にする** で1本の動画に（「入れた 3/12」などの文字入り。外せます）。各場面の **⬇** で、その場面だけの動画にもできます
   - 1場面の長さは「入った瞬間の **前4秒＋後1秒**＝5秒」。前・後の秒数は変えられます
   - タブの下に **🤔 たぶん入った（確認して）** が出たら、▶ で見て「入った」か「外れ」を押す（「入った」にすると、上の一覧に入ります）
   - はっきりした外れは、得点のタブには出しません（**📋 記録** で見られます）

### 「入った」「たぶん入った」「外れ」の分け方

| 段 | どんなとき | 画面 |
|---|---|---|
| **入った** | ボールがリングの内側を下へ抜け、**ネットも大きく揺れた**（両方で確かめられた） | 得点のタブの一覧（再生・書き出しに入る） |
| **🤔 たぶん入った** | 片方しか確かめられなかった：① ボールは見えないが、ネットが大きく揺れた ② リングに来たあと、ネットが揺れた（リングで弾んでから入ったかもしれない） ③ ボールは通ったが、ネットがあまり揺れなかった（リングの手前に落ちた外れかもしれない） | 得点のタブの下に並ぶ。人が ▶ で見て「入った」「外れ」 |
| **外れ** | ボールがリングまで来たが、ネットは揺れなかった | 得点のタブには出さない。📋 記録 で見られる（「入った」に直すこともできる） |

「ネットが大きく揺れた」とみなすのは：ネットのあたりの動き（ボールらしい形を除いた分）が急に大きくなり、0.4〜2 秒で収まり、ネットの左右はあまり動いていないとき
（選手の体がネットの前を通ると、まわりも一緒に動く。カメラを大きく振った直後の、ゆっくり増えてなかなか減らない動きも使わない）。

### 📋 記録（シュート・リバウンド・2点/3点/FT）

ゴールに来たシュート（入った・たぶん入った・外れ）を、時刻の順に全部並べます。1行ずつ ▶ で見て、
- 結果（入った／外れ。「たぶん入った」はここでも決められる）
- 種類（2点・3点・FT）と、打った人の番号
- 外れなら、リバウンドを取ったチームと番号（打ったチームと同じならオフェンスリバウンド）

を付けると、下に **集計**（チームごとの得点・2点/3点/FT の成功数と本数・リバウンド、番号ごとの成績）が出ます。どれも付けなくてかまいません（種類のない成功は 2 点として数えます）。
「▶ 上から続けて見る」で、シュートを1本ずつ続けて再生（外れはリバウンドが見えるよう、後ろを長めに）。見つからなかったシュートは「＋ 入った」「＋ 外れ」で足せます。
「⬇ CSV で保存」で、1本1行の表（Excel でそのまま開ける）にできます。

同じ動画を開き直すと、色・ゴールの指定・結果・手直しが戻ります（このブラウザに保存。動画そのものは保存しません）。

### 直す・足す

| こんなとき | すること |
|---|---|
| 自動で見つけたゴールがちがう・見つからない | ③ の「ちがう・直す」／「このゴールを教える」→ リングのあたりをタップ（だめなら、リングをなぞる） |
| 自分と相手が全部逆になっている | 「⇄ 入れ替える」（解析のやり直しは不要） |
| 1本だけチームが違う | その場面の「⇄ 入れられたへ／入れたへ」 |
| 得点ではなかった（笛で取り消し など） | 左のチェックを外す（再生・書き出しに入らない） |
| 入っていたのに一覧にない | まず一覧の下の「🤔 たぶん入った」を見て、▶ で確かめて「入った」（間違えたら一覧の「↩」で戻せる）。なければ 📋 記録 の「外れ」の行を「入った」に |
| それでも見つからなかった得点がある | ボールがリングを通った瞬間で止めて「＋ 入れた」「＋ 入れられた」（📋 記録 の「＋ 入った」でも同じ） |
| ハーフタイムのあとが逆になっている | 後半の始まりを設定する（解析のあとに「シュートが1本もない長い時間」を見つけると、ハーフタイムの候補として教えてくれます） |

## 📲 スポーツ タップ記録から切り出す

「スポーツ タップ記録」（8種目）で撮影しながら記録した動画も、「🎬 場面を切り出す」から、時刻あわせなしで開けます（`?tapgame=…&tapvideo=…&tapapp=stap`。動画は IndexedDB `stap-media` から読む）。記録のファイル（JSON）を「📲 タップ記録を読み込む」で開くこともできます。

- 書き出した記録に、記録ごとの呼び名（`text`：「致遠館 #10 たけし ゴール」）と場面の呼び名（`when`：「前半 23:41」「3回表」「第2セット」）、種類ごとに場面にするか（`types[].scene`）が入っているので、ここでは種目のルールを知らなくてよい作り（`js/taplog.js` の `parseSports`）
- 絞り込みの「プレー」は、その記録にある種類（ゴール・シュート・コーナーキック、アタック・ブロック、単打・三振 など）。得点は記録アプリの書き方（「1 − 1（PK 4−3）」「セット 2−1」など）
- 「この端末で記録した試合」には、スポーツ タップ記録で試合を終えた（または「🎬 場面を切り出す」を押した）試合も並びます（`stap:export:<id>`）
- 得点の場面を動画から自動で探すのは、バスケだけです

## 📲 タップ記録（バスケ タップ記録）から切り出す

[バスケ タップ記録](https://dora9991.github.io/math-dialogue/basket-tap/)（`basket-tap/`）で、試合を見ながら「だれが・何をしたか」をタップしておくと、
その記録の場面を、この動画から切り出せます。ゴールの指定や解析はいりません。

1. **🎬 動画を選ぶ** と **📲 タップ記録を読み込む**（どちらが先でも。記録は「書き出す」→「記録のファイル（JSON）」。同じ端末・同じブラウザで記録したなら、ファイルにしなくても「この端末で記録した試合」から選べます。動画と一緒にドロップしても読み込めます）
2. **③ 記録と動画の時刻を合わせる**（記録の時刻は「スタートを押してからの秒」なので、動画のどこがその時刻かを1か所決める）
   - **📅 撮影時刻から合わせる（目安）**：動画のファイルに撮影の時刻が入っていれば、記録のスタートの時刻と比べて、自動で合わせます（iPhone は撮影を始めた時刻 `com.apple.quicktime.creationdate`、ほかは作成時刻 `mvhd` から動画の長さを引いた時刻）。カメラと記録した端末の時計のずれ（ふつう1〜2秒）だけ、ずれることがあります
   - **✋ 手で合わせる**：記録の1つ（ふつうは「スタート」＝ティップオフ）を選び、動画をその瞬間で止めて「⏱ この瞬間が、選んだ記録」
   - **⚡ 自動で探した得点と照らし合わせる**：「得点を自動で探す」の結果があれば、記録の得点と重なるように合わせます
   - 合わせたあと、ずれていたら「−1秒／−0.5秒／+0.5秒／+1秒」で全部をずらす。1つの場面だけなら、その場面の「⌖」（いまの映像の位置を、その記録の瞬間にする）
   - 撮影を途中で止めた動画・つないだ動画は、止めた後の場面で「＋ ここでも合わせる」（その点より後ろの記録に効きます）
3. **④ 場面を選んで、見る・動画にする**
   - 絞り込み：**チーム**（自分・相手）・**プレー**（得点・シュート失敗・リバウンド・パスミス・ミス・スティール・アシスト・ブロック・ファウル・★）・**選手**（#7 など）。プレーは「すべて」から押すと、それだけになります
   - 記録の画面の下の「パスミス」「★ あとで見る」で記録したもの（だれのかを決めない「チームなし」）は、「パスミス」「★」として場面になります。チームの絞り込みでは外しません（どちらのチームか決めていないため）。一覧では灰色
   - 1場面の長さは「タップした瞬間の **前 6 秒＋後 2 秒**」（人がタップするのは、プレーの 1〜2 秒あとなので、前を長めに）。変えられます
   - ▶ で1場面ずつ、**▶ 続けて再生**、**🎬 動画にする**（「#7 たけし 2P成功」などの文字入り。外せます）、各場面の ⬇ でその場面だけ
   - 続けて起きたプレー（シュート失敗 → リバウンド など）で場面が重なるときは、1つの場面につなぎます（同じところを2回見せない。つなぐのは 24 秒まで）
   - 動画に入っていない時間の記録（撮影していない時間・ほかの動画の時間）は、数だけ知らせます。クォーターごとに分けて撮った動画なら、動画ごとに同じ記録を読み込んで、それぞれ時刻を合わせます

**📹 撮影しながら記録した動画**（バスケ タップ記録の「📹 撮影しながら記録する」）は、時刻あわせがいりません。
- 同じ端末なら、タップ記録の「🎬 場面を切り出す」から、または「📲 タップ記録を読み込む」→ その試合の「📹 動画1を記録と一緒に開く」で、動画と記録がそろって開き、時刻もぴったり合っています（動画は、タップ記録が保存した IndexedDB `btap-media` から読む。`js/tapvideo.js`）
- 保存した動画のファイルと記録のファイルを、ほかの端末で開いたときも、記録に入っている動画の情報（ファイル名・長さ・録画を始めた時刻）で見分けて、自動で合わせます（③ に「📹 撮影しながら記録した動画なので、自動でぴったり」）

記録・時刻あわせ・絞り込みは、動画ごとにこのブラウザに保存されます（同じ動画を開き直すと戻ります）。
「得点を自動で探す（映像の解析）・チームの色」は、たたんだ中にそのまま使えます。

## どちらのチームの得点か、の決め方

ボールが入った **ゴール** で決めます。バスケは前半・後半それぞれで、チームが攻めるゴールが決まっている（ハーフタイムで入れ替わる。延長は後半と同じ向き）ので、
「動画のはじめに、そのゴールを攻めていたチーム」と「後半の始まり」が分かれば、全部の得点のチームが決まります。

ユニフォームの色を映像から見分ける方法は使っていません。ゴール下では両チームの選手が重なり、照明や影で色も変わるため、得点ごとに色で判定すると間違えやすいからです。
選んだ色は、画面の表示（タブ・一覧・タイムラインの印）と、書き出す動画の文字の色に使います。

## できること・できないこと

- ○ ボールがリングを通った場面（得点）を、動画の最初から最後まで自動で探す。手持ちカメラのパン・ズームにもついていく
- ○ ゴールの指定を自動で探す（オレンジの細い輪＝リングと、その真下の白い網目＝ネットを手がかりに。ボード・リングの色や形が少し違っても探せる）
- ○ ゴールの裏（バックボードの斜め後ろ）から撮った映像にも対応（ガラスのボード越しにリングが見えていれば）
- ○ 三脚で固定してコート全体を撮った映像（360°・広角）にも対応（③ のチェックを入れる）
- △ **ゴールが画面に映っていない間の得点は見つけられません**（「＋」で手で足せます）。結果の下に、ゴールが映っていた時間の割合が出ます
- △ 審判の判定（笛で取り消された得点など）は分かりません。2点・3点・フリースローの区別、打った人・リバウンドを取った人も、自動では分かりません（📋 記録 で、見ながら付けられます）
- △ オレンジ〜茶色のボールを想定しています
- △ ゴールの自動検出は、リングがオレンジ（色相 9〜37°くらい）で、幅 16 画素以上に映っているときだけ。赤すぎる・色あせたリング、小さく映ったゴールは見つからないことがあります（そのときはリングをタップ／なぞる）
- △ ゴールの裏から撮ると、手前のゴールのリングに、ボードの下の縁・取り付け金具・吊り金具が重なり、ボールが「リングの上で見えて、次はネットの下」になります。得点の見落としが、横から撮るより少し増えます（下の「確かめたこと」）。手前のゴールの得点は「🤔 たぶん入った」に入ることが多いです
- △ 不透明な（白い板の）バックボードを真後ろから撮ると、リングが板に隠れて見えないので、得点は見つけられません（斜め後ろから、リングが見える位置で）
- △ カメラ側のリングに当たって、ネットの手前（カメラ側）へ真下に落ちた外れは、ボールの動きだけではネットを通ったように見えます。ネットがあまり揺れないので「🤔 たぶん入った」に回ります（合成映像で 10 本中 10 本。以前は「入った」に混ざっていた）
- △ ネットの揺れは、選手の手がネットに触れた・ボールがネットの後ろを横切った、などでも起きます。「たぶん入った」に、シュートでない場面が混ざることがあります（合成映像 31 分で 4 本）。「外れ」を押してください
- △ 直接読めない形式（WebM など）は、再生しながら探す互換モードになります。間に合ったコマだけを調べるので、実行のたびに結果が少し変わり、見落としが増えることがあります（スマホの MP4・MOV は、全部のコマを調べるので変わりません）
- 書き出しは実際の長さの時間がかかります（10本なら1分ほど）。書き出し中はタブを表示したままにしてください

うまく見つけるための撮り方：ゴール（リングとネット）が画面に入るように、高めの位置から少し引きぎみに。横 1280 画素（720p）以上で。
ゴールの裏から撮るときは、真後ろより **斜め後ろ** の、ガラスのボード越しにリングとネットが見える位置から（2階のギャラリーの隅など）。
体育館の横の壁に練習用のゴールがあると、それを自動で拾うことがあります。③ の絵で確かめて、違っていたら「ちがう・直す」。
ズームや向きで見え方が大きく変わると、同じゴールが A・B の両方に選ばれることもあります（③ の2枚の絵が同じゴールになる）。そのときも、片方を「ちがう・直す」で、もう一方のリングをタップ。

## 確かめたこと（正直な範囲）

- **3段の判定とネットの揺れ**（合成映像 6 本・計 31 分。`tests/tier-check.cjs`）：本物の試合（ゴール裏から撮った 3 分ほどの動画）で、得点 2 本を1本も見つけられなかったことから。
  原因は本物の動画を見ないと分からないため、「ボールを見失っても、ネットの揺れで気づける」ように手がかりを足し、判定を3段にした。

  | 映像 | 得点 → 入った／たぶん入った／外れ・見つからない | 外れ → たぶん入った | シュートでない所 → たぶん入った |
  |---|---|---|---|
  | 横の2階・800 秒（リングで弾むシュート入り） | 35 本 → 35／0／0 | 32 本のうち 7（すべて、リングの手前に落ちた外れ） | 2 |
  | 横の2階・300 秒（同上） | 11 本 → 11／0／0 | 12 本のうち 3（同上） | 0 |
  | 横の2階・150 秒・ボールの動きぶれ入り | 7 本 → 7／0／0 | 5 本のうち 0 | 0 |
  | ゴール裏の2階の隅・300 秒 | 11 本 → 7／2／2 | 12 本のうち 0 | 0 |
  | ゴール裏の2階の隅・150 秒 | 7 本 → 4／2／1 | 5 本のうち 0 | 0 |
  | ゴール裏のフロア・150 秒 | 7 本 → 4／2／1 | 5 本のうち 0 | 2 |

  - 「入った」に、外れが1本も混ざらなくなった（以前は、リングの手前に落ちた外れを得点と誤るものが、横からの映像で 10 本混ざっていた。いまは「たぶん入った」に回る）
  - **ボールがまったく見えなかったとしても**（判定が何も出さなかったとしても）、ネットの揺れだけで、得点 78 本のうち 69 本（88%）を「たぶん入った」に拾えた（外れを拾ったのは 0 本、シュートでない所 4 本）。横からの映像では 53 本すべて、ゴール裏・フロアから撮った映像の奥のゴールも 16 本すべて。**手前のゴール（ボードの裏から見るゴール）は 9 本のうち 0 本**
  - 暗い体育館のつもりで、ボールの動きぶれ（シャッター 1/30 秒）を入れた映像でも、得点 7 本をすべて「入った」にできた（ぶれだけでは、本物で 0 本だった理由にならない）
  - 手前のゴール（ボードの裏から見るゴール）は、カメラが動き続け、ネットの向こうを選手が行き来するので、ネットの揺れをはっきり測れない。
    ボールがリングを通るのが見えていれば「たぶん入った」に出る（9 本のうち 5 本）が、ボールが見えないときにネットの揺れだけで拾うのは、いまはできない。ここがいちばんの弱点
  - **本物の映像では、まだ確かめていません**（ネットの色・太さ・揺れ方、照明、カメラの揺れが違う）

- **ゴールの自動検出とゴール裏からの撮影**（合成映像。`tests/goalfind-check.cjs`・`tests/e2e.cjs`）：本物の映像が手元にないため、
  テスト用の合成映像に、カメラの場所を3つ用意して確かめた（横の2階：もとの映像／ゴール裏の2階の隅：手前のゴールはガラスのボード越しに裏から見る。
  カメラはボールを追ってパン・チルト・ズーム／ゴール裏のフロア：手前のゴールを下から見上げる）。体育館の壁・2階の観客・赤いステージの幕・
  赤い得点板・天井から吊るすゴールも描いてある。

  | カメラの場所 | 1コマずつ、映っているリングを見つけた割合 | ゴール2つ | 自動で見つけたゴールのまま、画面の流れで解析（得点） |
  |---|---|---|---|
  | 横の2階 | 100% | 正しい | 150 秒：7/7・300 秒（リングで弾む得点入り）：11/11 |
  | ゴール裏の2階の隅 | 94% | 正しい | 150 秒：6〜7/7（同じ場面を2回動画にしたもので 7/7 と 6/7。落としたのは手前のゴールの1本）・300 秒：8/11（1本はゴールが画面から外れていた場面、1本は「外れ」と判定、1本はボードに当たって入った得点を見落とし） |
  | ゴール裏のフロア | 91% | 正しい | 150 秒：7/7 |

  コマの取り方は、動画を開いたときと同じ（150 秒の動画なら 25 コマ、300 秒なら 36 コマ）。取り方を変えて（150 秒から 40 コマ）試すと、
  ゴール裏の2階の隅で、奥のゴールが見え方の違いで2つのまとまりに分かれ、両方が選ばれて、手前のゴールが選ばれないことが1回あった
  （③ の2枚の絵が同じゴールになるので分かる。片方を「ちがう・直す」で、もう一方のリングをタップすれば直る）。
  リングのそばをタップしたときに、そのリングを正しく見つけた割合は 92〜96%（タップの位置を、リングの中心からリング幅の 0.8 倍までずらして試した）。
  見つけたリングの幅は、正解の 1.00〜1.07 倍（中央値。少し大きめに当てはまる癖があったので、タップのときは、同じ中心で少し小さい楕円のほうが輪に合えば、そちらにする）。
  ゴール裏から撮った映像で分かって直したこと（`auto.js`）：
  - 手前のゴールを1倍の広い画角で撮ると、カメラを振るだけで、画面の端のゴールは大きく・真ん中では小さく見える（0.3 秒で2割縮む）。
    ゴールの大きさの追従を、2コマに1回・1段から、毎コマ・速いときは2段までにした（正しいゴールの指定で、得点 7 本のうち 5 本 → 6〜7 本）
  - 2つのゴールは同じ形・同じ色なので、見失ったゴールを探し直すときに、もう片方のゴールを捉えることがある。2つの追跡が同じ場所を捉えたら片方を取り消す。
    1 秒以内に両方のゴールで出た「得点」は、確かさの低いほうを外す
  - 追跡の見本の枠は、リングのまわりで縦と横の模様がはっきりした所（ボードの枠など）を選ぶ。床と壁の境の横線ばかりの所を見本にすると、大きさの追従が流れた
  - 自動検出で見本にするコマは、画面の真ん中に近いもの（画面の端では、広い画角のゆがみで見え方が変わり、ほかの位置で合わなくなった）
  - 再生しながら探す互換モード（WebM など）では、コマの間隔が不ぞろい（飛ぶ）なので、大きさの追従は、もとの動き（2コマに1回・1段ずつ）のまま
    （毎コマ・2段までにすると、飛んだコマの間に大きさがずれて、別の所に張り付くことがあった）

  試してやめたこと：板の見本を、いまの見え方に少しずつ寄せる更新。ゴール裏では効き目がなく、横から撮った映像で、ゴールA・B の取り違えが増えた。
  **どれも合成映像での結果です。本物のゴール裏からの映像では、まだ確かめていません**（リングの色・ボードの形・吊り金具・照明が違うので、数字は変わるはずです）。

- **合成の試合映像**（バスケ分析スタジオのサンプル試合を 1280×720・30fps の動画にしたもの）で、画面を実際に操作して確認（`tests/e2e.cjs`）：
  - 動画を開くとゴールを2つ自動で見つけ（左右1つずつ・リングの位置と大きさが正解と合う）、**そのまま**探して、150 秒の映像の得点 7 本（フリースロー1本を含む）を
    **7/7 で検出**、入れた／入れられたの振り分けも **7/7 正しい**、正解にない得点 0
  - ゴールを手で教える：リングのタップ（中心のずれ 1 画素ほど）・リングのなぞり（小さいと拡大される）
  - 前半の頭＋後半の頭をつないだ映像で、後半の始まりを設定すると、前半・後半の得点 7 本がすべて正しいチームに分かれる
  - ゴール裏の2階の隅から撮った映像で、手前・奥のゴールを自動で見つけ、そのまま探して得点を正しいチームで見つける（7 本のうち 1 本までの見落としは許す確認）
  - WebM（直接読めない形式）は、再生しながら探す互換モードで同じように見つかる
  - 続けて再生（5秒たつと次の場面へ）、書き出した動画の長さ・中身が動いていること、保存ボタン、開き直したときに結果が戻ること
- **リングに当たってから入る／外れるシュート**（`tests/rim-check.cjs`）：本物の試合で「リングに当たってゴタゴタしてから入った得点」を見落とすと分かったため、
  サンプル試合のシュートの一部を、リングで弾んでから入る形（手前・奥・転がる・1周近く回る・ボード）／弾んで外れる形に変え、ゴールの見え方も本物に近づけた（輪の中のボールは手前のリングとネットの陰・リングが揺れる）800 秒の映像で確かめた：

  | | 得点 35 本 | 外れ 32 本 |
  |---|---|---|
  | もとのエンジン | 31 本を得点と判定（見落とし 4） | 見つからない 6 本・得点と誤る 6 本 |
  | いまのエンジン | **35 本すべて**を得点と判定 | 見つからない **0 本**・得点と誤る 7 本（すべて「カメラ側のリングに当たってネットの手前に落ちた」形） |

  見落とし 4 本の原因は、リングで弾んだことそのものではなく、**ゴールの追跡**だった：ゴールが画面の端から出たあと、探し直しが「リングが画面の外になる位置」の少し似ているだけの物を捉え、
  そこではリングの色で確かめられないので、40 秒間そこに張り付き、戻ってきた本物のゴールを探し直さなかった（その間の得点を落とす）。
  画面の外になる位置は、よく合うときだけ捉え、長く張り付いたら手放して探し直すようにした（`auto.js` の TH_ACQ_EDGE・TH_KEEP_EDGE）。
  あわせて、ボールがリングに重なって輪の色が崩れたコマも捨てない（OCCL_MAX）、ネットの下から現れたボールの条件を少し広げた（bornYMax・bornGap）。
- 実際の試合の動画での精度は、解析エンジンのもとになった「バスケ分析スタジオ」で測ったものがあります（体育館の2階から iPhone 手持ちで撮った 11 分半の試合で、得点 9/9）。**上の直しを入れたあとの版は、まだ本物の試合動画で通していません。** 見落としや誤りがあれば、「🤔 たぶん入った」「📋 記録」「＋」やチェックで直せます
- **📲 タップ記録（バスケ タップ記録）から切り出す**（`tests/unit.cjs`・`tests/e2e-log.cjs`）：記録アプリの `core.js` で作って書き出した記録を、そのまま読み込めること
  （2つのアプリの約束ごと）。ffmpeg で作った「撮影を終えた時刻入り」の 120 秒の動画で、タップ記録を先に読み込む → 動画を開く（ゴールは探さない）→ 撮影時刻から合わせる（記録の 0:00 ＝ 動画の 0:12）→
  ずらす → 手で合わせ直す（記録を選ぶ → 止める → ボタン）→ 絞り込み（得点だけ・#7 だけ・相手だけ）→ 続けて再生（重なる 2 場面は 1 つにつながる）→「⌖」→ 1 場面を動画にする（約 8 秒の MP4）→
  開き直すと戻る → 同じ端末で記録した試合から読み込む → 自動で探した得点と照らし合わせて合わせる → チームなしのパスミス・★ → タップ記録を外す、を画面で操作して確かめた（40 件）。
  撮影時刻の読み取りは、ffmpeg で作った MP4（`mvhd` の作成時刻）と MOV（`com.apple.quicktime.creationdate`）で確かめた。
  **本物の iPhone・Android の動画では、まだ確かめていません**（「`mvhd` の作成時刻＝撮影を終えた時刻」は、iPhone・Android でそうなっていることが多い、という前提。違う機種では、目安がずれます。そのときは手で合わせてください）
- 確認したブラウザ：Chromium（Playwright 同梱・画面なし）。Safari・iPhone では未確認（エンジンと動画まわりの部品は、バスケ分析スタジオで Safari のエンジンでも確認ずみのもの）

## 開発

```bash
node basket-clips/build.mjs              # 1ファイル版を作り直す（公開するのはこれ）
node basket-clips/tests/unit.cjs         # 回帰テスト（113件。ffmpeg があれば MP4 の読み取り・撮影時刻も）
node basket-clips/tests/e2e.cjs built    # 画面を通した確認（76件・約8分。初回は合成動画を作るので +6分）
node basket-clips/tests/e2e.cjs dev      # 開発版で同じ確認
node basket-clips/tests/e2e-log.cjs built  # 📲 タップ記録から切り出す流れ（40件・約1分。初回はテスト用の動画を ffmpeg で作る）
node basket-clips/tests/server.cjs       # 開発用サーバー → http://127.0.0.1:5192/

# リングに当たるシュートの見分け（合成映像を作って → 形ごとに数える。800 秒の動画で、作るのに約6分・調べるのに約5分）
node basket-clips/tests/tools/make-video.cjs /tmp/rim800.mp4 0-800 30 4 rim
node basket-clips/tests/rim-check.cjs /tmp/rim800.mp4 dev /tmp/rim800.log.json      # OCCL=0 で、リングが隠れたコマを使わない（もとの動き）
node basket-clips/tests/rim-replay.cjs /tmp/rim800.log.json /tmp/rim800.mp4          # 判定だけをかけ直す（数秒）

# ゴール裏から撮った合成映像（6つ目の引数：rim か -、7つ目：カメラの場所）と、ゴールの自動検出の確かめ
node basket-clips/tests/tools/make-video.cjs /tmp/behind150.mp4 0-150 30 4 - behind
node basket-clips/tests/goalfind-check.cjs /tmp/behind150.mp4 30 1 run              # 30 コマで探す・コマごとに表示・見つけたゴールのまま解析
node basket-clips/tests/node-run.cjs /tmp/behind150.mp4 0 150                        # 正しいゴールの指定で解析（FASTSCALE=0 で、もとの大きさの追従）

# 3段の判定とネットの揺れ（8つ目の引数：ボールの動きぶれ＝シャッターの秒数）
node basket-clips/tests/tools/make-video.cjs /tmp/blur150.mp4 0-150 30 4 - side 0.033
node basket-clips/tests/tier-check.cjs /tmp/rim800.mp4 /tmp/rim800.tier.json          # 解析して比べる（記録を保存）
node basket-clips/tests/tier-check.cjs --from /tmp/rim800.tier.json                   # 保存した記録で、判定だけやり直す（NET='{"peak":0.3}' でしきい値を試す）
```

- e2e は Playwright（`npm i -g playwright` など）と、その Chromium を使います。合成動画は `WORK`（既定は一時フォルダの `basket-clips-e2e/`）に置き、次から使い回します。
- テストの Chromium は H.264 を扱えないため、合成動画は VP9 の MP4 にしています。ふつうの Chrome・Edge・Safari では、スマホの H.264 / HEVC の動画を同じように直接読みます。
- 解析エンジン（`vision.js` `auto.js` `auto-engine.js` `mp4.js`）を直すときは、バスケ分析スタジオと同じ直しを入れると、両方がそろったままになります。
  いまは `auto.js` に、バスケ分析スタジオ（9331ba6）にまだない直しが入っています：画面の外になる位置のゴールの捉え方（TH_ACQ_EDGE・TH_KEEP_EDGE・OUT_MAX）、
  リングが隠れたコマを捨てない（OCCL_MAX・OCCL_NCC・設定の rimOcclusion）、ネットの下から現れたボールの条件（bornYMax・bornGap）、
  大きさの追従を毎コマ（fastScale。再生しながら探すときは使わない）、2つの追跡が同じ場所を捉えたら片方を取り消す（resolveSame）、両方のゴールで 1 秒以内に出た得点の片方を外す（dedupe）、
  ネットの揺れの記録と3段の判定（netEvents・classify・しきい値 NE。設定の tiers: false で、もとの2段に）。
  向こうにも同じ直しを入れると、そろいます。ゴールの自動検出（`goalfind.js`）も、そのまま使えます。

## 公開

`public/basket-clips/index.html` は、ふだんの `npm run deploy`（Vite のビルド → gh-pages）で一緒に公開されます。
アプリだけを直したときは、`node basket-clips/build.mjs` のあと、`gh-pages` ブランチの `basket-clips/index.html` を差し替えても公開できます
（`bash basket-tap/tools/deploy-ghpages.sh` は、バスケ タップ記録と一緒に、`basket-clips/index.html` だけを差し替えます。ほかの公開物は変えません）。
