# ミニバス スコアシート分析

ミニバスの公式スコアシート（JBA形式）の**写真**を入れると、得点・フリースロー・ファウル・出場を読み取って、**試合ごと・通算**で分析する。

```
写真 ──(Claude が読み取る)──▶ 数字のデータ ──(自動チェック)──▶ 確認・修正 ──▶ 分析
```

写真は端末のメモリの上だけで扱い、**保存するのは確認した後の数字（背番号・得点・ファウル・出場）だけ**。選手の氏名は読み取らない設定もある。

## 使い方

| 方法 | 手順 |
|---|---|
| **Claude のアーティファクト**（いちばん簡単） | 公開したページを開く → 写真を選ぶ → 読み取りが終わったら、写真と見比べて確認 → 「この内容で分析する」。Claude の利用枠を使う。読み取った試合は、自分だけが読める保存領域に残る |
| **手動**（ChatGPT・Gemini・Claudeのチャットでも使える） | `minibasket-all-in-one.html` をダブルクリックで開く → 「手動で読み取る」の指示文をコピー → 写真と一緒にAIへ送る → 返ってきたJSONを貼り付けて「読み込む」。保存先はこのブラウザ |
| **サンプル** | 「サンプルで分析を見る」。練習試合3試合（背番号だけ。チーム名は仮のもの）の分析がそのまま開く |

自チームは、チーム名に含まれる言葉で決める（画面の欄に入れる。変えた値は保存される）。**空欄のとき、または当てはまるチームがないときは、用紙の右側のチームBを自チームにする**。試合ごとに、確認の画面の「自チーム」でも選べる（こちらが優先）。初期値を決めたいときは `js/config.js` の `myKeyword`。

## 共有するとき（Claude のアーティファクトとして公開した場合）
- **共有の切り替えは、ページの持ち主がページの「共有」メニューで行う**（リンクを知っている人に開く、など）。ツールの側からは変えられない
- 見る人は Claude のアカウントが必要。写真の読み取りは**見る人自身の Claude の利用枠**を使う（初回に許可を求められる）。持ち主の枠は減らない
- **保存**：共有の権限が「コントリビューター」以上の人は、自分だけが読める保存領域に残る。「閲覧のみ」の人は、**そのブラウザの中**に残る（ほかの端末には出ない）。どちらの場合も「全部書き出す（JSON）」で手元に残せる。ほかの人の保存は読めない
- Claude を使えない人、許可しなかった人は、自動で「手動で読み取る」（ChatGPT・Gemini などにコピー）に切り替わる
- サンプルのチーム名・会場は仮のもの。選手の氏名は入っていない
- 読み取りは、必ず写真と見比べて確認する前提のツール。共有するときに、そのことを一言添えてほしい

## 分析でわかること

| | |
|---|---|
| 試合 | ピリオド別の得失点・点差、前半と後半、ピリオド終了ごとの点差 |
| 得点 | 選手別（2点・3点・フリースロー別）、得点者の偏り、3点シュート |
| フリースロー | 成功数と**機会**（相手のファウルの P1・P2 の数字の合計）→ 成功率。相手側も |
| ファウル | 選手別・ピリオド別・チーム別、4ファウル到達、相手に与えたフリースローと、そこからの失点 |
| 出場 | 誰がどのピリオドに出たか、5人の組み合わせごとの得失点、選手ごとのプラスマイナス（ピリオド単位）、1ピリオドあたりの得点 |
| その他 | タイムアウトのピリオドと時間、出場の印がない登録選手 |
| 通算 | 複数の試合をまとめた、チームと選手の通算・平均、ピリオドごとの傾向 |

### この記録からは分からないこと
- シュートの試投数・成功率（FG%）。入った得点だけが記録される
- リバウンド・アシスト・ターンオーバー・スティール
- **同じピリオドの中での、両チームの得点の前後関係**。ランニングスコアは、チームごとに別々の列に書くので、リードチェンジや連続得点（ラン）は出せない。分かるのはピリオドの終わりごとの点差まで
- ピリオドの途中の交代。出場は「ピリオド単位」でしか記録されない
- 出場しなかった理由（欠席・ケガ等）

## 読み取りの仕組み

写真1枚をそのまま渡すと、Claude 側で約120万画素に縮小されて、ランニングスコアの数字がつぶれる。そこで、

1. 用紙（白い部分）を自動で見つけ、領域ごとに切り出す（上段の表／A欄／B欄／ランニングスコア3分割）。範囲がずれたら画面の「読み取りに使った範囲」で調整できる
2. **①基本情報**（得点・出場・ファウル・タイムアウト）を読み取る
3. **②ランニングスコア**を読み取る。①の結果（ピリオド得点・各ピリオドの出場メンバー）を「手がかり」として渡し、背番号の読み違いを減らす。ただし「手がかりに合わせて作り変えず、見えたとおりに書く」よう指示している
4. **自動チェック**：ピリオド得点の合計＝最終得点／ランニングスコアの最後＝最終得点／各ピリオド終了の累計がランニングスコアにある／得点者がそのピリオドに出場している／出場が各ピリオド5人／ファウルの数、など。合わない箇所は画面に出る
5. 人が写真と見比べて直す → 不一致を伝えて**読み直し**もできる

### 精度（検証したこと、していないこと）
- 写真3枚（960px幅に縮小したもの）を、**答えを見せずに別の Claude（Opus）に読ませ**、手で書き起こした正解と突き合わせた
  - ランニングスコア：**126件すべて一致**（得点番号・●か斜線か・背番号・3点の丸・ピリオド終了の丸）。自動チェックもエラー0
  - 基本情報（出場・ファウル・タイムアウト・得点）：約178項目のうち5項目が不一致（約97%一致）。いずれも読み取り側が「自信がない」とメモしていた箇所（④の列の薄い斜線の見落とし、ファウルの添え字の 1／2 など）。この種の見落としは「出場が5人に満たない」という自動チェックの警告で気づける
  - この突き合わせで、**正解側（私の書き起こし）の誤りも1件**見つかり直した（ファウルの添え字）。読み取りは、必ず人の目で確認する前提
- **していないこと**：アーティファクトの `sample` 機能で、実際の写真を読み取ること（この環境では実行できない）。画面の流れは、`window.claude` を模した偽物で動作確認した。別の大会の用紙、書き手のちがう字、暗い・斜めの写真での精度も未確認

## 記号の読み方（スコアシートの約束と、このツールの解釈）
- ランニングスコア：●＝フリースロー1点／斜線＝2点／選手番号が丸で囲まれた得点＝**3点シュート**（確認ずみ。この練習試合では3点シュートがある）。ピリオド最後の得点の丸と下線は、得点の種類とは別
- 得点の種類は、印だけでなく**得点番号の増え方**（+1／+2／+3）でも決め、食い違えば警告する
- 出場時限：斜線（／）＝出場。まれに「＼」「×」が書かれる（意味は用紙からは確定できない）。出場扱いにするが、プラスマイナスと5人の組み合わせは「参考値」にする
- ファウル：P＝パーソナル、右下の数字＝フリースロー本数（P2＝2本）。赤インクは1Q・3Q、黒は2Q・4Q
- チームファウル欄は1ピリオド4個までしか数えられない。そのため**ピリオド別のファウル数は、インクの色ごとの合計から割り出す**。両方のピリオドが4個以上のときは幅（5〜7など）で示す
- タイムアウト欄の番号＝そのピリオドの何分めか（欄①〜④＝1Q〜4Q）

## データの形（`samples/*.json` が例）
`js/core.js` の先頭コメントが仕様。要点：

```json
{ "meta": { "date": "2026-01-10", "time": "11:20", "gameNo": "3", "venue": "…" },
  "teams": [ { "side": "A", "name": "…", "finalScore": 33, "quarterScores": [7, 13, 11, 2],
               "timeouts": [{ "box": 1, "minute": 2 }], "teamFouls": [4, 2, 0, 2],
               "players": [{ "no": "88", "name": "", "marks": ["/", "/", "\\", ""], "fouls": [{ "type": "P", "ft": 2, "ink": "black" }] }],
               "running": [{ "total": 3, "mark": "slash", "player": "88" }, { "total": 7, "mark": "slash", "player": "15", "qEnd": true }] },
             { "side": "B", "…": "…" } ] }
```

## プライバシー
- 写真は保存しない（ブラウザのメモリの上だけ）。リポジトリの `samples/` も、**写真ではなく背番号だけの数字データ**で、選手の氏名は入れていない。チーム名・会場も仮のものにしてある
- Claude で読み取るとき、写真は Claude に送られる（あなたの Claude の利用枠。アーティファクトでは、初回に許可を求められる）
- 「選手の名前は読み取らない」にすると、氏名を読み取らない
- 保存先：アーティファクトでは自分だけが読める領域（`data/users/<id>/`。書けない権限のときは、そのブラウザの localStorage）、普通のブラウザでは localStorage。読み込みは両方をまとめて見る

## ファイル
```
minibasket/
├─ index.html                       開発用の入口（ビルド不要。ブラウザで開くだけ）
├─ minibasket-all-in-one.html       全部を1つにしたもの（ダブルクリックで開く）
├─ minibasket-artifact.html         Claude のアーティファクト用（枠なしの断片）
├─ css/minibasket.css
├─ js/  config.js  core.js  analysis.js  charts.js  extract.js  store.js  samples.js  app.js
├─ samples/game2.json game3.json game5.json   練習試合3試合（背番号だけ。チーム名は仮のもの）
└─ tools/  check.cjs  make-samples.cjs  bundle.cjs
```
- `core.js`＝データの正規化と自動チェック、`analysis.js`＝分析と「気づき」の文章、`extract.js`＝指示文・写真の切り出し・Claudeへの問い合わせ、`charts.js`＝グラフ（SVG）、`store.js`＝保存、`app.js`＝画面

## 開発
```bash
node minibasket/tools/check.cjs            # 分析エンジンのテスト（samples/ の3試合を使う）と、生成物が最新かの確認
node minibasket/tools/make-samples.cjs     # samples/*.json → js/samples.js
node minibasket/tools/bundle.cjs           # → minibasket-all-in-one.html
node minibasket/tools/bundle.cjs --artifact   # → minibasket-artifact.html
python3 -m http.server 8786 --directory minibasket   # 開発用（.claude/launch.json の "minibasket"）
```
- コードを変えたら、`make-samples` → `bundle`（2種類）を実行して作り直す。`check.cjs` が作り直し忘れを検出する
- アーティファクトとして公開するときは、`minibasket-artifact.html` を、`capabilities: { sample: { images: true }, db: {}, user: {}, downloads: true }` で公開する
- 分析を足すときは `analysis.js` の `analyzeGame` / `analyzeMany` と、`check.cjs` の期待値を一緒に足す。期待値は、紙の上で別に数えた値にする
