# 学力推移調査型の類題 ─ 見た目のバグの点検と直し（担当むけ）

公開の前の点検で、機械の検査（`suii/tools/lint_board.cjs`）が、実際のバグをいくつも見つけた。**担当の1ページ（`<PAGE>`）の全ステップを目で見て、バグを直す。** 数学の中身（問題文・数値・答え）は変えない。

**約束：ファイルを消さない・動かさない（`rm`・`mv`・`rmdir` は使わない。作業フォルダの中でも使わない）。** 書くのは `<PAGE>`（html）と、scratchpad の自分の作業フォルダ `<WORK>` の中だけ。ほかのページ・`tools/`・`kukan/`・`katsuyo/js/`・`heikou/js/` は書きかえない。git・公開はしない。インターネットは使わない。

## 1. さがすバグ（4種類）

### A. 答えの先見え（いちばん多い・いちばん大事）
答えのあるステップは、はじめ「問いの画面」（右に「考えてから、つぎへ ▶ で答え」）が出て、「つぎへ」で答えが出る。
**問いの画面の図に、その小問の答え・答えを決める途中の結果が、もう出ていてはいけない。**
見つかった例：
- 表の空らん（ア・イ）をきく小問なのに、問いの画面の表に、もう数（210・0.40）が入っている
- 「歯数は？」ときく画面の図に「B 歯数 16」と書いてある／「色紙は何枚？」の図に「全部で 52枚」
- 「それぞれ何人？」の帯の図に「x＝180」「y＝300」／「小数第1位まで求めよう」の数直線に「8.484…」
- 正しいか判断させる小問で、判断の決め手（「A が当たり 21通り」「B が当たり 21通り」、「中央値 3.5（そのまま）」、反例の数）が先に出ている
- 答えの棒・点・線だけ色がついている、答えの位置に点がある

**問いの画面に出してよいもの**：問題文にある数・図、**前の小問までの答え**（もう答えたもの）、その小問の問いが指す場所の印（「ア」「？」の空らんを光らせる、など。数は入れない）。

直し方：`draw` の中で、`D.ph`（0＝問いの画面、1＝答えを出したあと）で分ける。`D.t` は、問いの画面では 0、答えを出すと 0→1 に動く（動きを止める設定では、すぐ 1）。
```js
draw: function (D) {
  var t = D.ph ? D.t : 0;            // 問いの画面では 0
  base(D, { cell: t > 0 ? '210' : 'ア' });   // 答えは t > 0 のときだけ
  if (t > .3) CH.text(D, x, y, '歯数 16', { a: CH.smooth(.3, .5, t) });
}
```
「問いの画面」で図がさびしくなってもよい（問題の図＝そのステップの前の「問題」のステップと同じ図に、前の小問の答えを足した形にする）。

### B. 図の字の重なり
図の中の字が、ほかの字・座標軸の目もりの数・点の名前に重なって読めない。→ 字の位置をずらす（線や図形の上は `outline` をつけてもよい）。

### C. はみ出し・切れ
図の字が図の外に出て切れる。右のらん（問題文・小問・答え・説明）が下に切れる。→ 位置・大きさを直す。文を短くする（意味は変えない）。

### D. 図と問題文のくいちがい
図の数・形・点の位置・名前が、問題文・答えとちがう。→ 図を問題文に合わせる（問題文のほうがまちがいなら、報告に書く。直すときは `suii/text/<ID>.q.md`・`.a.md` も同じに直す）。

## 2. 手順

```bash
cd /home/user/math-dialogue
node suii/tools/lint_board.cjs <PAGE>                       # 機械が見つけた候補（重なり・はみ出し・先見え・新しく出た字）
node suii/tools/check_board.cjs <PAGE> --shots <WORK>/s1    # 全画面の写真。動きを止めた、できあがりの形
```
- 写真の名前は `<ページ>-<ステップ>-<何回目>.png`。答えのあるステップは 2枚（先が **問いの画面**、次が **答えの画面**）。答えのないステップ（各題のはじめの「問題」）は 1枚。
- **全部の写真を Read で開いて見る**（候補だけでなく全部）。ステップごとに、html の `q`・`a`・`sub`・`notes` と照らして、A〜D を見る。問いの画面では「この画面を見ただけで、答えがわかってしまわないか」を1枚ずつ考える。
- lint の候補は、1つずつ「バグ（直す）」か「問題ない（理由）」かを決める。「新しく出た字」は、前の小問の答えや、問題文の数なら問題ない。
- 直す → `node suii/tools/check_board.cjs <PAGE>`（動きつきで通す。OK・エラー 0）→ `--shots <WORK>/s2` で撮り直して、**直したステップの問いの画面と答えの画面を見直す** → lint をもう一度（のこった候補は、すべて「問題ない」と説明できること）。
- 答えの画面は、直す前と同じ内容が出ること（答えの図を消さない）。`CH.check` の確かめは消さない。

## 3. 報告（短く）
- 直したところ：ステップ番号・種類（A〜D）・何が見えていたか・どう直したか
- lint にのこった候補と、問題ないと判断した理由
- 直さなかった・判断に迷ったところ
