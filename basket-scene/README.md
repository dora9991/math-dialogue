# バスケ シーン

バスケの試合の**動画を見ながら**タップで記録すると、その場面が**そのまま切り出されて**、選手ごと・プレーごとに見たり、1本の動画にしたりできるブラウザアプリです。スタッツと、**反省会でみんなで見る画面**も、同じ画面から出せます。

「バスケ タップ記録」（記録）と「場面の切り出し」（トリミング）を、**1つの流れに作り直した**ものです。

- インストール不要。記録は、この端末（ブラウザの中）に保存します。**動画は、どこにも送りません**
- 外部ライブラリなし・通信なし（見本の試合の動画を読むときだけ、同じ場所から読む）
- 1ファイル版：`docs/index.html`（`node build.mjs` で作る）

## 使い方（1つの画面で、①→②→③）

1. ホームの「🎬 **試合の動画を選ぶ**」→ 自分のチームの名前と背番号（前の試合のものが入っています）→「▶ 記録をはじめる」
2. 上に動画、下（横長の画面では右）に 3 つのタブが出ます

| タブ | すること |
|---|---|
| **① 記録** | 動画を止めたり戻したりしながら、プレー（2P・3P・FT・リバウンド・アシスト…）と背番号をタップ。どちらが先でもかまいません。相手は、得点（+1・+2・+3）だけ |
| **② 場面** | 記録した場面が、もう並んでいます。押すと、その場面を再生。選手ごと・プレーごとにしぼって「▶ 続けて再生」「🎬 1本の動画にする」 |
| **③ スタッツ** | 成功率・選手ごとの数。数字を押すと、その場面へ。「📺 反省会の画面」「🖼 画像で保存」「📊 CSV」 |

「試合を終える」「動画を選び直す」「時刻を合わせる」は、ありません。記録の時刻は、いつも動画の時刻だからです。

- **見本の試合**：ホームの「▶ 見本の試合で試す」で、約1分の見本の動画と、記録ずみの試合が開きます（はじめての人に見せるときに）
- **続きから**：ホームで同じ動画を選ぶと「この動画で記録した試合があります」→ 続きを開く。「これまでの試合」から開くと、動画なしでスタッツが見られます（場面を見るときは、同じ動画をもう一度選ぶ。動画の中身は保存していません）
- **ピリオド**：上の帯の「1Q」→「ここから 2Q」。動画を、次のピリオドが始まる所まで動かしてから押します

## 設定（⚙）

はじめから、記録するものは**全部オン**です。いらないものを外します。

| | |
|---|---|
| 👥 チーム・背番号 | 自分のチームの名前・背番号・選手の名前・色、相手の名前 |
| ① 記録するもの | シュートの失敗（×）・リバウンド（Oリバ／Dリバに分けるか）・アシスト・スティール・ブロック・ターンオーバー・ファウル・★、シュートの場所、タップしたら動画を止めるか |
| ② 場面の長さ・動画 | 場面の長さ（はじめは、タップの前 10 秒・後 2 秒。リバウンドと ★ は前 5 秒）。プレーごとにも変えられます。書き出す動画の札、場面ごとの細かい手直し（✎）を出すか |
| 画面の色・💾 データ | 明るい／暗い、記録のファイル（JSON）・一覧（CSV）、試合を消す |

## もとのアプリとの関係

- 記録の形は「バスケ タップ記録」と同じ（`format: 'basket-tap'`・`mode: 'video'`）。書き出した JSON は、どちらでも開けます
- 試合を**見ながら**（リアルタイムで）記録する・この端末のカメラで撮影しながら記録する・クラウドに残す、は、もとの「バスケ タップ記録」にあります。このアプリは、**撮った動画を見ながら**の流れだけに絞っています
- `js/lib/` は、もとのアプリの部品を写したもの（`core.js`・`shot.js`・`agg.js`・`ui.js` と、切り出しの `bs-core.js`・`taplog.js`・`media.js`・`mp4.js`・`export.js`）。直すときは、もとと両方に

## ファイル

```
index.html        開発用（js/ と css/ を読み込む）
build.mjs         1ファイル版を作る → docs/index.html（＋ docs/demo/）
demo/             見本の試合（demo.mp4・demo.json）
css/base.css      色・ボタン・小窓（もとのアプリと同じ）
css/shell.css     ホーム・動画つきの作業の画面・タブ・設定
css/tap.css・scenes.css・stats.css   タブの中身
js/lib/           もとのアプリの部品（上の「もとのアプリとの関係」）
js/sc-store.js    保存（bscene:）・設定のはじめの値
js/sc-app.js      土台：ホーム・試合を作る・動画・再生・タブ・ピリオド・設定の入れ物（パネルとの約束は、先頭のコメント）
js/sc-tap.js      ① 記録
js/sc-scenes.js   ② 場面（再生・続けて再生・動画にする）
js/sc-stats.js    ③ スタッツ・反省会の画面・画像
js/sc-demo.js     見本の試合
js/sc-boot.js     はじめ
tests/            helpers.cjs（共通の道具）・e2e-*.cjs（Playwright の Chromium）・unit-*.cjs（node だけ）
```

## 開発

```bash
node build.mjs                      # 1ファイル版を作り直す（docs/）
node tests/unit-tap.cjs             # ① 記録の、画面なしの部分（22件）
node tests/unit-scenes.cjs          # ② 場面の、画面なしの部分（49件：場面の長さ・しぼりこみ・つなぎ方）
node tests/unit-stats.cjs           # ③ スタッツの、画面なしの部分（62件：数字・よかったところ・画像の割りつけ）
node tests/e2e-shell.cjs built      # 土台（51件：ホーム・動画・タブ・ピリオド・設定・見本の試合）
node tests/e2e-tap.cjs built        # ① 記録（122件）
node tests/e2e-scenes.cjs built     # ② 場面（103件：再生・続けて再生・動画にする・設定）
node tests/e2e-stats.cjs built      # ③ スタッツ・反省会の画面・画像（109件）
node tests/e2e-flow.cjs built       # はじめての人の流れ（54件：動画を選ぶ → タップ → 場面 → スタッツ → 反省会。スマホと iPad）
node tests/server.cjs               # 開発用サーバー → http://127.0.0.1:5194/
SHOTS=/tmp/shots node tests/e2e-flow.cjs dev   # 画面の写真も撮る
```

テストは Playwright（`npm i -g playwright`）と、その Chromium を使います。テスト用の動画は ffmpeg で作ります（VP9。テスト用の Chromium は H.264 を再生できないため。本物の iPhone の動画は H.264 で、そのまま使えます）。

## 確かめたこと・まだのこと（2026-11-21）

- 上のテストは、1ファイル版（`docs/index.html`）で全部通過（Playwright の Chromium）。画面は、スマホ（320・390px）・スマホの横・iPad の縦横で、はみ出し・重なりがないことを確かめた
- **記録のあと、タブ「② 場面」と場面の行の 2 回押すだけで、その場面が再生される**こと（小窓・動画の選び直し・時刻あわせがないこと）を `tests/e2e-flow.cjs` で確かめている
- まだ：本物の iPhone・iPad（Safari）での確かめ。iPhone の動画（H.264・HEVC）での再生と書き出し（テスト用の Chromium は H.264 を再生できないので、VP9 の動画で確かめた。もとのアプリと同じ部品なので、同じように動くはず）。共有の画面（「画像を保存」・LINE）・印刷の紙。試合時間（止められる時計）・コメントとスタンプ・これまでの集計（何試合もまとめて）・クラウドは、このアプリには、まだ入れていない（もとの「バスケ タップ記録」にある）
