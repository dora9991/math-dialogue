# 新しい単元をつくるときの進め方（トークンをおさえる版）

先生（kazu）から「確認は今までと同じぐらいでいい」「トークンがもったいない」と言われて、平行と合同（2026-10）のあとに決めなおした進め方。
**目標：確認にかける量を、いまの半分以下にする。ただし、答えのまちがい・正解が2つに読める・問題文が崩れる、は、かならず出さない。**

## 0. つくるもの（先生の指示：いまは「3点セット」だけ）

- **2026-10-29 から、3点セットは「新しい形」**（ワークシート A4 1枚・演習プリント 8問・罫 8mm）。決まりと作り手への指示書は `NEW_FORM.md`。中1 第1〜7章の 110授業は、この形でできている。以下の「つくるもの」の考え方（3点セットだけ・授業計画などは頼まれたときだけ）は、そのまま。

- **標準でつくる**：1授業につき、**ワークシート（表裏）・演習プリント（表裏）・小テスト（10点満点＋別枠のチャレンジ）**。と、答えの検算（`checks`）。
- **頼まれたときだけつくる**：授業計画（A4 1枚）・授業スライド・コツコツくん形式の問題（`kotsu/`）。いまは要らない（2026-10-26 に先生が言った）。
- 道具は、授業計画・スライドがなくても、そのまま動く（授業計画がなければ、`plan:` を書かない。タブも、ある物だけ出る。`IK.qrUnits` に単元のキーを足せば、QR・記録ページ・学習予定表は、演習プリント・小テストから自動でできる）。
- 3点セットでも、「考えよう」（学び合いの核。答えは載せない）と、先生のスタイル（量をへらし、書き込む余白を広く）は、そのまま。

## 1. 直す基準（これだけ直す。ほかは直さない）

| 直す（致命・要修正） | 直さない（軽微。報告もしない） |
|---|---|
| 答えがまちがい／正解が2つ以上／正解がない／問題文だけでは決まらない | 4択の「当てやすさ」が 35〜69% のもの |
| 問題文・解説が崩れる（名前の置き換え・符号・かっこ・同じ式が2回） | 言い回し・用語のゆれ・レベルの軽重 |
| 考えようの答えが、スライド・ワークシート・速記メモに出ている | バリエーションが少ない（答えが毎回同じは直す） |
| 図の字が切れる・線や別の字と重なって読めない | 解説の算式の `$` の入れ方などの表記 |
| 正解が毎回同じ・形だけで 70% 以上当たる 4択 | ヒントが「着眼点」を言っている（答えそのものは直す） |

- 1回目の確認のあと、直すのは上の左の列だけ。**2回目の確認は、全部やり直さない。**
- 4択の「当てやすさ」を 35〜45% 以下にそろえるやりとりが、いちばん高くついた（作り手 5 人が何度も直した）。目標は「正解が毎回同じにならない」「形だけで 70% 以上当たらない」まで。

## 2. 進め方（順番）

1. **道具に検査を持たせる（単元をはじめる前に、1回だけ）**
   `kotsu/verify.mjs` に、毎回人が測っていた次を、自動の検査として足す（足りないものから足す）。
   - 4択：正解が「最長／最短／唯一の形」で当たる率（70% 以上でエラー）。正解の語が毎回同じ。
   - 答えが問題文の数と同じになる率。答えの種類が少なすぎる（3 種類以下）。
   - 解説：同じ式が2回、5行以上、`−0`、`$` の外の数式。ヒントに答え。
   - 点の名前が、頂点と変数でぶつかる（問題文の中の文字の重なり）。
   作り手は、報告する前に、これを通す。確認する人が、同じことを測りなおさない。
2. **作る（作り手）**：授業 3〜4 時ずつ。指示書に「過去に見つかった型」を最初から書いておく（`KOTSU_BRIEF` 系）。
3. **機械の検査**：`tools/verify.cjs`・`tools/check.cjs`・`kotsu/verify.mjs`・図の字の切れ（`slide-src.cjs` の PNG の端）。すべて緑にしてから、人の目に出す。
4. **人の目の確認は、1回だけ**
   - 対象：**作り手が答えを独立に出せないもの**に絞る。図の文章化・理由を選ぶ 4択・証明・場面の言い切り。数だけを答える問題で、作り手が別の道すじで検算している（`hq_*` の解き直し）ものは、見ない。
   - 人数：2 人まで（授業の数ではなく、テンプレートの数で割る）。強いモデル（Opus）で、範囲をせまくして見るほうが、弱いモデルで広く見るより安い。
   - 報告は、致命・要修正だけ（軽微は書かない）。
5. **直す**：小さいものは自分（Claude）で直す。大きいものだけ作り手に返す（同じ作り手を呼びもどすと、文脈がふくらんで高い。範囲がせまいときは、新しい作り手に、そのファイルだけ渡す）。
6. **直したあとの確認は、機械だけ**（`verify`＋ 解き直しの道具）。直した所が大きく作りなおされたときだけ、そのテンプレートだけ、もう1回人の目で見る。
7. PR・見本ページ・README の数字。公開は「公開して」と言われたときだけ。

## 3. これまでで、いちばん高かったところと、へらす案

- **授業教材（3点セット）の作成**：授業 14 時で約 300 万トークン。ここは、へらさない（質のもと）。**いまは、ここだけをつくる**ので、1単元あたりの量が、これまでの約半分になる。
- 授業計画・スライド・コツコツくん形式の問題は、頼まれるまでつくらない（スライドは、作り手 4 人で約 170 万＋確認 3 人で約 80 万。問題テンプレートは、作り手＋確認 2 回で約 500 万かかった）。
- 3点セットの確認：機械の検査（`verify.cjs`・`check.cjs`）と、`checks`（答えの検算）で足りる。人の目の確認は、頼まれたとき、または図・証明が多い単元で、Opus 1 人・範囲をせまく、1 回だけ。
- 頼まれて、またスライドをつくることになったら、スライドを授業の資料から自動で組み立てる道具を先につくる（先生に聞いてから）。

## 4. 変えないきまり（先生との約束）

- 公開（`gh-pages`）は、先生が「公開して」と言ったときだけ。出すのは `ikkan/`（`index.html`＝全部入り HTML、`slides/`）だけで、ほかの公開物は変えない。
- 考えようの答え・想定される見方は、ワークシート・スライド・速記メモのどこにも書かない。
- 1授業＝ワークシート（表裏）・演習プリント（表裏）・小テスト（10 点満点＋別枠のチャレンジ）。授業計画（A4 1 枚）は、頼まれたとき。
- 確認していないことは、報告で「確認していない」と言う。
- 作ったら、`ikkan/README.md` と `ikkan/kotsu/README.md` の数字をそろえる。PR は下書きで作る。
