# ikkan の問題 → コツコツくん（数学ラボ ソロ）の問題テンプレート

ikkan（授業準備ツール）の演習プリント・小テストの問題を、**コツコツくんの問題データと同じ形**（毎回数字が変わるテンプレート）にして置いたものです。

## いまの数（4単元・全50授業）

| 単元（キー） | 学年・章 | 授業 | テンプレート | ikkan の問題 | 移した | 移さなかった |
|---|---|---|---|---|---|---|
| 空間図形（`kukan`） | 中1 | 15 | 313 | 225 | 224 | 1（投影図をかく作図） |
| データの活用（`data`） | 中1 | 11 | 208 | 136 | 136 | 0 |
| 式の計算（`shiki`） | 中2 第1章 | 11 | 281 | 160 | 160 | 0 |
| 連立方程式（`renritsu`） | 中2 第2章 | 13 | 209 | 159 | 159 | 0 |
| 合計 | | 50 | **1011** | 680 | 679 | 1 |

- 1授業＝1単元（id は `J1-kk01`〜`15`・`J1-dk01`〜`11`・`J2-sk01`〜`11`・`J2-rk01`〜`13`）。
- 作ったあと、作った人とは別の人が、問題文の数字だけから答えを解き直して確かめ（1回目・2回目。数万〜数十万問ぶん）、見つかった問題（正解が2つに読める選択肢、ヒントが答えを言っている、問題文が図表に頼っている、数字が現実的でない、など）を直してある。直したあとも、検査（`verify.mjs`）は、エラー 0。
- 見本（テンプレートごとに2問、答え・ヒント・解説つき）：`node ikkan/kotsu/preview.mjs 出力先.html [--unit=data,shiki]`。

## 位置づけ（いま、どこまでできているか）

- コツコツくんの本番（`/solo/`）のソースは、このリポジトリに無い（公開された `solo/` の中身だけが `gh-pages` にある）ので、**コツコツくんの中には、まだ入れていません**。
  ここにあるのは、コツコツくんの問題データの書き方（`src/solo/content/` の `UNITS`／`t(id, build)`。`docs/solo-問題データの書き方.md`）にそろえた、**取りこむだけの形のデータ**です。
- 問題は、`kit.js`（コツコツくんの本物と同じ道具）だけで動くので、コツコツくんのソースに置けば、そのまま動くはずです（まだ、本物の中では動かしていません）。
- ikkan 側では、**記録ページ・集計**（`#/r/…`・`#/rsum`）が、同じ問題ID（`<授業のID>.<dr|qz>.<番号>`）で、授業での自己採点（○△×）を集められます。コツコツくん側の学習記録に、テンプレート id（`03d04` ＝ `<単元>-03.dr.4`）を残すと、授業の理解度と、コツコツくんの習熟が、同じ問題でつながります。

## ikkan の問題との対応（問題ID）

- テンプレート id＝「授業の番号 2けた」＋ `d`（演習プリント）／`q`（小テスト）／`w`（ワークシート。任意）／`x`（ikkan にない補い問題）＋ 問題の番号 2けた（＋ a, b…）。
  例：`03d04` ＝ ikkan の `kukan-03.dr.4`（記録ページの問題IDと同じ）。
- ikkan の演習プリント・小テストの問題（（1）（2）…）は、**1問のこらず**「移した」か「`SKIPPED` に理由つき」のどちらかです（`verify.mjs` が、もれをエラーにする）。「（1）①」「（1）②」のように 2 つ並んだ問題（連立方程式の第4〜6時の演習）は、「（1）」の 1 問にまとめて一覧に入る（問題文は「1つ目 … 2つ目 …」）。

## 移し方の約束

- コツコツくんの答えは、**数値の入力**か**4択**だけ。図は出せない。そこで、
  - 数・長さ・面積・体積・式の値・解 → 数値入力。
  - **式を答える問題は、入力欄で打てない**ので、(a) 式から出る数（係数・次数・値）を聞く、または (b) 4択にする（誤答は「ありがちな間違い」。`peq` で正解と式として同じになるものは外す）。
  - 「すべて答えよう」 → 「何個か」の数の問い、または「次のうち…はどれか」の4択。
  - 名前・用語・性質・理由 → 4択（誤答は「どう読んでも誤り」になるようにしてある）。
  - 表・グラフが必要な問題 → 度数分布表は「0分以上10分未満が 3人、…」のように文章にする。連立方程式は `\begin{cases}…\end{cases}` で 2行にならべる。文章だけで言い切れないものは `SKIPPED`。
  - 説明・記述・作図 → 概念をたずねるものは、正しい説明（理由）を選ぶ4択。それもできないものは `SKIPPED`。
- 答えは、**計算で出す**（手で書いた答えを埋めこまない）。立体の関係・統計・式の展開・連立方程式の解を、`solids.js`・`stats.js`・`algebra.js` が計算する。
- 数字は毎回変わる。ikkan の問題は 1 つの例なので、テンプレートは、その型の**数字が変わる問題**にしてある。四捨五入は、ちょうど 5 の境目になる組を使わない。

## コツコツくんに取りこむとき

1. `content/*.js`・`unit-kit.js`・`stats.js`・`algebra.js`・`solids.js`・`kukan-kit.js` を、`src/solo/content/jhs/` のあたりに置く（`../kit.js` の読み込みは、本物の `kit.js` に合わせて直す）。
2. 単元（`J1-kk01`〜 など）は、`chapterId`・`chapterName` を持つ（例：`ikkan-kukan`「空間図形（ikkan の授業）」）。中学の単元は章でまとめる決まりなので、本物の章の持ち方に合わせる。`prereqs` は、既存の単元（`E6-kakuchu`・`J1-k2`〜`k4`・`J1-z3`・`J1-d1`〜`d3`・`E6-data`・`J1-v4`・`J1-v5`・`J2-g2c1u1`・`J1-e2` など）につないである。本物にその id が無いときは、直す。
3. 単元の要点（`points`）は、講義の代わりの 2〜4行。ホー先生の解説（講義データ）は、まだ無い。
4. 本物の検査（`solo-verify.mjs`）を通す。`ikkan` フィールドと、`fixed` は、本物のアプリには使われない（あっても害はない）。
5. 4択の選択肢に、`\begin{cases}`（連立方程式を 2 行で見せる式）や `\square` を使っているものがある（連立方程式・式の計算）。本物のアプリのボタンの中で、高さや表示が崩れないか、確かめる。分数の答え（`"1/2"` のような文字列）を、入力欄が正解にするかも、確かめる。

## 注意

- 答えの正しさは、機械の検査（書式・選択肢・数値の誤差）と、別の目での解き直し（独立の確認）で確かめています。ただし、実際の授業・生徒に出す前に、見本（`preview.mjs`）を見て、問題文の言い回しを確かめてください。
- **直さずに残した軽微な点**があります（確認で出た、言い回し・ヒントが手順を言い切るもの・答えの種類が少ないテンプレート・理由を選ぶ4択の誤答が「明らかな作り話」のもの、など）。問題の正しさには関わりません。
- 図が出せないので、立体の頂点の名前（A〜H）は、問題文の頭に文章で約束しています。表・グラフの図は、問題文では出していません。
