このセッションは、コツコツくんの本体（`src/solo`）を編集できません。本体のソースを持っているセッションが、これを読んで取り込めるように、データ・手順・依頼文・検査をそろえました。

## 1. できていること／まだのこと

| | |
|---|---|
| できている | 中1空間図形の解説15本それぞれに、簡単・普通・難しい・入試レベルの4段階 × 5問（300問）。確認ページ（`review.html`）、機械検査、正解を伏せた解き直し（299/300一致、残り1問は問題集が正しいと確認） |
| できている | 既存の演習150問（J1-SP-001〜150）を、解説ごとの復習に振り分ける案（`existing-redistribution.json`） |

## 2. 別セッションに貼る依頼文

````text

データは GitHub の dora9991/math-dialogue、ブランチ claude/kukan-lesson-problems（PR #92）の ikkan/kukan-bank/ にあります（add_repo で読めます）。
最初に ikkan/kukan-bank/IMPORT.md を読んでください。

目的：解説（動画）15本 kukan-01〜15 それぞれに、簡単・普通・難しい・入試レベルの4段階 × 5問以上の演習を、解説に連動して出せるようにする。
いまは1つの小単元（J1-k1〜k4）に解説が最大8本入っているのに、演習は小単元ごとに少しだけで、解説と連動していない。
既存の演習（J1-SP-001〜150）は消さず、小単元の復習として残す。

やること：
1. docs/solo-問題データの書き方.md と、J1 の単元・問題の持ち方を読み、取り込み方を決める。IMPORT.md の「3. 2つの取り込み方」のどちらにするか、理由を一言で書く。
2. 解説1本 = 1つの出題単位にして、その解説の演習として4段階が出るようにする。解説（talks など）の u の持たせ方も、必要なら直す。
3. 難易度4（入試レベル）をアプリが受けつけるか確かめる。受けつけないなら、先に私に聞く（勝手に d=3 にまとめない）。

5. 1つの解説（例 kukan-09）の4段階を、実際にアプリで開いて、問題・選択肢・解説の表示を確かめる。

守ること：
- 問題文・選択肢・正解・解説は変えない（正解は計算で出したもので、別の目で解き直し済み）。直したいところがあれば、直さずに私に伝える。
- 既存の演習150問は消さない。
- 公開（デプロイ）は、取り込みと確認が終わってから、私に確認をとってから。

終わったら、次を報告してください：取り込み方（A/B）、d=4 の扱い、検査の結果、確かめたこと、確かめられなかったこと。
````

## 3. 2つの取り込み方

どちらも、1解説＝1つの出題単位（15単位）にして、解説に連動して演習が出る形にします。

### A．テンプレートで入れる（第一候補。ただし未検証）

- 場所：`ikkan/kotsu/content/kukan-01〜15.js`（313テンプレート、単元 ID `J1-kk01`〜`J1-kk15`、レベル1〜4＝基礎・標準・応用・入試レベル）。
- 手順は `ikkan/kotsu/README.md` の「コツコツくんに取りこむとき」に書いてあります。
- 良いところ：1解説＝1単元の形がすでにある。数字が毎回変わるので、5問より多く、くり返し練習できる。アプリ本来の書き方（`t(id, build)`）。
- 注意：**本物のアプリの中では、まだ一度も動かしていません**。公開版では、テンプレートで書かれた単元は小学・高校だけで、中学（J）は固定問題だけでした。J の単元でテンプレートが使えるか、レベル4を受けつけるかを、最初に確かめてください。
- このときも、`bank.json` の300問は、「同じ型の問題が出るか」を見比べる基準に使えます（`meta.json` に、各問題の元テンプレートの id があります）。

### B．固定問題で入れる（A がだめなとき）

- 場所：`import/problems.json`（300問）と `import/video-map.json`（解説ごとの一覧）。`node ikkan/kukan-bank/export-for-app.mjs` で作り直せます。
- 項目は、公開版の J1 の固定問題と同じ：`{ id, u, s, d, q, c:[{t, k|m|w}], e, h }`。`l`（解説の番号）だけが新しい項目です。`u` は `J1-SP`、`s` は `J1-SP-K01`〜`K15`。
- `video-map.json` の `pool`（段階→問題ID）と `dir`（`[問題ID, 章, 段階]`）は、公開版の同じ名前のデータと同じ形にしてあります。各解説の `parentUnits` は、いまその解説が属している小単元です（解説13は J1-k3 と J1-k2 の2つ）。`review` は、その解説の復習に付ける既存の演習の ID です。
- 良いところ：データを足すだけ。誤答に「まちがえ方の理由」（`w`）が付いたものがある。
- 注意：1解説・1段階が5問で固定。誤答の理由が付くのは 900個中 180個。

## 4. 公開版（2026-11-10）から読み取ったこと

ソースは見ておらず、ビルド済みの公開版を読んだだけです。ソースの実際の構造とちがう場合は、ソースを優先してください。

- J1 の固定問題は `{ id, u, s, d, q, c, e, h }`。`c` の正解は `{ t, k: 1 }`、誤答は `{ t, m, w }`（`m`＝まちがいの種類 ID、`w`＝理由）。
- 出題の候補は、`pool`（小単元→難易度→問題ID）と `dir`（小単元→`[問題ID, 章, 難易度]`）。**難易度は 1〜3 しか確認できていません**。
- 解説（動画）は `talks` などのデータに、`u: [小単元の ID]` を持ちます。小単元あたりの解説の数は `forUnit()` で数えているようです。
- 空間図形の小単元と解説：J1-k1（解説01〜08）、J1-k3（09、10、13）、J1-k2（11、13、14、15）、J1-k4（12）。

## 5. 決めてほしいこと（先生）

- **入試レベル（d=4）**：アプリが受けつけないとき、(1) アプリを直して4段階にする、(2) 「難しい」にまとめる（`export-for-app.mjs --fold-level4`。難しい＝10問になる）のどちらにするか。
- **誤答の `m`**：アプリが `m` を必須にしているとき、`--fill-m=SLIP-calc-02`（既存の問題が使っている「計算ミス」）で埋めるか、手で付けるか。
- **公開**：取り込み・確認のあと、どの形で公開するか。
