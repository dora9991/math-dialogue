# 体育館よやく（gym-booking）

佐賀市内の体育館（学校体育館・市の体育館）を、**市役所・学校・団体が同じ画面を見ながら、決まったルールで分け合う**ための試作。
部活動の地域展開で、勤務時間後の平日の夕方と休日に体育館を使いたい団体が増え、取り合いになることにそなえる。市への提案で「動く見本」として見せるために作った。

- 先着順にしない。**毎月の抽選**（申込期間のうちなら、いつ申し込んでも同じ）→ 残りを**先着**。その前に、年に1回の**定期枠**。
- 抽選は**くじの本数**で重みをつける（区分の基本＋地区内＋優先時間帯＋前回はずれ）。**上限**（1か月・1日）で1団体に集まらないようにする。
- 学校行事と大会はいつでも最優先。入っていた予約の団体には自動でお知らせ（違反にはならない）。
- 抽選は**シード**から作る乱数で行い、あとから**同じ結果になるか確かめられる**。

データはすべてサンプル（実在の施設・団体ではない）。ブラウザの中だけで動き、ほかの人とは共有されない。佐賀市の公式のものではない。

## 開き方

**いちばん簡単**：`gym-booking-all-in-one.html`（全部を1つにまとめたファイル）をダウンロードして、ダブルクリックでブラウザで開く。
フォルダごと持っているときは、`index.html` を開いてもよい（ビルド不要。サーバーも不要）。

上の「日付を進める」で「きょう」を進めると、**申込 → 抽選 → 確定 → 先着 → 利用の確認** の流れを試せる。最初の状態に戻すときは「最初からやり直す」。

## 画面

| 画面 | できること |
|---|---|
| しくみ | ルールの説明。市役所の「ルール」で変えた値が、そのまま文章に入る |
| 団体 | 体育館の時間割を見る・抽選に申し込む（くじの本数と当たる見込みが出る）・当選を確定する・先着で予約する・キャンセルする・お知らせ |
| 学校 | 自校の予定を見る・学校で使う日を登録する・予約した団体が使ったかを確認する（学校開放の運営委員会が使う想定にもできる） |
| 市役所 | 概要（混み具合）・抽選（シード・区分や地区ごとの当選率・くじの結果・確かめ）・団体の承認・施設・定期枠と大会の優先確保・ルール・データ（CSV・JSON） |

## ルール（既定値。市役所の「ルール」で変えられる）

| | 既定値 |
|---|---|
| 日程 | 利用月の前月 1〜9 日に抽選の申込、10 日に抽選、15 日までに確定、16 日から先着（利用日の 3 日前まで）。**佐賀市の体育施設のオンライン予約と同じ日程** |
| くじの本数 | 認定地域クラブ 3・子どもの団体 3・一般 2・営利 1。地区内の体育館 ＋2、優先時間帯 ＋2、前の月に1つも当たらなかった ＋1（2回ぶんまで） |
| 優先時間帯 | 学校体育館の平日の放課後（17:00–19:00）は、認定地域クラブと子どもの団体 |
| 上限 | 抽選の申込 月10件・当選 月4コマ・抽選と先着の合計 月8コマ・1日1コマ。定期枠は1団体 週2コマ、体育館のコマの50％まで |
| 約束ごと | 確定しないと取り消し。キャンセルは7日前まで違反なし（それより後は1点）。無断で使わなかったら2点。3点で1か月停止 |
| 使える団体 | 学校体育館は市内の団体だけ（学校開放の規則）。営利の団体は学校体育館を使えない（「先着だけ」「抽選も」に切りかえ可）。市外の団体は抽選なし・先着のみ |

ルールを決めた理由と、ほかの自治体の例は [`docs/rules.md`](docs/rules.md)。市への提案のたたき台は [`docs/proposal.md`](docs/proposal.md)。

## 抽選のしかた

1. 申込を集め、対象外のもの（上限をこえた分・市外・営利・学校行事が入ったなど）をのぞく。
2. コマを引く順番を乱数で決め、コマごとにくじを引く。当たる確率はくじの本数に比例する。
3. 半面に分けられる体育館は、半面ずつ（A面・B面）引く。全面の申込は、両方が空いているときだけ当たる。
4. 1か月の当選の上限・1日のコマ数の上限に達した団体は、そのあとのコマのくじから外れる。
5. 申込とくじの本数とシードを記録に残す。「同じシードでやり直して確かめる」で、同じ結果になるかを調べられる。

## 検査

```bash
node tools/test.cjs                                     # ルールと抽選の検査（日付・祝日・日程・くじ・上限・違反・サンプル）
NODE_PATH=$(npm root -g) node tools/check.cjs [出力先]   # 画面の検査：ひととおり操作して、エラーと横のはみ出しを調べ、画像を書き出す。playwright が必要
```

## 1つにまとめたファイルの作り方

```bash
node tools/bundle.cjs              # → gym-booking-all-in-one.html（js・css を直したら作り直す。できたファイルは手で直さない）
node tools/bundle.cjs --artifact   # 埋めこみ表示用（<html> などの枠なし）
```

## ファイル

```

js/lottery.js         抽選：シードつき乱数・コマごとの重みつき抽選・確かめ（画面を持たない）
js/actions.js         状態を変える操作：申込・抽選・確定・キャンセル・先着・学校の使用・利用の確認・違反点数（画面を持たない）
js/sample.js          サンプルデータ（開いた月に合わせて作る。今月分の抽選も本物の抽選で決めている）
js/store.js           保存（ブラウザの localStorage。使えないときは開いているあいだだけ）
js/app.js             画面
docs/rules.md         ルールを決めた理由と、ほかの自治体の例
docs/proposal.md      市への提案のたたき台
tools/                test.cjs（ルールの検査）・check.cjs（画面の検査）・bundle.cjs（1ファイルにまとめる）
gym-booking-all-in-one.html  全部を1つにまとめたファイル（tools/bundle.cjs でつくる）
```

## 本番にするなら（この試作にないもの）

- ログインと権限（市役所・学校・団体ごと）、データをサーバーに置く、個人情報の扱い。
- 今の「佐賀市施設予約システム」に学校体育館を載せて、ここのルール（くじの本数・上限・優先時間帯・定期枠の上限）を足すほうが、新しく作るより早くて安い可能性がある。この試作は、その「動く仕様書」として使う。
- 鍵の受け渡し、使用料と減免、雨天の振替、希望順位つきの申込（熊本市の方式）など。
