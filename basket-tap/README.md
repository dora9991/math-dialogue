# バスケ タップ記録

バスケの試合を見ながら、**だれが・何をしたか**（2P・3P・フリースローを入れた、リバウンド）と、**パスミス・あとで見たい場面の瞬間**を**タップで記録する**ブラウザアプリです。
記録には「スタートを押してからの時刻」が付くので、あとで **「バスケ得点クリップ」に試合の動画と一緒に読み込むと、その場面を切り出せます**（選手ごと・プレーごとに、続けて見たり、1本の動画にしたり）。

- インストール不要・通信なし。**記録はその端末のブラウザの中だけ**に保存し、どこにも送りません
- 公開ページ：**https://dora9991.github.io/math-dialogue/basket-tap/** （iPhone は「共有」→「ホーム画面に追加」で、画面いっぱいに使えます）
- 1ファイル版：`public/basket-tap/index.html`

## 使い方

1. **＋ 新しい試合を記録する** → **試合の準備**
   - チーム名・ユニフォームの色を選ぶ（なくても大丈夫）
   - **背番号は「4〜15」「4〜18」などのボタンでまとめて選ぶ**。番号のマスをタップして足す・外す。「4-15, 23」のように直接入れることも
   - 選手の名前（ニックネーム）も入れられます（なくてもOK）。入れると、行の高さに余裕があるとき、背番号の下に小さく出ます
   - 自分のチームは保存され、**次の試合からは最初から入っています**。相手のチームも、名前を付ければ「前のチームから」選べます
2. **ティップオフ（試合開始のジャンプボール）の瞬間に「▶ スタート」** → 左上の時計が動き出す
3. **プレーが起きたら、その選手の行のボタンを1回タップ**。押した瞬間の時刻で記録されます

### 記録の画面

```
┌ ● 12:05 ┐┌1Q┐   ┌ 12 ┐ − ┌ 8 ┐   ┌≡┐     ← 時計（スタートからの時間）・ピリオド・得点・メニュー
┌ 致遠館      12 ＋番号 ┐┌ 城南        8 ＋番号 ┐
│  4 [2P][3P][FT][リバ] ││  4 [2P][3P][FT][リバ] │  ← 選手1人＝1行。背番号の小さい順に上から
│  5 [2P][3P][FT][リバ] ││  5 [2P][3P][FT][リバ] │     押せば、その選手のプレーとして1回で記録
│  …                    ││  …                    │
│ 18 [2P][3P][FT][リバ] ││ 18 [2P][3P][FT][リバ] │
│  ？[2P][3P][FT][リバ] ││  ？[2P][3P][FT][リバ] │  ← だれか分からないとき（チームの記録）
└───────────────────────┘└───────────────────────┘
[パスミス] [★ あとで見る]  12:05 2P成功 +2 / 致遠館 #7  [↶ 取り消す]   ← いつでも押せる（チーム・選手は決めない）
```

- **選手の行**：「2P」「3P」「FT」はどれも**成功**（入れたとき）。「リバ」はリバウンド。失敗のボタンはありません
- **「？」の行**：番号が分からないときに。チームの記録になり、あとで一覧から番号を付けられます（設定で消せます。背番号を入れていないチームは、この1行だけ）
- **画面の下の「パスミス」「★ あとで見る」**：だれのかは決めずに、**時刻だけ**を残します（記録の上では「チームなし」）。あとで動画で見返すための目印。一覧から、チーム・番号を付けることもできます
- **ボタンの右上（狭いときは文字の下）の小さな数**：その選手がそのプレーをした回数。押せたことの確かめにもなります
- 名簿にない背番号が出たら、チームの帯の「**＋番号**」で足せます（番号の順のところに行が入ります）
- 同じボタンを 0.45 秒以内に2回押したときは、1回として数えます（二度押しの防止。フリースローの2本目は、間をあけて押せば数えます）
- まちがえたら「**↶ 取り消す**」で、いちばん新しい記録を取り消し（「やり直す」で戻せます）。どの記録も、メニューの「記録の一覧」で直せます

#### 画面の大きさと並べ方

画面の大きさと人数から、ボタンがいちばん押しやすくなる並べ方を自動で選びます（`core.js` の `BT.planLayout`）。

| 画面 | 15 人ずつ（＋「？」）のとき |
|---|---|
| ふつうのスマホの縦（390×664・Safari） | 2チームを左右に、上から1列ずつ。**全員が1画面に入る**（ボタン 約 32×29） |
| 大きいスマホ・iPad（縦・横） | 左右に1列ずつ。全員が1画面に入る（iPad はボタン 約 80×55） |
| iPhone SE の縦（375×553） | 左右に1列ずつ。入りきらない2行ほどは、行を縦にすべらせる |
| スマホの横向き | チームの中を2列にして、足りない分は縦にすべらせる（**スマホは縦向きがおすすめ**） |
| 相手の背番号を入れないとき | 自分のチームを画面の幅いっぱいに（相手は下に「チーム」の1行） |

ホーム画面に追加すると、Safari の帯がなくなるぶん、ボタンが大きくなります。

### メニュー（≡）

| | |
|---|---|
| 記録の一覧 | どの記録でも、番号・プレー・チーム・時刻（±0.5〜5 秒）を直す・消す |
| 集計 | ピリオドごとの得点、選手ごとの得点・2P／3P／FT（入れた本数）・リバウンド、チームなしのパスミス・★ の数（前の版で失敗も記録した試合は「成功/打った数」と成功率も） |
| チーム・背番号を直す | 試合の途中でも |
| 設定 | 名前の表示・「？」の行・タップ音・画面の色（端末に合わせる／明るい／暗い） |
| 書き出す | **記録のファイル（JSON）**＝動画の切り出し用・開き直し用、**記録の一覧（CSV）**、**選手ごとの集計（CSV）**。CSV は Excel でそのまま開ける形（BOM 付き UTF-8）。スマホでは「共有」（AirDrop・ファイルに保存・LINE など） |
| 試合を終える | 時計を止めて、集計を見る（まちがえて終えたら「続きを記録する」） |

ピリオドは、時計の右の「1Q」を押して「**2Q を始める**」。始めた時刻が記録に残ります（動画で場面を探すときの目印にも）。
押し忘れても、一覧で「2Q 開始」の時刻を直せば、それより後の記録は全部 2Q になります（ピリオドは記録ごとに持たず、「その時刻より前のいちばん新しいピリオドの始まり」で決めるため）。

### 記録の途中で困らないように

- **画面が自動で消えないように**しています（Screen Wake Lock。できない端末では、端末の自動ロックを長めに）
- 1つ記録するたびに、すぐ保存。画面を閉じても、開き直せば続きから（時計もスタートから進んだまま）
- 記録中に「戻る」（スワイプ・戻るボタン）をしても、ページを離れません
- 押せたことが分かるように：ボタンが光る・ボタンの回数が増える・下の帯に出る・振動（Android は vibrate、iPhone は iOS 18 からのスイッチの振動を使う）・音（設定でオン）
- ダブルタップの拡大・長押しのメニュー・文字の選択が出ないように
- ホーム画面に追加すると、電波が弱い体育館でも開き直せます（Service Worker。https で公開しているときだけ）

## 📹 撮影しながら記録する（この端末のカメラ）

iPad やスマホを三脚に立てて**録画しながら、同じ画面でタップして記録**できます。
録画を始めた時刻を記録と同じ時計で持つので、**あとで動画と記録の時刻を合わせる必要がありません**。
試合のあと「🎬 場面を切り出す」を押すと、そのまま「バスケ得点クリップ」が開き、記録した場面を動画から切り出せます。

1. 記録の画面で「**📹 撮影しながら記録する**」（スタート前の札・または ≡ メニューの「撮影」）→ カメラの大きな映像で、コートが入るように向きを決める
   - **撮る向き**を「横向き（コート全体）」か「縦向き」から選ぶ（はじめは横向き）。横向きなら、**端末を横向き**にしてから。選んだ向きと映像の向きが合わないときは、画面に注意が出ます
   - **画面の向きのロックをしたまま**横に置くと、画面が回らず、縦長の動画になってしまいます。そのときは注意の中の「**⟲ 上側を左にして使う**」「**⟳ 上側を右にして使う**」で、**アプリごと横向き**になり（記録のボタンも横向きに並びます）、横向きの動画が録れます。録画には「回して映す」向きを書くので、写真アプリ・パソコン・「バスケ得点クリップ」のどれでも横向きで再生されます
   - 撮影の画面の大きな映像の向きが、**録れる動画の向き**です。横倒し・さかさまのとき（端末による違い）は「**↻ 映像を回す**」で直せます。向きは、録画していないときに変えられます
2. ティップオフ（試合開始のジャンプボール）の瞬間に、赤い「**● 録画と記録をスタート**」（スタート前の札・上の帯・撮影の画面の「● 録画と記録を同時にスタート」）。**録画と記録が同時に始まります**
   - ウォーミングアップから撮るなら、撮影の画面の「● 録画だけ先に始める」。録画したまま、ティップオフで「▶ 記録をスタート」
3. 記録はいつもどおり。録画中は、右上にカメラの小さな映像（赤いふち）。押すと撮影の画面（録画の時間・大きさ・空き容量・「■ 録画を止める」）。録画中に端末を回して映像の向きが変わったときは、そこから**別の動画**として録ります（1本の動画の中で向きが変わらないように）
4. 「**試合を終える**」で録画も止まり、動画が仕上がります。「試合終了」の札と「書き出す」に、動画ごとに
   **🎬 場面を切り出す**（同じ端末の「バスケ得点クリップ」で、記録と一緒に開く）・**⬇ 保存**（写真・ファイルへ。MP4）・**🗑**（この端末から消す）

- **動画はこの端末（このブラウザ）の中に保存**します（IndexedDB。どこにも送りません）。録画は 1 秒ごとに保存するので、途中で画面が閉じても、そこまで（最後の1〜2秒を除く）は残り、次に開いたときに仕上げます
- 録画を止めて、また始めると、**別の動画**になります（どれも記録と時刻が合っています）。**ほかのアプリに切りかえたり、画面を消したりすると録画は止まる**ので、戻ったときに新しい動画として続けます
- 画質は設定で 720p（1時間 約 1.4GB）／1080p（約 2.8GB）。音も入れるかを選べます。撮影の画面に、空き容量と「あと何時間撮れるか」が出ます
- 電池をたくさん使います。電源につないでおくと安心です
- 録画は、ブラウザの録画（MediaRecorder）が作る「細切れの MP4」を、仕上げのときに**ふつうの MP4 に組み直します**（`js/fmp4.js`。中身は写さず、目次だけを作り直すので、1時間の動画でもすぐ終わり、容量も増えません）。長い動画でも、先のほうへすぐ飛べ、写真アプリにも保存できる形です
- 保存した動画と「記録のファイル（JSON）」を、ほかの端末（パソコンなど）の「バスケ得点クリップ」で開いても、**ファイル名（または長さ）で動画を見分けて、時刻を自動で合わせます**
- ホーム画面に追加して使う場合、「🎬 場面を切り出す」で開く「バスケ得点クリップ」も同じアプリの中で開くように、アプリの範囲（manifest の scope）を `/math-dialogue/` にしています（前に追加した人は、追加し直すとこの形になります）

## 動画から場面を切り出す（バスケ得点クリップ）

1. 「書き出す」→「**記録のファイル（JSON）**」で保存（同じ端末・同じブラウザなら、ファイルにしなくても読み込めます）
2. **バスケ得点クリップ**（https://dora9991.github.io/math-dialogue/basket-clips/ ）で、試合の動画を開いて「📲 タップ記録を読み込む」
3. **時刻を合わせる**：動画の撮影時刻から自動で合わせる目安が出ます（iPhone など）。手で合わせるときは、記録の1つ（ふつうは「スタート」）を選んで、動画の同じ場面（ジャンプボールの瞬間）で止めてボタンを押すだけ
4. **場面を選ぶ**：チーム・プレー（得点・シュート失敗・リバウンド・パスミス・★…）・選手で絞り込み、▶ で1場面ずつ、「▶ 続けて再生」でまとめて、「🎬 動画にする」で1本の動画に

くわしくは `basket-clips/README.md` の「📲 タップ記録（バスケ タップ記録）から切り出す」。

## 記録のデータの形

`js/core.js` の先頭コメントが仕様。書き出す JSON の例：

```json
{
  "format": "basket-tap", "version": 1, "app": "バスケ タップ記録",
  "id": "g…", "title": "", "date": "2026-10-19",
  "startedAt": 1792391412000, "startedAtText": "2026-10-19 15:30:12 (UTC+09:00)", "endedAt": null, "tz": 540,
  "teams": [
    { "name": "致遠館", "color": "#f4f4f4", "colorName": "白", "players": [{ "no": "7", "name": "たけし" }] },
    { "name": "城南", "color": "#2f6fed", "colorName": "青", "players": [{ "no": "4", "name": "" }] }
  ],
  "events": [
    { "id": "e1", "t": 0, "type": "period", "period": 1 },
    { "id": "e2", "t": 125.4, "type": "fg2", "team": 0, "no": "7", "period": 1 }
  ],
  "score": [2, 0],
  "types": { "fg2": { "label": "2P成功", "pts": 2 } }
}
```

- `t`：スタートを押してからの秒（0.1 秒まで）。`startedAt`（エポックミリ秒）と足せば、その時刻
- `team`：0 = 自分、1 = 相手、`null` = チームなし（画面の下の「パスミス」「★」）。`no`：背番号（文字。`"0"` と `"00"` は別）。`null` は番号なし。得点（`fg2` `fg3` `ft`）には必ずチームが付く
- `videos`：撮影しながら記録した動画（なくてよい）。`[{ vid, n, startedAt（録画を始めた時刻・エポックミリ秒）, endedAt, duration, name（保存するときのファイル名）, mime, w, h, bytes }]`。記録の `t` 秒 ＝ 動画の `t ＋ (startedAt(記録) − startedAt(動画)) / 1000` 秒。中身は入らない（この端末のブラウザの IndexedDB `btap-media` にある。形は `js/vstore.js` の先頭）
- `type`：記録の画面にあるのは `fg2` `fg3` `ft`（成功）・`reb`（選手の行）と `pass`（パスミス）・`mark`（★あとで見る）。前の版で記録した `fg2x` `fg3x` `ftx`（失敗）`ast` `stl` `blk` `tov` `foul` も、そのまま読み込み・集計・書き出しできる。`period`（ピリオドの始まり）
- ブラウザの中の保存（localStorage）は `btap:games`（試合の一覧）・`btap:game:<id>`（試合）・`btap:teams`（チーム）・`btap:prefs`（設定）

## 開発

```bash
node basket-tap/build.mjs                 # 1ファイル版を作り直す（公開するのはこれ）
node basket-tap/tests/unit.cjs            # 回帰テスト（63件）
node basket-tap/tests/fmp4.cjs            # MP4 の組み直し（10件。ffmpeg が必要）
node basket-tap/tests/e2e.cjs built       # 画面を通した確認（102件・約1分）。dev で開発版
node basket-tap/tests/e2e-camera.cjs      # 撮影しながら記録する（37件・約2分。先に basket-tap と basket-clips の build.mjs）
SHOTS=/tmp/shots node basket-tap/tests/e2e.cjs dev   # 画面の写真も撮る（見た目の確認用）
node basket-tap/tests/server.cjs          # 開発用サーバー → http://127.0.0.1:5193/
python3 basket-tap/tools/make_icons.py    # アイコンを作り直す（Pillow が必要）
bash basket-tap/tools/deploy-ghpages.sh   # 公開（gh-pages の basket-tap/ と basket-clips/index.html だけを入れかえる。ほかの公開物は変えない）
```

e2e は Playwright（`npm i -g playwright` など）と、その Chromium を使います。

## 確かめたこと（正直な範囲）

- **Chromium（Playwright・画面なし）で、スマホの大きさ（タッチ）にして操作**（`tests/e2e.cjs`）：準備（「4〜15」・番号のタップ・直接入力・名前）→ スタート → 選手の行のボタンを1回押して記録（#7 の 2P・相手 #00 の 3P・「？」の行のリバウンド）→ 画面の下のパスミス・★（チームなし）→ 二度押しの防止・フリースローの2本目 → 取り消す・やり直す（回数も戻る）→「＋番号」で足した行で、すぐに記録 → ピリオド → 一覧で直す・消す・チームなしのパスミスにチームと番号を付ける → 集計 → 書き出す（JSON・CSV 2種類）→ 開き直すと続きから → 試合を終える・続きを記録する → 設定（「？」の行）→ 次の試合で自分のチームが入っている。時計は Playwright の clock で進め、記録の時刻が 0.1 秒まで合うことを確かめた
- **画面の大きさ**：背番号 15 人ずつ（＋「？」の行）で、ふつうのスマホ（390×664）・大きいスマホ（430×800）・iPad 縦・横は、全部のボタンが1画面に収まり（すべらせない）、iPhone SE の縦（375×553）・スマホの横向き（750×340・667×320）は、ボタンの幅を保ったまま、入りきらない行を縦にすべらせて、いちばん下の「？」の行まで押せる。どの大きさでも、上の帯（時計・ピリオド・得点・メニュー）が重ならない（1時間を超えた時計・3 けたの得点でも）
- **撮影しながら記録する**（`tests/e2e-camera.cjs`）：Chromium のカメラを「その瞬間の時刻を白黒の模様で描いた映像」に差しかえて録画し、録れた動画のコマから時刻を読んで、**記録と動画の時刻のずれが ±0.15 秒以内**（実際は −0.05〜0 秒）であることを確かめた。録画 → スタート → 記録 → 画面を離れたあと新しい動画 → 試合を終える → 2本の動画が仕上がる → 保存した MP4 が ffprobe で読め、ふつうの MP4（moof なし）→ 記録のファイルに動画の情報 → 「🎬 場面を切り出す」でバスケ得点クリップが時刻あわせなしで開き、場面の位置が合う → 「この端末で記録した試合」から動画2 → 保存した動画とファイルを別のブラウザで開いても自動で合う → 録画の途中でページを閉じても仕上がる → スマホの大きさで上の帯が重ならない → 保存できなくなったら録画を止めて、そこまでを仕上げる → カメラを断られたときの案内
- **MP4 の組み直し**（`tests/fmp4.cjs`）：H.264＋AAC（B フレームあり）・VP9＋Opus・最後が切れたファイル・映像の始まりが遅いファイルで、組み直した MP4 の全部のコマの中身と時刻が元と同じ
- **していないこと**：本物の iPhone・iPad・Android での撮影。とくに、**Safari の録画（H.264）の形と、時刻のずれ**（Chromium では −0.05〜0 秒）、長い試合（1時間）での容量・電池・発熱、画面を離れたときの録画の止まり方。本物の iPhone・iPad（Safari）での操作。とくに、小さなボタン（ふつうのスマホで約 32×29）が試合中に押しやすいか、iPhone の振動（スイッチの振動を使う方法は iOS 18 から）・画面を消さない仕組み（Wake Lock）・ホーム画面に追加したときの動き・本物の試合での記録は、まだ確かめていません
- 「バスケ得点クリップ」との受け渡し（このアプリが書き出した JSON を、そのまま読み込めるか）は、`basket-clips/tests/unit.cjs` と `basket-clips/tests/e2e-log.cjs` で確かめています

## 注意

- iPhone の Safari は、**しばらく（7日ほど）開かないサイトの保存を消す**ことがあります。大事な試合は「書き出す」でファイルにも残してください（ホーム画面に追加したアプリは、この消え方をしにくくなります）
- ホーム画面に追加したアプリと、Safari で開いたページは、保存場所が別です（「バスケ得点クリップ」から「この端末で記録した試合」を読むときは、同じ Safari で開いてください。読めないときはファイルで）
- 時計は「試合の時計（残り時間）」ではなく、スタートからの経過時間です。止めずに進むので、動画と同じ時間の流れになります
