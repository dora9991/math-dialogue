# バスケ タップ記録

バスケの試合を見ながら、**だれが・何をしたか**（2P・3P・フリースローを入れた、リバウンド）と、**パスミス・あとで見たい場面の瞬間**を**タップで記録**し、
試合が終わったら**そのまま試合の動画から場面を切り出して**（トリミング）、選手ごと・プレーごとに見たり、1本の動画にしたりするブラウザアプリです。
前は「記録」（このアプリ）と「切り出し」（バスケ得点クリップ）の2つに分かれていたのを、**1本にまとめました**（2026-11）。

- インストール不要。**記録は、この端末（ブラウザの中）とクラウド（Supabase）の両方に保存**します。端末の保存が消えても、ほかの端末でも、合言葉で同じ記録が見られます。**動画はどこにも送りません**（この端末の中だけで扱います）
- 公開ページ：**https://dora9991.github.io/math-dialogue/basket-tap/** （iPhone は「共有」→「ホーム画面に追加」で、画面いっぱいに使えます）
- 1ファイル版：`public/basket-tap/index.html`（＋ `demo/` の見本の動画）
- **▶ 使い方のデモ**：ホームの「▶ デモ」。見本の試合と動画で、アプリが自動で動いて説明します（下の「使い方のデモ」）

## 2つの始め方

ホームに、大きなボタンが2つあります。

| | 流れ |
|---|---|
| **🏀 試合を見ながら記録する** | 試合の準備（チーム・背番号）→ ティップオフで「▶ スタート」→ タップで記録 →「≡ メニュー」→「試合を終える」→ **「動画のトリミングを行いますか？」** →「🎬 はい、動画を選ぶ」→ **✂️ 場面を切り出す**（① 動画を選ぶ → ② 時刻を合わせる → ③ 場面を見る・動画にする）。動画がまだなら「あとで」 |
| **🎬 撮った動画を見ながら記録する** | 試合の準備 →「🎬 動画を選んで、記録の画面へ」→ 動画を止めたり戻したりしながら記録 →「記録を終える」→ **試合のページ**（集計・CSV の書き出し）→「🎬 場面を見る・動画にする」（時刻あわせはいらない）→ 場面を見る・1本の動画にする |

### 画面の行き来（どこからでもホームへ）

```
ホーム ──🏀──▶ 試合の準備 ──▶ 記録の画面 ──「試合を終える」──▶ 試合のページ ──▶ ✂️ 場面を切り出す
  ▲  └──🎬──▶ 試合の準備 ──▶ 記録の画面（動画つき）──「記録を終える」──┘         │
  └────────────────── 🏠（どの画面にもある）─────────────────────────────────────┘
```

- **ホーム**：記録中の試合（「続きを記録する」）・2つの始め方・**✂️ 切り出し待ち**（試合を見ながら記録して、まだ動画から切り出していない試合。「🎬 動画を選ぶ」ですぐ続き）・**これまでの試合**（押すと試合のページ。札：● 記録中／✂️ 切り出し待ち／✓ 切り出しずみ／🎬 動画を見ながら記録／☁️ 保存ずみ・送る待ち）。クラウドにだけある試合（ほかの端末で記録した・この端末の保存が消えた）も、点線の枠で並びます（押すと、この端末に読み込む）
- **試合のページ**（試合を終えると開く）：得点・記録の数・☁️ クラウドの状態・切り出したか →「次にすること」の大きなボタン（✂️ 動画から場面を切り出す／🎬 場面を見る・動画にする）→ 📊 集計 → 💾 書き出す（集計 CSV・記録の一覧 CSV・記録のファイル JSON・撮影した動画）→ そのほか（📋 記録の一覧を見る・直す・👥 チーム・背番号を直す・▶ 続きを記録する・🗑 消す）→ **🏠 ホームへ戻る**
- **記録の画面**：「≡ メニュー」の「🏠 ホームへ」（記録は保存されたまま。ホームの「続きを記録する」で戻る）。終えたあとは「📄 試合のページへ」
- **✂️ 場面を切り出す**：上に「← 試合のページ」「🏠」、下に「✓ 終わる（試合のページへ）」「🏠 ホームへ」
- ブラウザ・スマホの「戻る」：切り出し → 試合のページ、試合のページ・準備 → ホーム（記録の途中だけは、うっかり離れないよう止める）

## ✂️ 場面を切り出す（トリミング）

前の「バスケ得点クリップ」の「📲 タップ記録から切り出す」を、このアプリの中に入れたものです（`js/trim.js`。得点の自動検出（映像の解析）は入れていません。使うときは、これまでどおり basket-clips/）。

1. **① 試合の動画を選ぶ**：「📂 動画を選ぶ」（iPhone・iPad は写真アプリから）。この端末で撮影しながら記録した動画は「📹 撮影した動画で切り出す」（時刻あわせなし）
   - **動画がまだ用意できていないとき**は、「← 試合のページ」「🏠」で戻ってかまいません。**記録は消えません**（この端末とクラウドに保存ずみ）。ホームの「✂️ 切り出し待ち」に残り、いつでも続きができます
2. **② 記録と動画の時刻を合わせる**（記録の時刻は「スタートを押してからの時間」なので、動画のどこがその時刻かを1か所決める。前と同じやり方）
   - **✋ 手で合わせる**：記録の1つ（ふつうは「スタート」）を選び、動画をその瞬間（ジャンプボール）で止めて「⏱ この瞬間が、選んだ記録」
   - **📅 撮影時刻から合わせる（目安）**：動画に撮影の時刻が入っていれば（iPhone など）
   - **↔ 指でずらして合わせる**：場面の枠（色の帯）を、目盛りの上で指で左右に動かすと、白い線（記録した瞬間）のコマが上に出る。プレーの瞬間で離して「✓ これで合わせる」。「±5秒」「±30秒」の目盛り・「−1秒／−0.1秒／+0.1秒／+1秒」も。各場面の「↔」なら、その場面を見本に
   - 全部の場面を「−1／−0.5／+0.5／+1秒」ずらす・その場面の「⌖」（いまの映像の位置を、その記録の瞬間にする）・「＋ ここでも合わせる」（撮影を途中で止めた動画）
   - 撮影しながら記録した動画・動画を見ながら記録した試合の、その動画は**自動でぴったり**
3. **③ 場面を選んで、見る・動画にする**：チーム・プレー・選手で絞り込み、▶ で1場面ずつ・「▶ 続けて再生」・「🎬 動画にする」（「#7 たけし 2P成功」などの文字入り。外せる）・各場面の ⬇。1場面の長さは「タップした瞬間の前 10 秒＋後 2 秒」（リバウンド・★ は前 5 秒。プレーごとに変えられる）。「＋ この瞬間を場面に足す」で記録にない場面も
   - できた動画は、その場で再生して確かめ、「⬇ 保存する」「📲 写真に保存」（iPhone・iPad）
   - 動画を見ながら記録した試合で 💬 コメント・スタンプがあれば「🎞 動画全体を書き出す（コメント入り）」も
4. 合わせた時刻・絞り込み・自分で足した場面は、**試合の記録と一緒に保存**（`game.trims`。この端末とクラウド）。あとで同じ動画を選ぶと、そのまま開く

## ☁️ クラウド（Supabase）

- 1つ記録するたびに、この端末に保存し、クラウドにも送る（記録の途中は 8 秒ごとにまとめて・試合を終えたらすぐ）。電波がないときは「送る待ち」に残し、つながったら・次に開いたときに送る。試合のページに「☁️ クラウドに保存ずみ／送る待ち」
- ログインはなし。**端末ごとの合言葉**（16 文字。「⚙ 設定」に出る）で読み書きする。ほかの端末で「⌨ ほかの端末の合言葉を入れる」か「🔗 ほかの端末で開くリンク」（`#k=合言葉`）で、同じ記録が見られる（試合はスマホで記録して、パソコンで動画から切り出す など）。合言葉を知っている人は記録を見られるので、チームの外には教えない
- 設定で「クラウドにも記録を残す」を外すと、この端末だけ（前の版と同じ）
- サーバー：Supabase の `math-labo-second`（ほかの教材と同じ所）の `public.btap_games`（owner＝合言葉の sha256・id・data（試合の記録そのまま）・summary・client_at・deleted_at）。表は直接さわれず（RLS・決まりなし）、`btap_put`（新しいものだけ上書き）・`btap_list`・`btap_get`・`btap_del`（消した印だけ）の関数（SECURITY DEFINER・anon で呼べる）だけで読み書きする。1試合 3MB・合言葉ごとに 3000 試合まで
- デモの試合（`game.demo`）は送らない

## 🔑 場面パック（購入コード・お試し 3 試合）

売り始めるまでは**スイッチを切ってある**（`js/license.js` の `MODE = 'off'`）。切ってあるあいだは、画面にも保存にも何も出ず、動きはこれまでと同じ。

**きまり**
- ずっと無料：記録（タップ）・集計・CSV と JSON の書き出し・クラウド・撮影・動画を見ながらの記録
- 有料の「場面パック」：クラブで **年 3万円**（人数は数えない。クラブに 1 つのコードで、何台の端末でも使える）。「🎬 場面を見る・動画にする」（切り出しの画面ぜんぶ）が使える。あとで入る「シュートの場所」も同じパック（`BT.license.can('shot', game)`。機能名で見る）
- お試し：この端末で、**はじめの 3 試合**まで無料。パックの機能を最初に使った試合が数えられ、数えた試合は、その端末でずっと開ける。切り出しは、**動画を付けたとき**に数える（画面を開いただけでは数えない）
- デモの試合（`game.demo`・デモ中）は、いつも使えて、数えない
- 期限の 30 日前から「あと n 日で期限です」。切れたら、パックのない状態にもどる（数えたお試しの試合は開ける）

**画面（スイッチが on のときだけ）**：切り出しを開くとき（`openTrim`。記録を終えたあとの「トリミングを行いますか？」も同じ道）に確かめ、使えなければ案内の小窓（お試しの 3 試合・無料のもの・「🔑 購入コードを入れる」・申し込みの窓口）。試合のページの切り出しボタンの下に「お試し：あと n 試合」「お試し中の試合です」「🔒 場面パックが必要です」、パックがあればクラブと期限。設定の末尾に「🔑 場面パック」（状態・コードを入れる・コードを外す）。

**端末に残すもの**：`btap:license`（`{ code, club, plan, expiresAt, checkedAt }`）・`btap:trial`（`[{ id, at, name }]` 3 件まで）・`btap:licmode`（見せる・試すとき用の `'on'`）。

**電波がなくても使える**：使う場面では、ネットを待たない。いちど確かめたコードは、期限まで端末の控えで通す。24 時間以上たって、つながっているときだけ、こっそり確かめ直す（サーバーで止められた・期限が切れたと分かったら控えを直す。つながらないときは控えのまま）。

**正直なところ**：端末の中の確認なので、詳しい人なら回避できる（コピー防止ではなく、クラブに気持ちよく払ってもらうための仕組み）。コードを止めても、その端末が次につながるまで（長くて 1 日ほど）は使える。

**試す（切りかえ）**：アドレスに `?lic=on` を付けて開くとオン（印が端末に残り、アドレスからは消える）。`?lic=off` でもどす。

**サーバー**：`cloud/license.sql`（Supabase の `math-labo-second`。**まだ流していない**）。表 `public.btap_codes`（コードそのものは持たず、sha256 だけ。RLS・決まりなし・anon に権限なし）と、関数 `btap_code_check`（アプリから anon で呼べる。`{ok:true, club, plan, expires_at}` か `{ok:false, error:'format'|'none'|'expired'|'revoked'}`）。作る・延ばす・止める関数は、SQL Editor からだけ動く。SQL Editor で：
```sql
select public.btap_code_new('○○高校バスケ部', 12, 'メモ');   -- コードは、この結果に 1 回だけ出る（控えて渡す）
select public.btap_code_extend('XXXX-XXXX-XXXX', 12);        -- 期限を 12 か月のばす
select public.btap_code_revoke('XXXX-XXXX-XXXX');            -- 止める
```

**本当に売り始めるときにすること**
1. `cloud/license.sql` を Supabase の SQL Editor に貼って Run（何回流しても大丈夫）
2. `js/license.js` の `MODE` を `'on'` に
3. 同じファイルの `CONTACT` に、申し込みの窓口（`https://…` か `mailto:…`）を入れる
4. `node basket-tap/build.mjs` で 1 ファイル版を作り直し、公開する
5. 1 つ目のコードを作り、自分の端末で入れて、切り出しが開くことを確かめる

確かめ：`tests/unit.cjs`（判定・コード・確かめ直し）と `tests/e2e-license.cjs`（画面。購入コードの返事は `tests/cloudstub.cjs`）。SQL は、手元の PostgreSQL 16 で 2 回流して、各関数と anon の権限・コードの形とばらつき（300 個が全部ちがう）を確かめた。**本物の Supabase では、まだ流していない**。

## ▶ 使い方のデモ

ホームの「▶ デモ」（はじめて開いたときは「▶ 使い方のデモを見る」も）→ 2つから選ぶ。アプリが自動で動き、下の帯で説明し、👆 が押すボタンへ動きます。帯の「⏸ 止める」「⏭ 次へ」「✕ やめる」。

1. **🏀 試合を見ながら記録 → 動画から場面を切り出す**（約2分半）：準備 → スタート → 選手の行のボタン（⏩ 早送りしながら）→ ★ → 試合を終える →「動画のトリミングを行いますか？」→ 動画を選ぶ → スタートで時刻を合わせる → ↔ 指でずらす → 場面を ▶ → #5 で絞る → 試合のページ → ホーム
2. **🎬 撮った動画を見ながら記録 → 集計・場面・動画**（約2分）：動画を選ぶ → 再生・止める →「2P → 5番」（スマホ）／選手の行（iPad）→ 記録を終える → 集計・CSV → 場面を見る（時刻あわせなし）→ 続けて再生 → ホーム

- 見本：`demo/demo.mp4`（78 秒・960×540・H.264。合成の試合映像）と `demo/demo.json`（起きたこと。動画の時刻・チーム・背番号）。作り直しは `node basket-tap/tools/make-demo-video.cjs`（パソコンの Chrome と playwright-core）
- デモの試合は、クラウドに送らず、自分のチームの名簿も変えず、終わる（やめる）と消す（`js/demo.js`・app.js の `S.demoMode`）

## 記録の画面（くわしく）

試合の準備：チーム名・ユニフォームの色を選ぶ（なくても大丈夫）。**背番号は「4〜15」「4〜18」などのボタンでまとめて選ぶ**（番号のマスで足す・外す。「4-15, 23」と直接入れても）。選手の名前（ニックネーム）も入れられる。自分のチームは保存され、次の試合からは最初から入っている。

### 記録の画面

```
┌ ● 12:05 ┐┌1Q┐   ┌ 12 ┐ − ┌ 8 ┐   ┌≡┐     ← 時計（スタートからの時間）・ピリオド・得点・メニュー
┌ 致遠館      12 ＋番号 ┐┌ 城南        8 ＋番号 ┐
│  4 [2P][3P][FT][リバ] ││  4 [2P][3P][FT][リバ] │  ← 選手1人＝1行。背番号の小さい順に上から
│  5 [2P][3P][FT][リバ] ││  5 [2P][3P][FT][リバ] │     押せば、その選手のプレーとして1回で記録
│  …                    ││  …                    │
│ 18 [2P][3P][FT][リバ] ││ 18 [2P][3P][FT][リバ] │
│  ？[2P][3P][FT][リバ] ││  ？[2P][3P][FT][リバ] │  ← だれか分からないとき（チームの記録）
└───────────────────────┘└───────────────────────┘
[パスミス] [★ あとで見る]  12:05 2P成功 +2 / 致遠館 #7  [↶ 取り消す]   ← いつでも押せる（チーム・選手は決めない）
```

- **選手の行**：「2P」「3P」「FT」はどれも**成功**（入れたとき）。「リバ」はリバウンド。ふだんは失敗のボタンはありません
- **シュート成功率も出したいとき・ファウルも数えたいとき**：「≡ メニュー」→「設定」の「**選手のボタン**」で、
  - 「**シュートの失敗**」→ 2P・3P・FT のそれぞれのとなりに失敗の「**×**」（そのシュートの色のふち・少し細め）。集計が「成功/打った数」と**シュート成功率**になります
  - 「**リバウンドを分ける**」→「リバ」が「**Oリバ**」（オフェンス）と「**Dリバ**」（ディフェンス）の2つに（狭いときは「OR」「DR」）。集計に **OR・DR の列**（リバウンドの列は合計）
  - 「**アシスト**」「**スティール**」→ リバのあとに「アシスト」「スティール」（狭いときは「AS」「ST」）。集計にそれぞれの数
  - 「**ファウル**」→ いちばん後ろに「ファウル」（狭いときは「F」）。回数が**4つ目で黄・5つ目で赤**。集計に**ピリオドごとのチームファウル**（5つ目からは赤）
  - ボタンを多く足して、1段ではボタンが細くなりすぎるとき（スマホの縦など）は、選手の行を**2段**にします（上の段にシュート、下の段にリバ・アシスト・スティール・ファウル）
  - どちらも、はじめは出しません（ふだんの4つのボタンのまま）。ボタンが増えるぶん1つずつは小さくなり、並べ方も自動で選び直します（例：iPad の横・15 人ずつで 2P 67×37・× 50×37。スマホで2チームとも大勢のときは、行を縦にすべらせて選びます）
- **「？」の行**：番号が分からないときに。チームの記録になり、あとで一覧から番号を付けられます（設定で消せます。背番号を入れていないチームは、この1行だけ）
- **画面の下の「パスミス」「★ あとで見る」**：だれのかは決めずに、**時刻だけ**を残します（記録の上では「チームなし」）。あとで動画で見返すための目印。一覧から、チーム・番号を付けることもできます
- **ボタンの右上（狭いときは文字の下）の小さな数**：その選手がそのプレーをした回数。押せたことの確かめにもなります
- 名簿にない背番号が出たら、チームの帯の「**＋番号**」で足せます（番号の順のところに行が入ります）
- 同じボタンを 0.45 秒以内に2回押したときは、1回として数えます（二度押しの防止。フリースローの2本目は、間をあけて押せば数えます）
- まちがえたら「**↶ 取り消す**」で、いちばん新しい記録を取り消し（「やり直す」で戻せます）。どの記録も、メニューの「記録の一覧」で直せます

#### 画面の大きさと並べ方

画面の大きさと人数から、ボタンがいちばん押しやすくなる並べ方を自動で選びます（`core.js` の `BT.planLayout`）。

| 画面 | 15 人ずつ（＋「？」）のとき |
|---|---|
| ふつうのスマホの縦（390×664・Safari） | 2チームを左右に、上から1列ずつ。**全員が1画面に入る**（ボタン 約 32×29） |
| 大きいスマホ・iPad（縦・横） | 左右に1列ずつ。全員が1画面に入る（iPad はボタン 約 80×55） |
| iPhone SE の縦（375×553） | 左右に1列ずつ。入りきらない2行ほどは、行を縦にすべらせる |

ホーム画面に追加すると、Safari の帯がなくなるぶん、ボタンが大きくなります。

### メニュー（≡）

| | |
|---|---|
| 記録の一覧 | どの記録でも、番号・プレー・チーム・時刻（±0.5〜5 秒）を直す・消す |

| チーム・背番号を直す | 試合の途中でも |

ピリオドは、時計の右の「1Q」を押して「**2Q を始める**」。始めた時刻が記録に残ります（動画で場面を探すときの目印にも）。
押し忘れても、一覧で「2Q 開始」の時刻を直せば、それより後の記録は全部 2Q になります（ピリオドは記録ごとに持たず、「その時刻より前のいちばん新しいピリオドの始まり」で決めるため）。

### 記録の途中で困らないように

- **画面が自動で消えないように**しています（Screen Wake Lock。できない端末では、端末の自動ロックを長めに）
- 1つ記録するたびに、すぐ保存。画面を閉じても、開き直せば続きから（時計もスタートから進んだまま）
- 記録中に「戻る」（スワイプ・戻るボタン）をしても、ページを離れません
- 押せたことが分かるように：ボタンが光る・ボタンの回数が増える・下の帯に出る・振動（Android は vibrate、iPhone は iOS 18 からのスイッチの振動を使う）・音（設定でオン）
- ダブルタップの拡大・長押しのメニュー・文字の選択が出ないように
- ホーム画面に追加すると、電波が弱い体育館でも開き直せます（Service Worker。https で公開しているときだけ）

## 📹 撮影しながら記録する（この端末のカメラ）

iPad やスマホを三脚に立てて**録画しながら、同じ画面でタップして記録**できます。
録画を始めた時刻を記録と同じ時計で持つので、**あとで動画と記録の時刻を合わせる必要がありません**。
試合のあと「📹 撮影した動画で切り出す」を押すと、そのまま記録した場面を動画から切り出せます（時刻あわせなし）。

1. 記録の画面で「**📹 撮影しながら記録する**」（スタート前の札・または ≡ メニューの「撮影」）→ カメラの大きな映像で、コートが入るように向きを決める
   - **撮る向き**を「横向き（コート全体）」か「縦向き」から選ぶ（はじめは横向き）。横向きなら、**端末を横向き**にしてから。選んだ向きと映像の向きが合わないときは、画面に注意が出ます
   - **画面の向きのロックをしたまま**横に置くと、画面が回らず、縦長の動画になってしまいます。そのときは注意の中の「**⟲ 上側を左にして使う**」「**⟳ 上側を右にして使う**」で、**アプリごと横向き**になり（記録のボタンも横向きに並びます）、横向きの動画が録れます。録画には「回して映す」向きを書くので、写真アプリ・パソコン・「バスケ得点クリップ」のどれでも横向きで再生されます
   - 撮影の画面の大きな映像の向きが、**録れる動画の向き**です。横倒し・さかさまのとき（端末による違い）は「**↻ 映像を回す**」で直せます。向きは、録画していないときに変えられます
2. ティップオフ（試合開始のジャンプボール）の瞬間に、赤い「**● 録画と記録をスタート**」（スタート前の札・上の帯・撮影の画面の「● 録画と記録を同時にスタート」）。**録画と記録が同時に始まります**
   - ウォーミングアップから撮るなら、撮影の画面の「● 録画だけ先に始める」。録画したまま、ティップオフで「▶ 記録をスタート」
3. 記録はいつもどおり。録画中は、記録の画面にカメラの映像（**ワイプ**。赤いふち・左下に「● 録画」と録画の時間）。押すと撮影の画面（録画の時間・大きさ・空き容量・「■ 録画を止める」）。録画中に端末を回して映像の向きが変わったときは、そこから**別の動画**として録ります（1本の動画の中で向きが変わらないように）
   - **ワイプの大きさ**は、映像の右上の「＋」「－」か、撮影の画面の「ワイプの大きさ」で **小・中・大・特大**（はじめは中。端末に覚えておきます）
     - **中・大**：選手のボタンに**重ならない所**に出します。横長の画面（iPad・スマホの横向き）は右側の列（下の「パスミス」「★」・いま記録したものも、映像の下へ）、縦長の画面は上の帯の下。ボタンは残りの広さで並べ直します（少し小さくなります）
     - **中**は、ボタンの行が縦にすべらない大きさまで（iPad の横なら、画面の約 1/3 の幅。小さなスマホで2チームとも大勢のときは、上の帯の小さな映像のまま）。**大**は、もっと大きく（人数が多いと、行を縦にすべらせて選びます）
     - **小**：上の帯の中の小さな映像（前の版と同じ）
     - **特大**：**相手チームの欄を小さくして映像の下に移し**、その分、映像をいちばん大きく映します。自分のチームのボタンは広いまま（行がすべらない大きさ）で、パスミス・★はその下。横長の画面は右側の列（上から映像・相手チーム）、縦長の画面は上の帯の下（映像・相手チーム）。相手の人数が多いと、相手の行は縦にすべらせて選びます（名簿なしなら「チーム」の1行だけ）
       - 例（自分 12 人＋？）：iPad の横・相手も名簿あり → 映像 643×361・相手は2列で全員が入る・自分のボタン 109×46。相手の名簿なし → 映像 725×408。スマホの横（844×390）→ 映像 410×231（大の 342×192 より大きい）・自分は2列でボタンがすべらない・相手は2行見えて、あとは縦にすべらせる
4. 「**試合を終える**」で録画も止まり、動画が仕上がります。「動画のトリミングを行いますか？」に「**📹 撮影した動画で切り出す（時刻あわせなし）**」。試合のページの「書き出す」に、動画ごとに **🎬 場面を切り出す**・**⬇ 保存**（写真・ファイルへ。MP4）・**🗑**（この端末から消す）

- **撮った動画は、試合のあと「📲 写真に保存」**（共有の画面で「ビデオを保存」）で iPhone の写真アプリへ（iCloud 写真を使っていれば iCloud にも。「ファイルに保存」なら iCloud Drive など）。ウェブのアプリは、写真アプリへ勝手には保存できない（1本ずつ、ボタンを押して保存する）ため。保存したら「✓ 保存した」になり、🗑 でこのアプリの中から消すと、次の試合の分が空きます
- 録画のあいだは、**動画をいったんこの端末（このブラウザ）の中にためます**（IndexedDB。どこにも送りません）。録画は 1 秒ごとに保存するので、途中で画面が閉じても、そこまで（最後の1〜2秒を除く）は残り、次に開いたときに仕上げます
- **保存が一度とぎれたとき**（iPhone で画面を消した・ほかのアプリに切りかえた などで、ブラウザに保存のつながりを切られたとき）は、つなぎ直して続け、それでもだめなら、そこまでを仕上げて**新しい動画として録画を続けます**（1分に2回まで）。「保存場所がいっぱい」と出すのは、本当にいっぱい（QuotaExceededError）のときだけ。それはこのサイトのブラウザの保存場所のことで、iPhone 本体の空きとは別です（前の版は、容量と関係のない失敗でも「空きが足りない」と出ていた）
- 録画を止めて、また始めると、**別の動画**になります（どれも記録と時刻が合っています）。**ほかのアプリに切りかえたり、画面を消したりすると録画は止まる**ので、戻ったときに新しい動画として続けます
- 画質は設定で 720p（1時間 約 1.4GB）／1080p（約 2.8GB）。音も入れるかを選べます。撮影の画面に、空き容量と「あと何時間撮れるか」が出ます
- 電池をたくさん使います。電源につないでおくと安心です
- 録画は、ブラウザの録画（MediaRecorder）が作る「細切れの MP4」を、仕上げのときに**ふつうの MP4 に組み直します**（`js/fmp4.js`。中身は写さず、目次だけを作り直すので、1時間の動画でもすぐ終わり、容量も増えません）。長い動画でも、先のほうへすぐ飛べ、写真アプリにも保存できる形です
- 保存した動画を、ほかの端末（パソコンなど）で「📂 動画を選ぶ」で開いても（記録はクラウドの合言葉か、記録のファイルで）、**ファイル名（または長さ）で動画を見分けて、時刻を自動で合わせます**
- アプリの範囲（manifest の scope）は `/math-dialogue/` のまま（前の版で、バスケ得点クリップもアプリの中で開くようにしたため。いまは切り出しもこのアプリの中）

## 🎬 撮った動画を見ながら記録する

試合の時間に追われずに、**撮っておいた動画を見ながら**記録できます。記録の時刻は「**動画の時刻**」なので、
**止めたり、戻したり、ゆっくり再生したり、1コマずつ動かしたり**しながら、落ち着いて正確に記録できます。

1. ホームの「**🎬 撮った動画を見ながら記録する**」（または、試合の準備のいちばん下の「🎬 撮った動画を見ながら記録する」）→ チーム・背番号を選ぶ →「**🎬 動画を選んで、記録の画面へ**」で動画を選ぶ（iPhone・iPad は写真アプリから）
2. 記録の画面の上に動画、その下に操作のボタン：**−5秒・◀コマ・▶／⏸・コマ▶・+5秒・速さ（×1・×0.5・×0.25・×2）・💬・⇄**
   - コマ送りは押し続けると続けて動きます（1秒のコマ数は再生したときに測ります。分からなければ 30 コマ）。映像を押しても、再生・一時停止
   - 動画の下の細いバーを指でなぞると、好きな所へ。バーには、記録（チームの色）・ピリオドの始まり（白）・コメント（黄色）の印
   - 左上の時計は**動画の時刻**（0.1 秒まで）。得点は**いま映っている時刻までの得点**、ピリオドもその時刻のもの
3. 記録のしかたは2通り（「⇄」か、設定の「動画を見ながら記録するときの入力」で切りかえ。はじめは自動）
   - **選手ごとの行**（ふつうの記録と同じ）：iPad など、行が入りきる画面
   - **「2P → 14番」**：スマホなど、4〜18 番の行が入りきらない画面。チームごとに、プレーのボタン（2P・3P・FT・リバ…設定で足したボタンも）と背番号のボタンが並び、**プレーと背番号を1つずつ選ぶ**と記録されます。**どちらが先でもよい**（「14」→「2P」でも）。時刻は**はじめに押したとき**。選びかけは画面の下に「2P → 番号は？」と出て、同じボタンをもう一度押すか「やめる」でやめられます
     - 選びかけのまま、動画が 20 秒より大きく動いたら、選びかけは自動でやめます（まちがえて押したプレーが、あとで押した背番号とくっついて記録されないように。画面の下に知らせが出ます）
     - 背番号を入れていないチームは、プレーのボタンだけが並び、**押すだけ**でチームの記録になります
4. **時刻をぴったりに**：画面の下の「いま記録したもの」を押す（または「記録の一覧」で選ぶ）→「**📍 映像で時刻を合わせる（コマ送り）**」→ 動画がその記録の時刻で止まるので、◀コマ・コマ▶で合わせて「**✓ この時刻**」。「いまの映像の時刻にする」「🎬 この場面を見る（2秒前から）」も
5. **💬 コメント・スタンプ**：その場面で「💬」→ スタンプ（👍 いいね・👏 ナイス・🔥 すごい など 12 種類・1つのコメントに 6つまで）・コメント・タグ（ヘルプ・リバウンドなど。文の中の「#ことば」もタグに）・出す長さ（3・5・8 秒）。その時刻から数秒、映像の上に出ます。「≡ メニュー」→「コメントの一覧」で見る・直す・消す
6. ピリオドは、動画をその始まり（ティップオフ・最初のスローイン）まで動かしてから「1Q」→「2Q を始める」
7. 終わったら「≡ メニュー」→「記録を終える」→ **試合のページ**（集計・CSV の書き出しがすぐできる）→「**🎬 場面を見る・動画にする**」で、その動画のまま（選び直さずに）時刻あわせなしで場面を切り出せます。💬 コメント・スタンプも、切り出した動画・動画全体の書き出しに入ります

- 動画の中身は保存しません（ファイル名・大きさ・長さ・見ていた所だけ）。**続きを記録するときは、同じ動画をもう一度選びます**（見ていた所から始まります）。長さの違う動画を選ぶと、注意が出ます
- キーボード（iPad のキーボード・パソコン）：スペース 再生／一時停止・← → 5秒（Shift で 1秒）・「,」「.」1コマ

## 📍 シュートの場所（設定）

コーチの方からの要望で、**どこから打ったシュートか**も記録できるようにしました。「≡ メニュー」→「設定」の「**シュートの場所**」で選びます（**はじめはオフ**。オフのときは、前とまったく同じです）。

売り始めたあとは「🔑 場面パック」の機能になります（`shotLocOn()` が `BT.license.can('shot', game)` も見る。場所を付けた試合が、お試しの 1 試合に数えられる。お試しを使い切ってコードがないときは、オンにしても聞かず、設定にわけを書く）。場面パックのスイッチが off のあいだは、だれでも使えます。

1. 2P・3P（成功も、設定で出した失敗の「×」も）を記録すると、**記録はいつもどおり先にすませて**（時刻は押した瞬間）、そのあと**ハーフコートの図**が出ます（「#14 2P成功：どこから？」）。ゴールが上。**打った場所を1回押す**と、その記録に場所が付き、画面の下に「📍 3P 右コーナー」などと出ます
   - 「**あとで**」で飛ばせます（記録は残ります。場所はあとから一覧で付けられます）
   - **試合を見ながら記録**しているときは、図が選手のボタンをふさぐので、**6 秒押さなければ自動で閉じます**（細いバーが縮みます。`js/shot.js` の `BT.shot.WAIT`）
   - **撮った動画を見ながら記録**するときは、自動では閉じません（図が出ている間は動画も止まっています）。落ち着いて場所を選べるので、こちらに特に向いています。「2P → 14番」でも、選手ごとの行でも聞きます
   - **フリースローは聞きません**。使い方のデモの最中も聞きません
2. **コート**：「ふつう：3P の線あり」か「**ミニバス：3P の線なし**」（ミニバスは 3P のシュートがないので、図に 3P の線を描かず、遠いシュートは「ロング」）
3. **直す**：「記録の一覧」の行に「📍 ゾーン」。行を押すと「場所」の欄に小さなコート（印つき）。押すと場所を付ける・動かす、「場所を消す」で消す。プレーをフリースローなどに直すと、場所は消えます
4. **集計**（試合のページ・「≡ メニュー」→「集計」）：場所のあるシュートが1本でもあれば「**📍 シュートの場所**」。自分／相手・選手（全員と、場所のある選手）で絞り込み、**図**（入った＝チームの色の丸に濃いふち・外れ＝×）と**ゾーンごとの表**（外れも記録した試合は「成功/打った数」と成功率）・場所あり／なしの本数
5. **書き出し**：記録の一覧（CSV）の**いちばん後ろ**に「場所X・場所Y・場所（ゾーン名）」（場所のある試合だけ。前からの列の位置は変わりません）。JSON は記録に `x`・`y`

### 場所の形とゾーンの決め方（`js/core.js` の `BT.shotZone`）

- 記録の `x`・`y`（0〜1・0.001 まで。2P・3P の成功と失敗だけ。なければ場所なし）。**攻めるゴールの向きに関係なく、ハーフコートの中の位置**：`x` はゴールを向いて左のサイドライン 0 … 右 1、`y` はゴールの後ろのベースライン 0 … センターライン 1。試合には、場所を記録したときのコート `court: 'std' | 'mini'`
- コートは FIBA の寸法（幅 15 m・奥行き 14 m・ゴールはベースラインから 1.575 m・3P は 6.75 m の弧とサイドラインから 0.9 m のまっすぐな線・ペイント 4.9×5.8 m・フリースローサークル 1.8 m・ノーチャージの半円 1.25 m）。ミニバスも、図と距離はこの形のまま（3P の線だけ描かない）
- ゾーン：ゴールから 1.25 m 以内は**ゴール下**、ペイントの中（線の上も）は**ペイント**、3P の線の外（線の上は 2P）は**3P**、そのほかは**ミドル**。向きは、ゴールの真上から左右 22.5° までが**正面／トップ**、3P はさらに 67.5° より外（ゴールより下も）が**コーナー**、その間が**ウィング**。ミニバスは 6.75 m より遠いと**ロング**（左／正面／右）
- 読み込むときは、2P・3P の記録で 0〜1 の数の `x`・`y` だけを残します（ほかは捨てる）

## バスケ得点クリップとの関係

切り出しは、このアプリの中（✂️ 場面を切り出す）でできるようになりました。**バスケ得点クリップ**（`basket-clips/`）は、得点を映像から自動で探す（解析）ためのアプリとして、そのまま残っています。
このアプリが書き出す記録のファイル（JSON）は、これまでどおりバスケ得点クリップでも読み込めます（形は変えていません。切り出しの状態 `trims` が増えただけ）。

## 記録のデータの形

`js/core.js` の先頭コメントが仕様。書き出す JSON の例：

```json
{
  "format": "basket-tap", "version": 1, "app": "バスケ タップ記録",
  "id": "g…", "title": "", "date": "2026-10-19",
  "startedAt": 1792391412000, "startedAtText": "2026-10-19 15:30:12 (UTC+09:00)", "endedAt": null, "tz": 540,
  "teams": [
    { "name": "致遠館", "color": "#f4f4f4", "colorName": "白", "players": [{ "no": "7", "name": "たけし" }] },
    { "name": "城南", "color": "#2f6fed", "colorName": "青", "players": [{ "no": "4", "name": "" }] }
  ],
  "events": [
    { "id": "e1", "t": 0, "type": "period", "period": 1 },
    { "id": "e2", "t": 125.4, "type": "fg2", "team": 0, "no": "7", "period": 1 }
  ],
  "score": [2, 0],
  "types": { "fg2": { "label": "2P成功", "pts": 2 } }
}
```

- `t`：スタートを押してからの秒（0.1 秒まで）。`startedAt`（エポックミリ秒）と足せば、その時刻
- `team`：0 = 自分、1 = 相手、`null` = チームなし（画面の下の「パスミス」「★」）。`no`：背番号（文字。`"0"` と `"00"` は別）。`null` は番号なし。得点（`fg2` `fg3` `ft`）には必ずチームが付く
- `videos`：撮影しながら記録した動画（なくてよい）。`[{ vid, n, startedAt（録画を始めた時刻・エポックミリ秒）, endedAt, duration, name（保存するときのファイル名）, mime, w, h, bytes }]`。記録の `t` 秒 ＝ 動画の `t ＋ (startedAt(記録) − startedAt(動画)) / 1000` 秒。中身は入らない（この端末のブラウザの IndexedDB `btap-media` にある。形は `js/vstore.js` の先頭）
- `mode: "video"`：撮った動画を見ながら記録した試合。`t` は**その動画の時刻**（秒）。`src: { name, size, duration, w, h }`（見ていた動画のファイル。中身は入らない）・`rvPos`（見ていた所）。`videos` に `file: true` の1本が入り、その `startedAt` は記録の `startedAt` と同じ（バスケ得点クリップで同じ動画を開くと、時刻あわせなしで合う）
- `notes`：💬 コメント・スタンプ（なくてよい）。`[{ id, t（記録の時刻）, dur（出す長さ・秒）, text, stamps, tags, at }]`。形と絵は `js/notes.js`（バスケ得点クリップの `basket-clips/js/notes.js` をそのまま写したもの。直すときは両方に）
- `type`：記録の画面にあるのは `fg2` `fg3` `ft`（成功）・`reb`（選手の行）と `pass`（パスミス）・`mark`（★あとで見る）。設定で `fg2x` `fg3x` `ftx`（失敗）・`oreb` `dreb`（オフェンス・ディフェンスのリバウンド。`reb` の代わり）・`ast`（アシスト）・`stl`（スティール）・`foul`（ファウル）のボタンも出せる。前の版で記録した `blk` `tov` も、そのまま読み込み・集計・書き出しできる。`period`（ピリオドの始まり）
- `trims`：✂️ 場面を切り出したときの状態（なくてよい）。`{ [動画の見分け（ファイル名|大きさ、撮影した動画は cam:vid）]: { anchors: [{ t, v }]（記録の t 秒 ＝ 動画の v 秒）, how（manual・meta・camera・review）, view（絞り込み）, off（外した場面）, adds（自分で足した場面）, win（1場面の長さ）, captions } }`・`trimmed`（1回でも時刻を合わせた）・`trimLast`。`updatedAt`（最後に直した時刻。クラウドの新しさ比べ）・`demo`（使い方のデモの試合。クラウドに送らない）
- ブラウザの中の保存（localStorage）は `btap:games`（試合の一覧）・`btap:game:<id>`（試合）・`btap:teams`（チーム）・`btap:prefs`（設定）・`btap:cloudkey`（合言葉）・`btap:cloudq`（クラウドへの送る待ち）・`btap:cloudok`（送った時刻）

## 開発

```bash
node basket-tap/build.mjs                 # 1ファイル版を作り直す（公開するのはこれ）
node basket-tap/tests/unit.cjs            # 回帰テスト（182件）
node basket-tap/tests/fmp4.cjs            # MP4 の組み直し（15件。ffmpeg が必要）
node basket-tap/tests/e2e.cjs built       # 画面を通した確認（142件・約1分）。dev で開発版
node basket-tap/tests/e2e-camera.cjs      # 撮影しながら記録する（86件・約1分半。先に basket-tap の build.mjs。保存した MP4 の確かめに ffprobe）
node basket-tap/tests/e2e-review.cjs built  # 撮った動画を見ながら記録する（87件・約2分。テスト用の動画は ffmpeg、なければ Chrome で作る。60 コマ/秒・縦長の動画の確認は ffmpeg があるときだけ）
node basket-tap/tests/e2e-shot.cjs built     # シュートの場所（67件・約1分）
node basket-tap/tests/e2e-license.cjs built  # 場面パック：購入コード・お試し 3 試合（72件・約1分。購入コードの返事は tests/cloudstub.cjs）
node basket-tap/tools/make-demo-video.cjs # デモの見本の動画を作り直す（パソコンの Chrome と playwright-core）
SHOTS=/tmp/shots node basket-tap/tests/e2e.cjs dev   # 画面の写真も撮る（見た目の確認用）
node basket-tap/tests/server.cjs          # 開発用サーバー → http://127.0.0.1:5193/
python3 basket-tap/tools/make_icons.py    # アイコンを作り直す（Pillow が必要）
bash basket-tap/tools/deploy-ghpages.sh   # 公開（gh-pages の basket-tap/ と basket-clips/index.html だけを入れかえる。ほかの公開物は変えない）
```

e2e は Playwright（`npm i -g playwright` など）と、その Chromium を使います。Playwright の Chromium がないときは、playwright-core とパソコンの Chrome でも動きます（`PW=…/node_modules/playwright-core CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" node basket-tap/tests/e2e.cjs dev`）。テストは、本物のクラウドには送りません（`tests/cloudstub.cjs`）。

### 1本にまとめた版（2026-11-07・パソコンの Chrome とアプリの中のブラウザ）

- **回帰テスト**：unit 117件・e2e 142件・e2e-review 87件 すべて通過。e2e-camera は 86件中 84件（のこり2件は、保存した MP4 を ffprobe で読む確かめ。このパソコンに ffprobe がないため未確認）
- **試合を見ながら記録 → 終える**：試合のページへ移り「動画のトリミングを行いますか？」（はい・あとで。撮影した動画があれば「📹 撮影した動画で切り出す」）。「あとで」→ 試合のページ・ホームの「✂️ 切り出し待ち」に残る・押すと試合のページ・終えた試合の記録の画面は押しても記録しない・「続きを記録する」で戻せる
- **✂️ 場面を切り出す**：見本の動画で、スタートで時刻を合わせる → 場面が並ぶ（記録の時刻＋3秒）→「↔ 指でずらして合わせる」で目盛りを指でなぞると、ずらす量が変わり、「✓ これで合わせる」で全部の場面がずれる → 絞り込み・▶・続けて再生。同じ動画を選び直すと、合わせた時刻のまま開く。動画を見ながら記録した試合は、記録した動画のまま時刻あわせなし（記録の時刻 ＝ 動画の時刻）で場面が全部並ぶ。撮影しながら記録した動画1・2は、どちらも自動でぴったり（±0.02 秒）・別のブラウザで記録のファイルと保存した動画を開いても自動で合う
- **クラウド**：本物の Supabase に送って、一覧・読み込みができることを確かめた（確かめた記録は消した）。合言葉の作り方・入れ方は unit で。古いもので新しいものを上書きしない（サーバーの関数で確かめた）
- **デモ**：2つとも、iPad くらいの画面（800×600）とスマホ（375×812）で、最後まで止まらずに動くこと・デモの試合がクラウドに送られず、終わると消えることを確かめた
- **画面の大きさ**：スマホ（375・390）で、ホーム・試合のページ・切り出し（動画が上に残り、場面の一覧を下へ送れる。続けて再生の操作は動画の下の行）が横にはみ出さない
- **していないこと**：本物の iPhone・iPad（Safari）での切り出し・動画の書き出し（MediaRecorder の MP4）・写真アプリへの保存、本物の試合の動画での時刻あわせ、電波の弱い体育館でのクラウドの送り直し

### 前の版まで

- **Chromium（Playwright・画面なし）で、スマホの大きさ（タッチ）にして操作**（`tests/e2e.cjs`）：準備（「4〜15」・番号のタップ・直接入力・名前）→ スタート → 選手の行のボタンを1回押して記録（#7 の 2P・相手 #00 の 3P・「？」の行のリバウンド）→ 画面の下のパスミス・★（チームなし）→ 二度押しの防止・フリースローの2本目 → 取り消す・やり直す（回数も戻る）→「＋番号」で足した行で、すぐに記録 → ピリオド → 一覧で直す・消す・チームなしのパスミスにチームと番号を付ける → 集計 → 書き出す（JSON・CSV 2種類）→ 開き直すと続きから → 試合を終える・続きを記録する → 設定（「？」の行）→ 次の試合で自分のチームが入っている。時計は Playwright の clock で進め、記録の時刻が 0.1 秒まで合うことを確かめた
- **画面の大きさ**：背番号 15 人ずつ（＋「？」の行）で、ふつうのスマホ（390×664）・大きいスマホ（430×800）・iPad 縦・横は、全部のボタンが1画面に収まり（すべらせない）、iPhone SE の縦（375×553）・スマホの横向き（750×340・667×320）は、ボタンの幅を保ったまま、入りきらない行を縦にすべらせて、いちばん下の「？」の行まで押せる。どの大きさでも、上の帯（時計・ピリオド・得点・メニュー）が重ならない（1時間を超えた時計・3 けたの得点でも）

## 注意

- iPhone の Safari は、**しばらく（7日ほど）開かないサイトの保存を消す**ことがあります。クラウドに残していれば、ホームの「これまでの試合」に「☁️ クラウドだけ」として出るので、押せば読み込み直せます（クラウドを使わないときは「書き出す」でファイルにも残してください）
- ホーム画面に追加したアプリと、Safari で開いたページは、保存場所が別です（合言葉も別になります。同じ記録を見たいときは「⚙ 設定」→「⌨ ほかの端末の合言葉を入れる」）
- 撮影しながら記録した動画は、この端末（このブラウザ）の中だけにあります。クラウドには送りません。試合のあと「📲 写真に保存」してください
- 時計は「試合の時計（残り時間）」ではなく、スタートからの経過時間です。止めずに進むので、動画と同じ時間の流れになります
