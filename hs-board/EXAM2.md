# 入試の類題②（2問目の類題）の作り方 ─ 執筆担当むけ

いまある入試の類題（`scenes/<元のID>.js`、例 `kyushu26-1`）は、元の入試問題と「同じ分野・ねらい・形式・難しさ」の **自作問題（類題①）** と、その黒板解説。
ここでは、同じ入試問題について、**場面も数値もちがう2問目の類題（類題②）** と、その黒板解説を作る。ID は `<元のID>b`（例 `kyushu26-1b`）。

**大事な約束：ファイルを消さない・動かさない（`rm`・`mv`・`rmdir` は使わない）。** 書くのは担当の `scenes/<ID>.js` と、scratchpad の自分の作業フォルダだけ。`js/lessons.js`・`js/`・`tools/`・ほかの台本・類題①は書きかえない。git・公開はしない。インターネットは使わない。

## 1. 読むもの
1. `hs-board/AUTHORING.md`（台本の書き方・部品・ことば・検査。すべて守る）
2. 類題①の台本 `scenes/<元のID>.js`：
   - いちばん上のコメントに、**元の入試問題のねらいと形式**（「〜というねらいと形式だけを合わせた自作問題」）と、類題①の答えが書いてある。これが「元の問題の要約」。
   - 類題①の問題（`problem`）と解説の流れ・部品の使い方を見本にする。
3. `js/lessons.js` で、元のIDの行（`'title'` の書き方）を見る。

## 2. 類題②の決めごと
- **同じ**：分野・ねらい（何ができるかを問うか）・小問の流れ（(1) で準備 → (2)(3) で本題、など）・難しさ・記述式かどうか。
- **ちがう**：場面・関数の式・図形・数値。**類題①とも別の問題にする**（類題①の数を変えただけ、は不可。例：類題①が円柱の切り口なら、類題②は円すい・角柱など同じ考え方で解ける別の立体。類題①が $\log$ の不等式なら、類題②は $e^x$ の不等式、など）。
- 入試問題・問題集・教科書の問題を写さない（AUTHORING.md の 0. 著作権）。
- 答え・途中式・図の座標は **python3（sympy 可）で検算**し、台本のいちばん上のコメントに「答え（python3・sympy で検算ずみ）」として書く（類題①と同じ形）。
- 台本：`HB.lesson({ id: '<元のID>b', field: '（類題①と同じ）', title: '<年度> <大学の略称> … 第N問の類題② ― <内容>', level: '（類題①と同じ形）', time: '目安 20〜25分', … })`。`problem.src` は「※ <年度>年度 <大学名> … 第N問と同じ分野・ねらいの自作問題（類題②。元の問題ではありません）」。
- 大きさ：類題①と同じくらい（16〜24 ステップ、発問 4〜6、考えてみよう 1〜2）。流れ：問題 → 方針 → 小問ごとに1行ずつ → 発問で確かめ → 考えてみよう → まとめ（POINTS）→ end。

## 3. 検査（必須）
```bash
cd /home/user/math-dialogue
node --check hs-board/scenes/<ID>.js
TMPDIR=/tmp/hbc node hs-board/tools/check.mjs <ID> --shots <自分の作業フォルダ>/shots
```
- `TMPDIR` は短いパス（`/tmp/hbc`）にする（長いと Chrome が起動しない）。✗ と ⚠ を全部なくす。
- `<作業フォルダ>/shots/<ID>.sheet.jpg` を **Read で必ず見て**、図の重なり・字のかぶり・はみ出しを直す。

## 4. 解き直し用のファイル（必須）
- `<作業フォルダ>/<ID>.q.md`：類題②の問題文と小問（答えなし。図は座標・長さで文に書く。それだけで解ける形）。
- `<作業フォルダ>/<ID>.a.md`：小問ごとの答えと、検算の python の式。

## 5. 最後の報告（短く）
作った ID ごとに：`js/lessons.js` に入れる題名（`'title'` の文字列）、ステップ数・発問数、検査の結果、数学的にあやしい所。
