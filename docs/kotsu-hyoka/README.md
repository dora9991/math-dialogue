# コツコツくん「評価される学習時間」の仕様（引き渡し）

コツコツくんの本体（`src/solo`）はこのリポジトリに無いので、ここには**仕様・見本の実装・テスト・依頼文**を置きます。本体を持っているセッションが、これを読んで入れます。

- 見本の実装：`credit.mjs`（画面や保存に触らない関数だけ）
- 受け入れテスト：`credit.test.mjs`（`node --test docs/kotsu-hyoka/credit.test.mjs`。22件）
- 使った集計：`queries.sql`

## 1. ねらい

1. **評価するのは、意味のある学習の時間だけ**にする。いまの単元（直近）、予習、本当の学び直し。
2. **まじめにやった時間は、ちゃんと数える**。いまは「1時間やったのに30分」が起きている。
3. 楽をして評価される抜け道を、ルールでふさぐ（生徒を責めるのではなく、仕組みで）。

## 2. いまの数え方と、データで分かったこと

公開版（2026-11-15）のコードと、中1の105人の記録（1人あたり直近400問）から。

### いまの数え方

- 数えるのは、**問題が表示されてから答えるまで**だけ。上限は1問3分（11/10 に5分→3分）。
- 見えていない間と、**窓にフォーカスが無い間**は数えない（11/10、11/12）。たくさんのタブ対策として、前の解答からの時間をこえない（11/12）。
- **数えていないもの**：答えたあとに解説を読む時間、ホー先生の解説授業、理解度診断、模試、ふりかえり、単元えらび。
- 経験値は、正解ならレベルだけで決まる。学年や、もうできているかは関係しない。

### 「1時間やったのに30分」の正体

| 見たもの | 結果 |
|---|---|
| 続けて解いていた時間のうち、カウントされた割合 | 全体で 65%。生徒・日の中央値は約70% |
| カウントが半分に満たない生徒・日 | 11/9 まで 102日中16日（16%）→ 11/12 以降 66日中15日（23%） |
| 下から1割の生徒・日の割合 | 45% → 35%（11/12 以降） |
| まちがえたあと、次の問題までの時間（いまは 0 秒扱い） | 中央値 5秒、9割が 33秒以内 |
| 正解のあと、次の問題までの時間 | 中央値 1秒、9割が 11秒以内 |
| 入試レベルで、3分をこえた問題 | 11.8%（5分をこえたのは 2.8%）。応用は 2.1%、基礎・標準は 1% |
| 解説授業を見た生徒 | 23人・80回。時間は 0 分扱い |

つまり、**差の大部分は「答えたあと」と「解説授業」を数えていないこと**から来ています。11/12 の変更は、下のほうの生徒をさらに少し削りました。11/12 以降に下がった理由がフォーカスの条件かどうかは、記録からは決められません（画面分割や、端末によっては解いていてもフォーカスが無い扱いになる、という可能性があります）。

生徒の声（ご意見箱 11/13）にも、同じことが出ています：「1時間やっても30分ぐらいしか反映されない」「理解度診断や模試が、時間や問題数に含まれない」。

### 楽をして評価される動き

| 見たもの | 結果 |
|---|---|
| 小1〜2の問題 | 全解答の29%。その64%を上位3人が解いている。1問の中央値 4秒、正答率 89% |
| 1分あたりの経験値 | 小1〜2が中心の生徒 63.5、中1を8割以上やっている生徒 34.4 |
| たくさんのタブで交互に解く | 生徒からの通報あり（11/11）。11/12 に対策ずみ |

## 3. ルール

### A. 何秒と数えるか

| 場面 | 数え方 | 上限 |
|---|---|---|
| 問題を解く | 表示から解答まで | 基礎・標準 3分、応用 4分、入試レベル 5分 |
| 答えたあと（解説を読む） | 解答から、次の問題に進むまで | 正解 20秒、まちがい 90秒、「ていねい解説」を開いたら 3分 |
| 解説授業（ホー先生） | 見ていた時間 | その解説の標準の長さ × 1.2（長さが分からなければ 6分 × 1.2）。同じ日の見直しも、合計がここまで |
| 単元テスト・理解度診断・模試 | 問題を解くのと同じ | 同じ（模試は模試の制限時間まで）。問題数にも入れる |
| ふりかえりを書く | 書いていた時間 | 1日 3分 |
| 単元えらび・ご意見箱・ホーム | 数えない | ― |

共通の決まり：

- **見えている間だけ**数える（`document.hidden` で判定）。**フォーカスの条件は外す**。
- **同じ時刻は1回だけ**数える。端末ごとに「ここまで数えた」時刻を1つ持ち（タブで共有）、それより前の時間は数えない。たくさんのタブで交互に解いても、実際の時間をこえない。いまの「前の解答からの時間をこえない」を、解説の時間にも広げたもの。

### B. その時間を評価に入れるか

問題を解くたびに、次の順で決めます。

1. **あてずっぽうが続いている**（同じ単元の直近10問で、正解が3問以下）→ 入れない。「解説を見てから、もう一度」と出す。解説授業か「ていねい解説」を見たら、数え直す。
2. **合格したレベルのくり返し** → 入れない。忘れかけのころの復習（復習の期日が来たもの）は入れる。
3. **いまの単元**（クラスのいまの単元と、その前の2単元）→ 入れる。
4. **予習**（いまの単元より先、または上の学年）→ 入れる。
5. **前の単元**（同じ学年の前の単元、下の学年）は、**学び直しと認められるときだけ**入れる。
   - アプリが弱点・学習中としている単元 → 入れる（合格するまで）。
   - まだ分からない単元 → **たしかめ**（はじめの5問）。2問まちがえたら学び直しと認め、たしかめ中の時間も、さかのぼって入れる。4問以上正解なら「もうできている」。
   - もうできている単元 → 入れない。
6. 入れない時間は「**じゆう練習**」。やってよいし、記録も残る。評価の時間・電子黒板・ランキング・メダルには入らない。経験値は2割。

「弱点・学習中・できている」は、アプリがいま持っている単元ごとの見立て（診断・単元テスト・ふだんの正誤から出している状態）を、そのまま使います。

### 抜け道と、ふさぎ方

| 抜け道 | ふさぎ方 |
|---|---|
| 小1の問題を連打する | できている単元は評価に入らない。経験値は2割 |
| 合格したレベルを何度も解く | 合格したら、復習の期日まで入らない |
| わざとまちがえて「学び直し」にする | 正解を続ければすぐ合格して止まる。まちがえ続ければ、あてずっぽうの判定で止まる |
| 問題を出したまま放置してから答える | 1問の上限。解説を読む時間の上限 |
| たくさんのタブで交互に解く | 同じ時刻は1回だけ |
| 別のタブ・別のアプリを見ている | 見えていない間は数えない |
| 解説授業を流したままにする | 標準の長さ × 1.2 まで |

**残る抜け道**：2台の端末で同時に進める、画面を出したまま別のことをして上限ぎりぎりで答える。これは端末の中だけでは防げません。先生の画面で「時間のわりに解答が少ない」「正答率が低い」生徒が見えるようにするのが、現実的な手当てです。

## 4. 試算（いまの記録に当てはめたら）

`queries.sql` の③。近似です（「弱点」「合格」は記録から代用。中1以上の単元はすべて評価に入るものとした。1人400問まで）。

| 生徒のまとまり | 人数 | いまのカウント | 新しい評価の時間 |
|---|---|---|---|
| 中1を8割以上やっている | 23人 | 1,756分 | 1,748分（100%。生徒の中央値は 108%） |
| 小1〜2が半分以上 | 9人 | 347分 | 229分（66%。いちばん下がる生徒は 14%） |
| その他 | 19人 | 1,481分 | 1,203分（81%。中央値は 99%） |
| 50問未満 | 31人 | 274分 | 312分（114%） |
| 合計 | 82人 | 3,857分 | 3,492分（91%） |

解答ごとに見ると：

| 種類 | 解答 | 生徒 | 正答率 | 1問の中央値 | 評価 |
|---|---|---|---|---|---|
| 中1以上 | 5,435問 | 80人 | 70% | 13秒 | 入る |
| 学び直し（弱点・つまずきあり） | 1,033問 | 36人 | 65% | 12秒 | 入る |
| 下の学年（弱点でない） | 2,288問 | 41人 | 88% | 9秒 | 入らない |
| 合格ずみレベルのくり返し | 2,048問 | 54人 | 90% | 4秒 | 入らない |

入らなくなる解答は、速くて正答率が高いもの、入る解答は、時間がかかって正答率が低いものに、はっきり分かれます。本当に学び直している36人の時間は、残ります。

この試算に入っていないもの：解説授業・診断・模試・ふりかえりの時間（記録に時間が無い）、入試レベルの上限を5分にする効果、中1の中の「もうできている古い単元」が外れる効果。

## 5. 入れるときのメモ

- **保存の形**：1日の記録（`state.daily[日付]`）の `sec` を「評価の時間」にする。電子黒板（`_board_row` が返す `ds`・`d28.sec`）と先生の画面は、いまも `sec` から作った数字を読んでいるので、**そのままで評価の時間に切りかわる**。足すもの：`raw`（数えた時間のぜんぶ）、`hold`（たしかめ中の保留）、`by`（いま・予習・学び直し・じゆう練習の内訳）。`credit.mjs` の `addToDay`・`release` が、この形。
- **先生に総時間や内訳を見せるなら**、まとめ（summary）にも足す。電子黒板に出すなら、DB の `kotsu._board_row` が返すキーの一覧にも足す（DB の変更）。
- **解答の記録**（`state.log`）に、種類を1文字で残すと、あとで検証できる。
- **切りかえ日より前**の日の `sec` は、古い数え方のまま。先生の画面に「◯月◯日から数え方が変わりました」と出す。
- **「いまの単元」**：まずは生徒の `profile.nowUnit`（すでにある）を使う。生徒が自分で変えられるなら、抜け道になる。先生がクラスごとに決める形が本筋だが、`kotsu.classes` には今 `name`・`year`・`archived` しか無いので、列と、生徒の端末に渡す口（RPC）を足す必要がある。
- **経験値**：評価に入る解答はいまのまま、じゆう練習は2割（`xpFactor`）。たしかめ中は2割で入れ、学び直しと決まったら差額を足す。
- 数値はすべて `credit.mjs` の `PARAMS` にまとめてある。

## 6. 生徒への見せ方

何が数えられるかを、先に見せます。見えないルールは、不満と抜け道さがしのもとになります。

- ホーム：「きょう 32分」と、その内訳（いまの単元 20分・予習 5分・学び直し 7分／じゆう練習 12分）。「きょう何分やったか出してほしい」は、生徒の要望にもあります。
- 単元のページ・問題の前：「⏱ 評価に入ります」／「じゆう練習（評価の時間には入りません）」。
- たしかめ：「はじめの5問で、学び直しがいるかを たしかめます」。
- 止まったとき：「まちがいが つづいています。解説を見てから、もう一度」。
- 合格したとき：「このレベルは合格！ 次のレベルか、次の単元へ」。

## 7. 先生が決めること

既定の値で進めて、あとで変えられます。

1. 「直近」は、いまの単元とその前の2単元でよいか。
2. じゆう練習の経験値は2割でよいか（0 にもできる）。
3. 解説授業・ふりかえりを、時間に入れてよいか。
4. 単元えらび・ご意見箱の時間は入れない、でよいか（生徒の要望はあるが、学習の時間ではないので）。
5. 「いまの単元」を先生がクラスごとに決める仕組み（DB の変更あり）を、最初から入れるか。
