# 「カードで学ぶ」：つぎへ進んだら、カードの一番上から始める

## 困りごと（先生から）

「カードで学ぶ」で、カードを一番下まで読んでから「✓ わかった！つぎへ」を押すと、次のカードが下のほう（例題・問題のあたり）から始まってしまう。言葉や求め方が書いてある、カードの一番上から始めてほしい。

## 原因

カードを切りかえる関数（solo バンドルの `S4` の中の `g`）は、ボタンを押した**瞬間**に「なめらかに上へスクロール（`scrollIntoView({behavior:"smooth"})`）」を始め、**同時に**カードを入れかえていた。
入れかえでページの長さが変わると、端末によってはスクロールが途中で止まり、前のカードで読んでいた高さのまま、新しいカードの下のほうが出ていた。

- 手元の Chromium（ふつうの時計）では、たまたま最後まで上に戻っていた。
- 時計を止めた（アニメーションが進まない）条件では、毎回この症状が出た（`test_cardtop.cjs` で、直す前は 9件 FAIL）。

## 直したこと（`patch_card_top.py.txt`）

カードを入れかえた**あと**（画面を描き終えたあと：`requestAnimationFrame` 2回、念のため 150ms 後にも）に、カードの上端（カード番号の並び）へ、**すぐに**戻す。なめらかなスクロールは使わない。

- 上のほうにいるとき（カードの上端が画面に見えているとき）は、動かさない（いままでどおり）。
- 「✓ わかった！つぎへ」「← まえ」「カード番号」「📌 まとめ」の、どれで切りかえても同じ。

## 確かめたこと

- `test_cardtop.cjs`：3つの単元（中1・中2）× ふつうの時計／時計を止めた条件 × 4つの操作（上のまま つぎへ／下まで読んで つぎへ／下まで読んで まえ／下まで読んで まとめの番号）。**直したあと 0件 FAIL**（直す前は、時計を止めた条件で 9件 FAIL）。コンソールのエラーなし。
- これまでのテスト（中3・高1・高2・高3 の「解説ごとの演習」）も、直したバンドルで 0件 FAIL。
- Safari（iPhone・iPad）のエンジンは、この作業環境に無いので、実機では確かめていない。
