ビルド済み JS だけを手がかりに作ったパッチです。元のソース（src/solo と、共有チャンク summary の元になっているモジュール）に入れ直すための説明です。

## 1. 何を変えたか（動きの要約）
- 方針：**①いまの単元・同じ学年の抜けているところが中心 ②前の学年は、つまずきの証拠があるときだけ（最大2件）③得意なときだけ、応用(L3〜4)と予習を後ろに1〜2件**。
- 変えたのは「並べ方・選び方」だけ。`state` は一切書きかえない。種類（kind）は既存の8つ（sakanobori/weak/shaky/goal/review/check/confirm/ahead）。
- 元のエンジン（`Ob`＝solo では `In`）は、そのまま「候補を作る係」として呼ぶ。新しい関数 `ktAi` がその出力を並べかえ・追加・削除する。

## 3. 変更前の動き（なぜ新入生に小6が先頭に出たか）
`Ob` の各 kind と点数：
| kind | 条件 | 点数 |
|---|---|---|
| sakanobori | 習った単元 X が weak → 前提をたどって、weak または「解いたがレベル0」の S | 120+3×下流数(≤6) |
| weak | 習った＆(授業でまちがえた[7日以内]→98+／状態 weak)で根っこ無し | 100+3×下流数+学年ボーナス+直近まちがい10 |
| shaky | `profile.shaky`（自信がない・3つまで） | 95+下流数（他の種類があれば+30） |
| goal | 習った＆目標未満で記録あり（learning/upper） | 80(+8)+学年ボーナス+直近まちがい15+下流数 |
| review | 目標到達済みで復習期限 | 60+経過日×2(≤20) |
| check | **習った＆記録なし** | 40+下流数(≤6)+学年ボーナス |
| confirm | 習った＆診断の推定だけでOK | 30+学年ボーナス |
| ahead | **習っていない**(learned でない)＆学年≤自分+1＆全前提がレベル≥1 | 20+(同学年5)−学年×0.1 |
学年ボーナス＝同学年+10／1つ前+5／それ以外0。「習った(learned)」は、**前の学年の単元は無条件に全部 true**、同学年は `profile.learned`（授業の範囲）に入っているものだけ、次の学年は false。
原因：
1. 前の学年の単元は全部「習った」扱いなので、記録が無いと全部 `check`（40+下流数+5＝最大51）になる。小6「分数のかけ算」などは中1の多くの単元の前提(下流数が多い)なので、最高点。
2. 中1の単元は、授業の範囲(`profile.learned`)に入っていないと `check` になれず、`ahead`(≤25点)にしかなれない。しかも `ahead` は「全前提がレベル≥1」が条件で、新入生は前提（小学校の単元）がレベル0なので、中1の単元は1つも出ない。
3. `check` には「証拠」の条件が無い（記録なし＝未確認だけで出る）。学年ボーナス(5〜10点)は、種類の差(10〜60点)に負ける。
4. 範囲外の学年（H3・既卒）は同学年の単元が無く、小1「10までのかず」まで出る。
→ 新入生(授業の範囲が空)は、小6の `check` が上位6件を独占。`授業の範囲` を設定していても、小6の `check`(51) が中1の `check`(最大56)の直後に並ぶ。

## 4. 新しい動き（`ktAi`；ソースは `ktai_core.js`、パッチは `patch_ai.py`）
`ktAiMake(s, now)` の流れ：
0. **「いまの単元」の目印**（同学年だけ）：授業の範囲の最後(`nowUnit`)・14日以内の `jugyo` ＝ 重み0、14日以内に解いた直近3単元 ＝ 重み1。ここからの「近さ」（授業の順の位置の差＋重み）で並べる。
1. **授業の範囲を「仮に」ひろげて、エンジンを1回だけ呼ぶ**：同学年で解いたことのある単元を `learned` に足した、**コピーの state**（`{...s, profile:{...pr, learned:[…]}}`）で `Ob(limit:999)`。記録が何もなく授業の範囲も空の生徒は、学年の**先頭5単元**を足す（新入生には、いまの単元＝先頭から）。本物の state は触らない。
2. **同学年の並び**：つまずき(weak) > いまの単元（目印の単元の goal/review/check/confirm）> 自信がない(shaky) > 練習中(goal) > 復習 > 未確認(check) > 診断OK(confirm)。同じ種類の中は「いまの単元からの近さ」→ 元の点数。
3. **前の学年を出す条件（証拠があるときだけ・合わせて最大2件）**
   - 結びつく：同学年の `status==="weak"`（診断・分析で弱い／くり返しのまちがい＝元のエンジンの weak）の単元 X の前提(推移)に、**はっきり弱い**単元 S がある（S は weak、または3問以上解いて正解が半分以下でレベル0）。S は **X のすぐ後ろ**に `sakanobori`（🌱）で置く。理由は元と同じ書き方「「X」のつまずきの根っこかも。小6にさかのぼって…」。同学年の S は X の前。
   - 結びつかないもの：前の学年で `weak`／`sakanobori`(根っこがはっきり弱い)／`shaky`(自信がない) の単元。いまの単元（目印と次の2単元）の前提の連鎖にあるものを先に、次に近い学年。3番目・5番目に入れる。
   - 前の学年の `check`/`confirm`/`review`/`goal`/`ahead` は出さない（例外：下の「少なすぎるとき」）。
4. **得意なときだけ**：判定（保守的）＝授業で習った同学年の単元が3つ以上／その70%以上(最低3)が、解いた結果で標準(L2)に到達／同学年につまずいている単元が無い／直近30問（20問以上、最後の解答が30日以内）の正答率80%以上で、直近15問のまちがいが2問以下。
   得意なら、4番目に**応用・入試の単元**（`goal`：「標準までできている。…「応用」にチャレンジしよう」、レベルは L3／L4。いまの単元に近い順）、5番目に**予習**（`ahead`：同学年の次の単元 → 無ければ次の学年の入口。前提がそろっているもの）。
   得意でなければ、予習・応用は出さない。
5. **少なすぎるとき（3件未満）だけ**おぎなう：(得意なら応用) → 予習 → 前の学年(2学年前まで)の check/confirm/review（いまの単元の前提を先に）。目標範囲内の同学年が1つも無い生徒（高3の文系・既卒）は、実質ここで前の学年が出る。
6. 安全装置：`try/catch` で、何かあれば元の `In(s,o)` の結果をそのまま返す。

`ktPlan(s,10)`：元の `zo`(A5) の代わり。上位5件に 3,2,2,2,1 問。5件に満たないときは上から1問ずつ足して10問（元は「上の件を繰り返し」で、先頭に偏った）。
