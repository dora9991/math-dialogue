# 02 Xserver 初期設定

はじめての1回の手順です（1〜2時間）。例では次の名前を使います。自分のものに読み替えてください。

| 例 | 意味 |
|---|---|
| `xs123456` | サーバーID（サーバーパネルの「サーバー情報」） |
| `example.com` | Xserver に追加してある独自ドメイン |
| `hub.example.com` | ハブ用のサブドメイン |
| `/usr/bin/php8.3` | PHP の場所（サーバーパネル「サーバー情報」→「コマンドパス一覧」で確かめる） |

> ✅ 終わったら `bin/hub doctor --online` が「すべて大丈夫」になります。途中で迷ったら、いつでも `doctor` を動かしてください。何が足りないかを日本語で教えてくれます。

---

## 1. サブドメインと SSL と PHP

1. サーバーパネル →「サブドメイン設定」→ 対象のドメイン（example.com）→「サブドメイン追加」
   - サブドメイン名：`hub`
   - ドキュメントルート：`public_html/hub`（`public_html/hub.example.com` でも可。**この場所をあとで使う**）
   - 「無料独自SSLを利用する」にチェック
2. サーバーパネル →「SSL設定」で、`hub.example.com` に SSL が付いていることを確かめる（反映に最大1時間ほどかかることがあります）
3. サーバーパネル →「PHP Ver.切替」で、example.com を **PHP 8.3 以上** にする
4. サブドメインのフォルダに Xserver が置いた `index.html` があれば、消してかまいません

> ハブ専用のサブドメインにします。WordPress などと同じフォルダには置けません（`deploy.sh` が止めます）。

## 2. データベース

サーバーパネル →「MySQL設定」

1. 「MySQL追加」：`xs123456_hub`（文字コード UTF-8）
2. 「MySQLユーザ追加」：`xs123456_hub`。パスワードは長い乱数（パスワード管理アプリで作り、そこに控える）
3. 「MySQL一覧」で、そのユーザーに `xs123456_hub` へのアクセス権を付ける
4. 画面に出ている「MySQLホスト名」を控える（`localhost` のことが多い）

> このユーザーは**ハブ専用**にします（ほかのサイトの DB と使い回さない）。ハブの表には「行ごとの守り」が無いので、DB のユーザーを分けることが守りになります。

## 3. SSH

1. サーバーパネル →「SSH設定」→ ON。「国外アクセス制限」も ON
2. 「公開鍵認証用鍵ペアの生成」でパスフレーズつきの鍵を作るか、自分の公開鍵（OpenSSH 形式）を登録する
3. 自分のパソコンから入る（パスワードでは入れません。鍵だけ）

```bash
ssh -p 10022 -i ~/.ssh/xs123456.key xs123456@xs123456.xsrv.jp
```

## 4. ハブを置く

SSH で入ったまま：

```bash
mkdir -p ~/src && cd ~/src
git clone --depth 1 https://github.com/dora9991/math-dialogue.git
bash ~/src/math-dialogue/xserver-hub/tools/deploy.sh --public-dir=$HOME/example.com/public_html/hub
```

- `--public-dir` は 1. のドキュメントルート。2回目からは覚えているので要りません
- 使う PHP は、入っている中でいちばん新しいもの（`/usr/bin/php8.x`）を自動で選びます。決めたいときは `PHP=/usr/bin/php8.3 bash …/deploy.sh`
- できあがる形：

```
~/hub/app/        プログラム（700/600）
~/hub/config/     設定と秘密（700）← 次の 5. で作る
~/hub/var/        ログ・バックアップ・書き出し（700）
~/example.com/public_html/hub/   index.php・.htaccess・assets/（755/644）
```

以下、`hub` と書いたら `/usr/bin/php8.3 ~/hub/app/bin/hub` のことです。毎回打つのが面倒なら：

```bash
echo "alias hub='/usr/bin/php8.3 ~/hub/app/bin/hub'" >> ~/.bashrc && source ~/.bashrc
```

## 5. 設定を作る（init）

```bash
hub init
```

質問に答えます（わからないところは Enter で飛ばして、あとで `~/hub/config/config.php` を直せます）。

| 質問 | 答え |
|---|---|
| ハブを開く URL | `https://hub.example.com` |
| DB のホスト名・名前・ユーザー・パスワード | 2. で作ったもの |
| LINE のチャネルID・チャネルシークレット | LINE Developers コンソール → プロバイダー → Messaging API チャネル →「チャネル基本設定」 |
| 知らせを受け取るメールアドレス | 失敗・あやしいログイン・毎朝の報告が届く。いつも見るアドレス |
| 知らせの差出人 | `hub@example.com` のように、**このサーバーのドメイン**のアドレス（迷惑メールに入りにくい） |
| 会員サイトと連携しますか | まだなら `n`（あとで [06](06_会員サイト連携API.md) を見て設定） |

- 暗号の鍵（データ・指紋・パスワードのこしょう・バックアップ）は **自動で作られます**
- **鍵を控える**：`config.php` の `keys` を、パスワード管理アプリか紙に控えます。サーバーが壊れたとき、鍵が無いと暗号化したトークとバックアップが読めません
- `config.php` は 600。公開フォルダの外。git・メール・チャットに貼らない

## 6. データベースの形と、最初のオーナー

```bash
hub migrate
hub admin:create-owner あなたのメールアドレス
```

仮パスワードが **1回だけ** 表示されます。

## 7. cron（毎分）

サーバーパネル →「Cron設定」→「Cron設定追加」

| 分 | 時間 | 日 | 月 | 曜日 | コマンド |
|---|---|---|---|---|---|
| `*` | `*` | `*` | `*` | `*` | `/usr/bin/php8.3 /home/xs123456/hub/app/bin/hub tick` |

- コマンドは**フルパス**で書く（`~` や alias は使えません）
- ふだんは何も出力しないので、cron のメールは来ません。失敗したときは、ハブが自分でメールを送ります
- 「Cron結果通知用メールアドレス」は、空でも、いつも見るアドレスでも構いません

## 8. LINE の設定

1. ハブから LINE に Webhook の URL を設定して、検証する：

```bash
hub line:set-webhook     # → https://hub.example.com/webhook/line を設定して「検証：成功」
hub line:check           # ボットの名前・Webhook の URL・今月の通数
```

2. LINE Developers コンソール → チャネル →「Messaging API設定」
   - **Webhookの利用：オン**
   - **Webhookの再送：オン**（ハブは同じイベントを二重に処理しません）
   - エラーの統計集計：オン（任意）
3. LINE Official Account Manager →「設定」→「応答設定」
   - **Webhook：オン**
   - **応答メッセージ：オフ**（ハブのルールと二重に返事をしないため）
   - あいさつメッセージ：ハブで「友だち追加」のルールを作るならオフ（どちらか一方に）
4. チャネルアクセストークンは**発行しなくてよい**です。ハブはチャネルID・シークレットから、短い期限のトークンを自分で作って使い、暗号化して持ちます

## 9. 最初のログイン

1. `https://hub.example.com/admin/login` を開き、メールアドレスと仮パスワードで入る
2. 自分のパスワードに変える（**12文字以上**。文の形がおすすめ：例「朝のピアノは3曲までと決めている」）
3. 二段階認証を登録する：認証アプリ（Google Authenticator・Microsoft Authenticator・1Password など）で QR を読み、6桁を入れる
4. **回復コード10個を控える**（スマホを無くしたときに使う。1つ1回）

## 10. 健康診断

```bash
hub doctor --online
```

LINE への接続・Webhook の URL・公開している URL（隠しファイルが見えないか・http が https に切り替わるか・管理画面がログインを求めるか）まで確かめます。❌ があれば、書いてある通りに直します。

## 11. 送り始める前に（管理画面の「設定」）

| 設定 | おすすめ |
|---|---|
| 練習モード（`dry_run`） | **最初はオン**。送らずに「送るはずだった」記録だけ残る。テスト送信で自分に届くのを確かめてからオフ |
| 月間の上限（`monthly_cap`） | 契約している LINE 公式アカウントのプランの「無料メッセージ数」に合わせる |
| 会員通知の取り置き（`notification_reserve`） | 一斉配信が上限を使い切っても、会員への通知が届くように残す数 |
| 運営への通知先（`admin_user_ids`） | 運営の LINE の userId（友だち一覧の詳細で見られる） |
| 会員サイトの URL（`site_url`） | 通知のリンクの頭（`https://member.example.com`） |

運営メンバーを増やすときは、管理画面の「運営メンバー」から（役割は [03](03_安全管理措置.md) の表）。

## 12. Xserver アカウントそのものの守り

ハブがいくら守っても、Xserver のアカウントを取られたら全部が見えます。

- **Xserver アカウントの二段階認証をオン**（Xserver アカウントのメニューにある「二段階認証」の設定）
- サーバーパネルのパスワードは、ほかで使っていないもの
- SSH の秘密鍵にはパスフレーズを付け、パソコンの外に出さない
- FTP アカウントを増やすときは、`~/hub` が見えない場所に限る（できれば作らない）
- 「WAF設定」はオンのままで。管理画面で保存しようとして 403 になる（本文に `<script>` や SQL らしい言葉が入っている）ときは、WAF の誤検知のことがあります。サーバーパネルの「WAF設定」でログを確かめ、必要な種類だけ一時的にオフにします

うまく動かないとき：

| 症状 | 見るところ |
|---|---|
| 500「ハブのプログラムが見つかりません」 | `index.php` の HUB_ROOT。`deploy.sh` で置き直す |
| 421 misdirected request | `config.php` の `app.base_url` のホスト名と、開いた URL が違う |
| 403 https only | http で開いている。`.htaccess` が置かれているか |
| LINE の検証が失敗 | `hub doctor --online`、`~/hub/var/log/` の最新のログ。チャネルシークレットの写し間違い |
| 毎朝の報告が来ない | cron（7.）。`hub report --print` で中身だけ見られる |
| ログイン画面で「有効期限が切れました」 | 30分以上置いた。画面を開き直す |
