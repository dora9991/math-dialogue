# 04 日々の運用

ハブは、ほうっておいても毎分・毎日の仕事を自分でします（配信・バックアップ・片づけ・報告）。
人がやるのは「**朝の報告メールを読む**」と、月に1回の点検くらいです。

以下、`hub` は `/usr/bin/php8.3 ~/hub/app/bin/hub` のこと（[02](02_Xserver初期設定.md) の 4 の alias）。

## 毎日：朝7時の報告メールを読む（1分）

| 項目 | 見るところ |
|---|---|
| 【友だち】 | いまの人数・ブロック |
| 【メッセージ】 | 前日に受け取った数・返事が要るもの → 管理画面「チャット」 |
| 【送信】 | 前日に送った通数・今月の通数と上限 |
| 【会員連携】 | 前日に連携した人数 |
| 【ログイン】 | 成功と失敗の回数。**自分たちの覚えのない成功があれば、[05](05_事故が起きたら.md) の A** |
| 【バックアップ】 | 最新の時刻と大きさ |
| 【操作の記録】 | 「鎖を確かめました（切れていません）」と最新の指紋。**このメールは消さずに残す**（あとで記録が書き換えられていないかを、サーバーの外から確かめられる） |
| 【気になること】 | あれば、書いてある通りに |

報告が来ない日は、cron が止まっています（`hub doctor` で確かめる）。
報告とは別に、失敗・あやしい動きがあれば、その場でメールが来ます（同じ知らせは間をあけて、まとめて）。

## 毎月（15分）

- [ ] `hub doctor --online` が ✅ だけ（⚠️ は理由がわかっていればよい）
- [ ] 管理画面「運営メンバー」：辞めた人・役割が高すぎる人がいない
- [ ] 管理画面「操作の記録」：知らない操作がない（設定の変更・一斉配信・運営メンバーの変更を中心に）
- [ ] 管理画面「送信状況」：失敗が続いていない。今月の通数が上限に近ければ、プランか配信を見直す
- [ ] バックアップを1つ、サーバーの外へ（下の「バックアップ」）

## 年に1回

- [ ] [03 安全管理措置](03_安全管理措置.md) の点検表
- [ ] バックアップから戻す練習（下の「戻す練習」）
- [ ] 鍵の入れ替え（任意。下の「鍵の入れ替え」）

## ハブを新しくする（更新）

```bash
cd ~/src/math-dialogue && git pull && bash xserver-hub/tools/deploy.sh
```

`deploy.sh` は：文法チェック（1つでも壊れていたら置かない）→ メンテナンス中にする → プログラムを入れ替える → データベースの更新（**流す前に自動でバックアップ**）→ 健康診断 → メンテナンスを終える。
メンテナンス中は、管理画面と API が 503、毎分の処理が止まります。LINE の Webhook は受け付け続けます（返事は少し遅れることがあります）。

### 更新が失敗したら

`deploy.sh` が「❌ 途中で止まりました」と出したとき：

1. **慌てなくて大丈夫です。** メンテナンス中のままなので、配信は止まっています。LINE からの受信は記録されています
2. 上に出ているメッセージを読む（ほとんどは、データベースの更新の失敗か、PHP のエラー）
3. 直し方がわかれば直して、もう一度 `deploy.sh`
4. わからない／急いで戻したいとき：
   ```bash
   cd ~/src/math-dialogue
   git log --oneline -5                       # ひとつ前のコミットを探す
   git checkout <ひとつ前のコミット>
   hub backup:list                            # 「更新の前の自動バックアップ」を探す
   hub backup:restore ~/hub/var/backup/<そのファイル> --yes   # データベースが途中まで変わっていたら、戻す
   bash xserver-hub/tools/deploy.sh           # 前のプログラムで置き直す（メンテナンスも終わる）
   git checkout main                          # あとで直したものを入れるときのために、戻しておく
   ```
5. 直す前に、とにかく再開したいとき（データベースの更新が無かった場合だけ）：`hub maintenance:off`

メンテナンス中のまま2時間たつと、知らせのメールが来ます（止めっぱなしの防止）。

## バックアップ

- **自動**：毎日3時（日本時間）。`~/hub/var/backup/` に、暗号化した `.hubbak`。14日分（`backup.keep_days`）
- **いま取る**：`hub backup`
- **一覧**：`hub backup:list`
- **読めるか確かめる**：`hub backup:verify ~/hub/var/backup/<ファイル>`（鍵で読めるか・壊れていないか・途中で切れていないか）
- Xserver 自身のバックアップ（サーバーの自動バックアップ）もありますが、**暗号化の鍵が無いと中身は読めない**ことは同じです

### サーバーの外へ（月に1回）

サーバーが丸ごと使えなくなったときのために、自分のパソコンなどへ1つ持ってきます。中身は暗号化済みです。

```bash
# 自分のパソコンで
scp -P 10022 -i ~/.ssh/xs123456.key 'xs123456@xs123456.xsrv.jp:hub/var/backup/hub-2026*.hubbak' ~/hub-backups/
```

鍵（`config.php` の `keys.backup`）は、**バックアップとは別の場所**に控えます（同じ場所に置くと、暗号化の意味がなくなる）。

### 戻す

```bash
hub backup:verify ~/hub/var/backup/<ファイル>
hub backup:restore ~/hub/var/backup/<ファイル> --yes
```

- 戻す前の中身も、自動でバックアップします（戻し間違えても、戻せる）
- 戻している間は、自動でメンテナンス中になります
- プログラムがバックアップより新しいときは、続けて `hub migrate`

### 戻す練習（年に1回）

本番を壊さずに練習するには、Xserver に練習用の DB（`xs123456_hubtest`）を作り、設定ファイルを写して DB の名前だけ変え、そこへ戻します。

```bash
cp ~/hub/config/config.php ~/hub/config/restore-test.php && chmod 600 ~/hub/config/restore-test.php
# restore-test.php の db.name・db.user・db.pass を、練習用の DB に書き換える
HUB_CONFIG=~/hub/config/restore-test.php hub migrate --no-backup
HUB_CONFIG=~/hub/config/restore-test.php hub backup:restore ~/hub/var/backup/<ファイル> --yes
HUB_CONFIG=~/hub/config/restore-test.php hub person:find <知っている人の名前の一部>   # 中身が読めることを確かめる
rm ~/hub/config/restore-test.php    # 終わったら設定を消し、練習用の DB もサーバーパネルで消す
```

## 鍵の入れ替え

| 鍵 | 入れ替え方 | 入れ替えると |
|---|---|---|
| `keys.data`（トークなどの暗号化） | 下の手順。いつでもできる | 何も起きない（古い鍵で読み、新しい鍵で書き直す） |
| `keys.backup` | `keys:generate` の結果に書き換える | これからのバックアップは新しい鍵。**古いバックアップを読むには古い鍵が要る**ので、古い鍵も控えに残す |
| `keys.index`（連携コードなどの指紋） | 事故のときだけ | 発行中の連携コード・回復コードが使えなくなる。Zoom の名前の結びつけを作り直す必要がある |
| `keys.pepper`（パスワードのこしょう） | 事故のときだけ | **全員のパスワードが使えなくなる**。全員に `admin:reset-password` |

`keys.data` の入れ替え：

```bash
hub keys:generate                       # 新しい鍵を表示
# config.php の keys.data に 'k2' => '新しい鍵' を足し、data_primary を 'k2' にする（k1 は残す）
hub keys:rotate-data                    # k1 で暗号化されているものを、k2 で書き直す
hub keys:status                         # k1 が 0 になったら
# config.php から k1 を消す（控えには、古いバックアップのために残してよい）
```

## 運営メンバー

- 増やす：管理画面「運営メンバー」→ メールと役割 → 仮パスワードが1回だけ出る → 本人に別の手段で伝える（同じメールに書かない）
- 役割を変える・外す：同じ画面。自分自身と、最後のオーナーは外せません
- **辞めた人は、その日に外す**

困ったとき（SSH で、オーナーが）：

| 困りごと | コマンド |
|---|---|
| パスワードを忘れた | `hub admin:reset-password その人のメール`（仮パスワードを作り直す。その人のログインは全部切れる） |
| 認証アプリのスマホを無くした・回復コードも無い | `hub admin:reset-2fa その人のメール`（次のログインで登録し直し） |
| 全員をいますぐログアウトさせたい | `hub admin:logout-all`（1人だけなら、後ろにメール） |
| 一覧 | `hub admin:list` |

## 本人からの求め（開示・消去など）

本人から「自分の情報を見せてほしい／消してほしい／使わないでほしい」と言われたとき。

1. **本人かどうかを確かめる**（ハブではできません。会員サイトのログイン・LINE のトークでのやり取りなど）。いつ・誰から・何を・どう確かめたかを控える
2. その人を探す：
   ```bash
   hub person:find 表示名の一部      # または 会員番号・userId
   ```
3. 求めに応じて：

| 求め | やること |
|---|---|
| 見せてほしい（開示） | `hub person:export <userId>` → `~/hub/var/export/` に JSON（600）。本人に安全な方法で渡し、**渡したらファイルを消す** |
| 配信を止めてほしい | いちばん確実なのは、本人に LINE でブロックしてもらうこと。ハブ側では「配信停止」のようなタグを1つ決めてその人に付け、ステップ配信の「このタグが付いたら止める」と、一斉配信の絞り込み（そのタグを除く）に入れておく |
| 消してほしい | `hub person:export <userId>`（控えが要るなら）→ `hub person:erase <userId> --yes` |
| 会員の情報も消してほしい | 会員サイトの退会の処理（会員サイトから `DELETE /api/v1/members/{会員番号}` が呼ばれる） |

消去について知っておくこと：

- 友だち台帳・タグ・友だち情報・トーク・受け取ったイベント・送信の記録（複数人への送信からは、その人だけ外す）・アンケートの回答・申込・出欠・動画・閲覧の記録が消えます
- **バックアップには最大14日残ります**（期間が過ぎれば自動で消える）
- 操作の記録（改ざん検知の鎖）に、その人の userId が残っていることがあります。記録の目的のため、保存期間（3年）まで残ります
- LINE の友だちのままだと、次にメッセージが来たとき、台帳に新しく載ります（本人にブロックしてもらうと止まる）
- LINE 側（LINEヤフー）にある情報は、ハブからは消せません

## 保存期間

| 何を | どれだけ | どこで変える |
|---|---|---|
| トーク（受信・送信の本文）・送り終わった送信の記録 | 365日 | 管理画面の設定 `chat_retention_days` |
| 受け取った Webhook の記録 | 30日 | 管理画面の設定 `log_retention_days` |
| 閲覧の記録 | 365日 | `config.php` の `retention.access_log_days` |
| 操作の記録 | 3年（1095日） | `retention.audit_days`（365日より短くはできない） |
| 動作のログ（`var/log`） | 90日 | `retention.log_days` |
| バックアップ | 14日 | `backup.keep_days` |
| 連携コード | 使ったら30日・使わなければ期限の1日後 | （固定） |

## 送信を止めたいとき

| 場面 | やり方 |
|---|---|
| ふだん（管理画面に入れる） | 「設定」→ 送信を止める（停止スイッチ） |
| 管理画面に入れない・急ぐ | SSH で `hub line:stop`（再開は `hub line:start`） |
| 送らずに試したい | 「設定」→ 練習モード（`dry_run`） |
| 更新・復元の作業中 | `hub maintenance:on` → 作業 → `hub maintenance:off`（`deploy.sh` は自動でやる） |

止めても、受信・友だち台帳・管理画面は動き続けます。止めている間に積まれた送信は残るので、再開する前に「送信状況」で古い予約を確かめます。
