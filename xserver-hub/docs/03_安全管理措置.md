# 03 安全管理措置

個人情報保護法は、個人データを扱う事業者に「安全管理措置」を求めています（法23条。中身は個人情報保護委員会の「ガイドライン（通則編）」10（別添）「講ずべき安全管理措置の内容」）。
この文書は、そのガイドラインの項目ごとに、**ハブが仕組みでやっていること** と **人（運営）がやること** を並べたものです。

> ⚠️ これは仕組みの説明と、運用のひな形です。法的な判断が必要なときは、個人情報保護委員会の最新のガイドラインと、必要なら専門家に確かめてください。

## このハブが扱う個人データ（概要）

LINE の友だちの userId・表示名・アイコン、トークの本文、タグ・属性・アンケートの回答、イベントの申込・出欠（Zoom の名前とメール）、
会員サイトの会員番号・プラン、運営メンバーのメールアドレス。詳しくは [07 データ台帳](07_データ台帳.md)。

**「要配慮個人情報」（病歴・信条など）は、扱わない運用にします。** トークに書かれてしまうことはあるので、トークの本文は暗号化して持ち、保存期間を過ぎたら消します。タグ・属性・友だち情報（暗号化していない）には、そうした情報を入れません。

| 人がやること |

## 10-3 組織的安全管理措置

| ガイドラインの項目 | ハブがやっていること | 人がやること |
|---|---|---|
| (1) 組織体制 | 役割で権限を分ける（下の表）。オーナーが最後の1人になる変更は断る | 責任者（オーナー）と、扱う人（運営メンバー）を決めて書き残す |
| (2) 決まりに従った運用 | 送信は停止スイッチ・練習モード・月間上限を必ず通る。テンプレートは「止めた状態」で作る | 決まりを運営メンバーに渡す |
| (3) 取扱状況を確認する手段 | **操作の記録**（誰が・いつ・何を。書き込みはすべて。断られた操作も）。**閲覧の記録**（友だちの詳細・トークを開いたこと）。毎朝の報告メール | 毎朝の報告を読む。月に1回、「操作の記録」を眺める |
| (4) 漏えい等への対応体制 | あやしい動き（ログイン失敗の連続・署名の合わない呼び出し・連携コードの総当たり・毎分の処理の失敗）をメールで知らせる。停止スイッチ・全員のログアウトがコマンドでできる | [05 事故が起きたら](05_事故が起きたら.md) を読んでおく。連絡先を決めておく |
| (5) 見直し | `bin/hub doctor` が設定の危ないところを日本語で指摘する | 年に1回、この文書と決まりを見直す。運営メンバーの棚卸し |

|---|---|---|---|---|---|---|---|
| オーナー | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 管理者 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | |

- 必要な人に、必要なだけ。迷ったら下の役割にする

## 10-4 人的安全管理措置

| ハブがやっていること | 人がやること |
|---|---|
| 仮パスワードで始め、最初のログインで自分のパスワード（12文字以上）と二段階認証の登録を必ずさせる。チャットの本文・仮パスワードは操作の記録に残さない | 運営メンバーに、決まりを読んでもらい、「知り得た個人情報を目的外に使わない・持ち出さない」ことに同意してもらう（下のひな形）。辞めた人はその日に外す |

## 10-5 物理的安全管理措置

| ガイドラインの項目 | ハブがやっていること | 人がやること |
|---|---|---|
| (1) 取り扱う区域 | サーバーは Xserver のデータセンター（国内） | 管理画面を人の目のある場所（カフェ・職員室の共用PC）で開かない |
| (2) 機器の盗難等の防止 | 管理画面は30分さわらないと自動でログアウト、12時間で必ずログインし直し | パソコン・スマホに画面ロック。認証アプリの入ったスマホを無くしたら、すぐ回復コードでログインして二段階認証を登録し直す |
| (3) 持ち運ぶ場合 | バックアップ・書き出しは暗号化済み（書き出しは本人に渡すためのもので、渡したら消す） | 個人の情報を USB・個人のクラウドに入れない。CSV を取り込んだら、すぐ消す |
| (4) 削除・廃棄 | 保存期間を過ぎた記録を毎日消す。本人の求めで、その人の情報を全部消す（`person:erase`） | Xserver を解約するときは、DB とバックアップを消してから |

## 10-6 技術的安全管理措置

| ガイドラインの項目 | ハブがやっていること |
|---|---|
| (1) アクセス制御 | 役割ごとの権限（上の表）。管理画面の IP 制限（`admin.allowed_ips`。任意）。会員サイトの API は鍵ごとに使える範囲（scopes）と IP を決められる。DB のユーザーはハブ専用。プログラム・設定・秘密は公開フォルダの外（700/600） |
| (2) 識別と認証 | 一人ひとりのアカウント（共有しない）。パスワードは pepper＋Argon2id（無ければ bcrypt）。**二段階認証（TOTP）必須**、同じコードの使い回しを防ぐ、回復コード10個。5回まちがえると15分、10回から60分ロック（知らせ先にメール）。セッションはサーバー側で管理し、ログイン・二段階認証の段階ごとに作り直す。クッキーは `__Host-`・HttpOnly・SameSite=Strict・Secure |
| (3) 外部からの不正アクセス等の防止 | https だけ。LINE の Webhook は署名を確かめる。会員サイトの API は、時刻（±5分）・使い捨ての nonce・HMAC 署名。管理画面のフォームは CSRF の合言葉と送り元（Origin）を確かめる。画面は CSP で外のスクリプトを読まない。回数制限（ログイン・API・連携コード・管理画面の操作）。違うホスト名のリクエストは断る。`.htaccess` で、index.php 以外の PHP・隠しファイル・バックアップらしいファイルを開かせない |
| (4) 情報システムの使用に伴う漏えい等の防止 | **列ごとの暗号化**（AES-256-GCM。列の名前を「付随データ」に入れて、別の列へのすり替えも見破る）：トークの本文・Webhook の中身・送信の中身・メモ・Zoom の名前とメール・二段階認証の秘密。連携コード・回復コードは指紋（HMAC）だけ。バックアップは丸ごと暗号化。ログに秘密や本文を書かない（名前で伏せる）。**操作の記録は前の行の指紋とつながる鎖**で、書き換え・途中の削除に気づける（毎朝の報告メールに最新の指紋を載せる＝サーバーの外にも控えが残る）。鍵の入れ替えができる |

人がやること（技術）：

- Xserver アカウントの二段階認証、SSH は鍵だけ（[02](02_Xserver初期設定.md) の 12）
- `config.php` の鍵は、パスワード管理アプリか紙に控える（サーバーの外。ほかの人に見せない）
- 月に1回 `bin/hub doctor --online`
- ハブを更新したら、`deploy.sh` が自動で健康診断をする。❌ が出たら直す

## 10-7 外的環境の把握

外国にある事業者のサービスで個人データを扱う場合は、その国の制度を把握して、安全管理措置を講じます。

| どこ | 扱うもの | 確かめておくこと |
|---|---|---|
| Xserver（エックスサーバー株式会社・日本） | ハブの全データ | 国内のデータセンター |
| LINE（LINEヤフー株式会社・日本） | トーク・プロフィール（LINE の側） | LINE のプライバシーポリシー（データの保管場所） |
| 会員サイト（Supabase：米国の会社） | 会員の情報 | 使っているリージョン（東京など）。方針（10-1）に、外国の事業者のサービスを使うことと、その国の名前を書く |
| Zoom（米国の会社） | 出欠の名前・メール | 同上 |

ハブ自体は、日本の Xserver の中だけで完結します（会員サイトへは、会員番号と「連携できた」しか送りません）。

## 取扱いの決まり（ひな形）

自分たちの言葉に直して、運営メンバーに渡してください。

```
LINE配信ハブ 個人情報の取扱いの決まり（20xx年x月x日）

1. 責任者：〇〇（オーナー）。扱う人：管理画面の「運営メンバー」に登録された人だけ。
2. 使う目的：会員への連絡・イベントの案内・学びの情報の配信・問い合わせへの返事。それ以外には使わない。
3. アカウント：一人ひとり別。パスワード（12文字以上）と二段階認証。人に貸さない・共有しない。
4. 画面：人の目のある場所・共用のパソコンで開かない。離れるときはログアウトか画面ロック。
5. 持ち出さない：個人の情報を、USB・個人のクラウド・個人の LINE・メールに移さない。
   画面の写真・スクリーンショットを撮らない。
6. 書かない：タグ・属性・メモに、病気・家庭の事情・成績など、人に知られたくないことを書かない。
7. 送る前に：一斉配信は、絞り込みの人数とテスト送信を確かめてから。迷ったら練習モード。
8. おかしいと思ったら：誤送信・知らないログインの知らせ・パソコンやスマホの紛失は、
   すぐ責任者へ（夜でも）。自分で消したり隠したりしない。
9. 辞めるとき：その日に運営メンバーから外す。手元に情報を残さない。
10. 見直し：年に1回、責任者がこの決まりと運営メンバーを見直す。

上の決まりを読み、守ることに同意します。　　年　月　日　氏名
```

## 点検表（年に1回・人が変わったとき）

- [ ] 運営メンバーの一覧に、辞めた人・役割の高すぎる人がいない
- [ ] 全員が二段階認証を登録している（`doctor`）
- [ ] 鍵の控えが、サーバーの外の安全な場所にある
- [ ] 暗号化バックアップを1つ取り出し、`backup:verify` で読める
- [ ] `audit:verify` が「切れていません」
- [ ] 方針（10-1）とこの文書が、いまの使い方と合っている
- [ ] Xserver アカウントの二段階認証がオン
