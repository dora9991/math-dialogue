# 数学ポータル（portal/）

生徒と先生の「入口」を1つにするページ。
小テスト（`../quiz/`）・応用チャレンジ（`../applied/`）・家庭学習ノート（`../home/`）を、**1回のログイン**で使えるようにまとめる。
Classi のような「ログインすれば、今日やることが全部見える」入口を、これまで作った道具を束ねて作る（作り直さない）。

## 画面

| ファイル | 役割 |
|---|---|
| `index.html` | **生徒用**。ログイン（小テストと同じID）→ **今日の授業**（先生が開始・配布した回の「小テスト」「振り返り」「学習時間」「応用チャレンジ」と、できたかどうか）／**いつでもできること**（家庭学習ノート・応用チャレンジ全8回）／**わたしの記録**（全ツールの記録を日付順に）。15秒ごとに自動で確かめるので、先生が授業を開始すると出てくる。 |
| `teacher.html` | **先生用**。先生ごとのID＋パスワード。担当クラスを選ぶ →「授業を開始」「小テストを配布」→ 生徒の入口のQRを投影 → **今日のようす**（名簿で未提出を正確に・要フォロー・振り返りを読む。20秒ごとに更新）→ 名簿（番号だけ）→ パスワードを忘れた生徒の救済。管理者は、先生の追加・担当クラス・パスワードの再設定。 |
| `back.js` | 公開するときに、各ツールの生徒画面へ「← 数学ポータル」を足す。 |
| `tools/deploy.cjs` | portal・quiz・applied・home を1つのサイトに組み立てて、Cloudflare Pages に出す。 |
| `schema.sql` | DB（`portal_` 接頭辞）。先生のアカウントと、番号だけの名簿。 |

## しくみ（なぜ1回のログインで済むのか）

- 生徒のアカウントは **quiz のもの**（学校コード＋出席番号＋パスワード、`quiz_accounts`）をそのまま使う。ポータルで新規登録しても、小テストで新規登録しても同じ。すでに小テストのIDを持っている生徒は、そのままログインできる。
- portal / quiz / applied / home を **同じサイト（同じドメイン）に並べて公開**する。ブラウザの保存場所（localStorage）はサイトごとに分かれているので、同じサイトにあれば、ポータルでのログインを3つのツールがそのまま読める。
  - `quiz:account_id` / `quiz:account_pw` … 小テスト（自動でログインする）
  - `applied:student` / `study:student` … 応用チャレンジ・家庭学習ノート（4桁の番号）
- 「この端末にパスワードを保存する」を外すと、パスワードはそのタブを閉じるまでだけ覚える（小テストを開くときに、もう一度聞かれる）。ログアウトすると、4つのキーをすべて消す。
- 各ツールのソースは、ほぼそのまま。変えたのは quiz の2か所だけ（応用チャレンジへのリンクを、同じサイトの中にあるときは同じサイトへ向ける／小テストと振り返りが両方開いているときにボタンがつぶれていたのを直す）。**今までの単独の公開（それぞれのQR）も、そのまま使える。**

## 先生のアカウント

- 先生ごとに ID ＋ パスワード（6文字以上。pgcrypto の bcrypt でハッシュ化し、平文は保存しない）。
- 先生は **担当クラスだけ** を見る・操作できる。**管理者** は同じ学校の全クラスを開け、先生を追加できる。
- パスワードを **10回続けて間違えると15分ロック**。管理者が新しいパスワードを設定すると、すぐに解ける。
- 呼び名は画面に出すだけ。本名でなくてよい（学校が特定される手がかりを増やさない）。
- 「授業を開始」「小テストを配布」は、小テスト管理（`quiz/teacher.html`）と同じ `quiz_state` を書く。どちらで切り替えても同じ。制限時間は小テスト管理で決めたまま。

## セットアップ（初回のみ）

1. quiz / applied / home の `schema.sql` が流してあること（math-labo-second に相乗りしているなら済んでいる）。
2. **`schema.sql`** を Supabase の SQL Editor に貼って Run（`portal_*` だけができる。足りないものがあれば、そこで止まって教えてくれる）。
3. **最初の管理者** を SQL Editor から作る（公開キーからは呼べない関数）:
   ```sql
   select portal_setup_admin('kazu', '6文字以上のパスワード', 'E-10', '呼び名');
   ```
   - 3つ目は、生徒に伝えている学校コード。
   - SQL Editor の履歴にパスワードが残るので、ログインしたら「パスワード変更」で変える。
   - 管理者がパスワードを忘れたときも、同じ文で設定し直せる（ロックも解ける）。
4. **公開**（リポジトリのいちばん上で）:
   ```bash
   node portal/tools/deploy.cjs           # 初回だけ先に：npx wrangler login
   ```
   Cloudflare Pages の `math-portal` に出る。名前がすでに使われていたら、`tools/deploy.cjs` の `PROJECT` を変える。
5. `https://math-portal.pages.dev/portal/teacher.html` に管理者でログイン →「先生の管理」で同僚を追加（ID・初期パスワード・担当クラス）→ 初期パスワードを口頭か紙で伝える。

## 授業での使い方

1. 先生：`teacher.html` → クラスを選ぶ → その回の「授業を開始」（小テストもやる回は「小テストを配布」も）。
2. 「QRを投影する」→ 生徒が読む → 初回だけ「新規登録」→ 今日の授業に「やること」が並ぶ。
3. 授業中は「今日のようす」が20秒ごとに更新される。名簿（人数）を入れておくと、まだの生徒の番号が出る。
4. 授業が終わったら「停止」。

## 手元で確かめる

```bash
python3 -m http.server 8793      # リポジトリのいちばん上で（portal は ../quiz などを読むため）
```
→ `http://localhost:8793/portal/`（生徒）／ `.../portal/teacher.html`（先生）。
「← 数学ポータル」のリンクは、公開用に組み立てたときだけ出る。組み立てた中身は `node portal/tools/deploy.cjs --out <フォルダ>` で見られる。
※ config.js は本番の Supabase につながっている（ほかのツールと同じ）。

## 制約・これから

- **1つの学校で使う前提**：家庭学習ノートと応用チャレンジは4桁の番号（学年・組・番号）しか保存していないので、先生画面ではこの2つを学年＋組で集計している。ほかの学校でも同じサイトを使うときは、この2つにも学校コードを保存する作り替えが要る。
- **くわしい分析は、まだ各ツールのPIN**：先生画面の「くわしい分析」は、これまでの先生画面へのリンク。1つの先生画面にまとめるのは次の段階。
- **教材は、いまは中1「比例と反比例」だけ**：ほかの学年・単元の先生が使うには、`quiz/quizdata.js` などに回を足す必要がある。
- **回の番号のずれ**：小テストは7回（4-1〜4-7）、応用チャレンジ・家庭学習ノートは8回（4章1〜8限目）で、同じ `M1-04-x` でも5回目からは中身がずれている（例：小テスト `M1-04-5` は「反比例」、応用チャレンジ `M1-04-5` は「比例のグラフ（効率）」）。ポータルは quiz と同じく同じ番号でつないでいる。応用チャレンジのめあてをそのまま表示するので、ずれは画面で分かる。
- **既存の割り切り**：quiz の生徒用RPC（`quiz_my_reflections` など）は、IDだけで読める作り。ポータルで新しく作った生徒用RPCは、毎回パスワードを確かめる。
