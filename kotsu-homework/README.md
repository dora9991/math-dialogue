# 宿題（先生）— コツコツくん

先生が、クラスや生徒に「この小単元を N問」「M分 学習」の宿題を出し、達成を見るための専用ページ。
公開先（予定）：`https://dora9991.github.io/math-dialogue/solo/teacher/homework/`（gh-pages の `solo/teacher/homework/`）。
プレーンな HTML / CSS / JS（ES モジュール）。外部ライブラリなし。スマホ（幅 360〜）と PC。
契約：`HW-CONTRACT.md`（4．RPC と 5．先生の画面）。進み具合の計算は、サーバーと生徒の画面が行い、このページは**表示するだけ**。

## 画面
| タブ | できること |
|---|---|
| ✏️ 宿題を出す | 宛先（クラス全員／生徒をえらぶ）・小単元（学年→章→単元、検索つき）・N問（1〜200）・M分（1〜240）・期間（既定：きょう〜あさって）・題（空なら自動）・ひとこと。入力のまちがいは、送る前に止めて、わかりやすく出す。出したら「出しました」と、いまの宿題へ |
| 📌 いまの宿題 | 一覧（出している／期限切れ／締めた／すべて、クラスのしぼりこみ、期限が近い順・新しい順）。達成○人・一部○人・まだ○人。1件をひらくと、生徒ごとの進み（番号・ニックネーム・バー・解いた問・時間・達成日・○△×・🎉達成）。「締める（取り消し）」「再開」「消す」 |
| 🟩 これまでの取り組み | マス目（行＝生徒・出席番号順／列＝宿題・古い順）。達成＝緑○・一部＝黄△・まだ＝赤×・期間前＝白・対象外＝しま。列ごと・行ごとの達成率。マスをタップで、○問・○分・達成日。スマホは横スクロール（番号とニックネームは固定） |

ハッシュで行き先が決まる：`#new`・`#list`（既定）・`#hw/<宿題id>`・`#grid/<クラスid>`。

## ログイン（先生の画面と同じ）
- `localStorage` の `kotsu-staff-v1`（`{token, user:{role,nick,login,id}, org:{code,name}, server, keep}`）を読むだけ（書きかえない・画面に出さない・URL に入れない）。
  `keep` を外したログインは `sessionStorage` にあるので、先生の画面から**同じタブで**来ること（`target="_blank"` にしない）。
- 先生の画面と同じく、保存された `server` が「いまのサーバーのURL」と同じときだけ使う。ちがうとき・ログインなし・生徒のログイン → 「先生の画面でログインしてください」＋リンク（`../`）。
- `{error:'auth'|'role'|'org_off'}` が返ったら、同じ案内（期限切れの文）。先生の画面でログインしなおしてこのタブにもどると、自動で読みこみなおす。
- サーバー：`?server=prod`／`?server=local`（`http://127.0.0.1:54473`）は先生の画面と同じ。localhost で開くと `local`、それ以外は本番。
  `?server=mock`（または `mock:<ポート>`）は、模擬のサーバー（`127.0.0.1` だけ）。

## 使っている RPC（`POST …/rpc/<名前>`、`Content-Profile: kotsu`）
先生の画面の既存：`t_home(p_token)`（担当のクラス：`classes:[{id,name,n,mine,…}]`・`org`・`me`）、`t_class(p_token,p_class)`（生徒：`students:[{id,no,nick,login,…}]`）。
宿題：`hw_t_create`・`hw_t_list`・`hw_t_detail`・`hw_t_grid`・`hw_t_close`・`hw_t_delete`（契約どおりの引数の名前）。

## 先生の画面（ホーム）から入るための案内（先生の画面への追加は、別に行う）
ホーム「担当のクラス」の上に、カード（または、タイトル横のボタン）：

> **📌 宿題を出す・見る**
> クラスや生徒に「この小単元を○問」「○分 学習」の宿題を出して、達成をチェックできます。これまでの取り組みは、マス目の一覧で見られます。
> 〔宿題のページをひらく〕

リンク先は `homework/`（先生の画面 `solo/teacher/` からの相対）。**同じタブで開く**（ログインを引きつぐため）。例：`<a class="k-btn sm" href="homework/">📌 宿題</a>`。
クラスの画面からは、そのクラスのマス目へ：`homework/#grid/<クラスid>`。

## 契約との関係で、決めたこと・迷ったこと（DB 側と合わせたいこと）
1. **`hw_t_list` の `missed`**：契約の文が崩れているので、「期限をすぎて、まったく取り組まなかった人数（`none` に入れない）」と読んだ。`partial` は期限後も `partial` のまま。画面は「達成／一部／まだ」＋あれば「期限切れ○人」を出す。
2. **`hw_t_delete`**：模擬は「出して 24時間以内、または、取り組んだ生徒が 0 人」だけ消せる。それ以外は `{error:'not_deletable'}`（画面は「締める」を案内）。DB 側の決めと、エラーの名前を合わせたい（知らないエラー名は「うまくいきませんでした（名前）」と出る）。
3. **マス目の「詳細（○問・○分）」**：`hw_t_grid` の cells には `pct`・`status` しか無いので、マスをタップしたとき `hw_t_detail` を呼ぶ（宿題ごとに 1回、画面の更新まで使いまわす）。
4. **色**：契約 5 の「期間中（薄い灰）」ではなく、依頼どおり 達成（緑）・一部（黄）・まだ（赤）・期間前（白）。期間前かどうかは、画面が `start_date` と日本時間の「きょう」で決める。対象でないマス（個人宛ての対象外）は、しま模様。
5. **個人宛て**：`class_id = null`・`user_ids`。一覧の「クラスのしぼりこみ」と、マス目（`hw_t_grid`）に、個人宛てが入るか（対象の生徒がそのクラスにいるとき）は契約に無い。模擬は入れる。個人宛ての `class_name` は null を想定。
6. **締めた宿題**：模擬は `hw_t_grid` に出さない（`hw_t_list` には `closed` つきで出る）。
7. **画面が足した入力の制限**：期限は「きょう以降」、期間は最長1年、題は60字（契約に無いが、画面で止める）。題が空のときは、画面が自動の題を作って送る（「単元名 N問」「単元名 N問・M分」「M分 学習」）。
8. 引数は、PostgREST が名前で関数を探すので、契約の名前そのまま。`hw_t_grid` は `p_from`・`p_to` を送らない（default の null）。
