## Mac での手順

> 作業中の Mac の作業ツリー（未コミットの `lesson-navi/` など）には触らず、このブランチを別の場所に取り出してから使う。**`git add -A` はしない。頼まれない限り commit しない。公開（デプロイ）しない。作業中は音を出さない（`--mute-audio`）。VOICEPEAK は同時に1本。`build-play.mjs` は直接実行せず `sh voice-queue.sh` だけ使う。**

```bash
# 1. このブランチの talk-g2/ だけを、一時フォルダに取り出す（作業ツリーは変わらない）
cd "<math-dialogue のリポジトリ>"
git fetch origin claude/eloquent-hypatia-j3tgfl
rm -rf /tmp/g2 && mkdir -p /tmp/g2 && git archive FETCH_HEAD talk-g2 | tar -x -C /tmp/g2

# 2. 台本を scenes/ にコピー（既にあるファイルは上書きしない）
sh /tmp/g2/talk-g2/install-g2.sh "<…>/lesson-navi/video/talk"

# 3. lessons.js に行を足す（ready:false）。/tmp/g2/talk-g2/lessons-g2-rows.txt の行を、既存の行の形と見くらべて貼る
```

4. **1本ずつ検査（音なし）**：`node check.mjs <ID> --shots`（⚠・✗ をなくす）。図のある授業は `python3 sheet.py <ID>` で写真を見て、重なり・はみ出しを直す。直すのは**レイアウトだけ**（図の高さ・左の列の行数・ページ分け `clear:true`・ラベルの位置）。**数学の中身（答え・数値・説明）は変えない。** 直したら `.check/<ID>.say.txt`（読み上げ一覧）も見る。
5. `.check/<ID>.say.txt` で、下の「耳で確認してほしい読み」にあたる行を見て、おかしければ `say:` で読みを直す。
6. 台本が最終になったものから、**章の順に** `sh voice-queue.sh <ID> …`（既存の147本の順番待ちの後ろに並ぶ）。1つの `voice-queue.sh` に複数のIDを渡すと、その順に作られる。
7. 声ができたら `python3 sync_ready.py`（`ready:true` にする）、`node test-play.mjs <ID>`（音なしの通しテスト）。
8. 朝の報告：声ができた授業・FAILED の授業・直したレイアウト・耳確認が必要な点を、短くまとめる。**公開（math-talk へのデプロイ）は、ユーザーが決めてから。**

## 判断が分かれる所（ユーザーに聞く／朝の報告に載せる）

1. `g2u3-13`（連立方程式と交点）の「平行なら交点なし」の一言、`g2u3-12` の「x＝−2 は y が x の関数ではないがグラフは直線」の一言、`g2u3-10` の最後の連立方程式の紹介（やや先取り・発展。不要なら削る）。
2. `g2u2-07`（解き方くらべ）の「いちばん速い道具」は、授業の中で基準を決めて出題している（主観を含む）。
3. `g2ch1-o09` は「一の位は0でない」の条件を付けた。`g2ch3-o10` は直線が満水（72cm）をこえた 84cm まで描かれている。`g2u3-04` の返し「左右には動きません」はやや強い言い切り（4択の正解は1つのまま）。
4. 7章の「箱が長い＝散らばりが大きい」は、四分位範囲の大小で言い切っている（ひげ込みの範囲とは逆になりうる。教科書の置き方に沿う）。「必ず言える（図から確実）／必ずしも言えない（図からは決められない）／言えない（図とくいちがう）」の定義の置き方で、どの台本も一貫している。
5. 6章 `g2ch6-o08` はくじを5本（当たり2本）にした（題材表の3本・7本ではなく、表で数えられるように）。
6. 5章 `g2ch5-n01` は、AD＝AE の証明が合同不要（引き算だけ）だったので、本題を DC＝EB の証明（△DBC≡△ECB）にした（AD＝AE はウォームアップ）。
