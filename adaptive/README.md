# つまずきナビ（仮称）— 適応型の算数・数学トレーナー【試作】

問題を解いていくと、**小2〜高3の算数・数学のうち「どこで」つまずいているか**を推定し、
**その人に合った難しさの問題**を出すブラウザアプリです。
ビルド不要の静的サイト（ES モジュール）で、既存の React アプリとは独立しています。

- 単元は 148、前提のつながりは 256 本、問題の型（テンプレート）は 270 個。
- 問題・図・解説は**すべてプログラムが自動生成するオリジナル**です（教科書・問題集・他社サービスの問題は使っていません）。
- 学習の記録は**この端末のブラウザの中だけ**に保存します（サーバーには何も送りません）。

> 名前は仮です。既存の商用サービス名に似せないよう、あえて別の名前にしています。

---

## 動かし方

```bash
# いちばん簡単：静的サーバーで adaptive/ を開く（Python があれば十分）
python3 -m http.server 8786 --directory adaptive
# → http://localhost:8786/ を開く      （.claude/launch.json の "adaptive" でも同じ）

# ダブルクリックで開ける 1 枚の HTML にまとめる（オフラインで動く。配るときに便利）
node adaptive/tools/build-single.mjs      # → adaptive/dist/tsumazuki-navi.html
```

`?seed=数字` を URL につけると、同じ順番で出題されます（動作確認用）。

### 使いかた

1. **ホーム**で学年を選び、**診断**をはじめる（12〜30 問。「わからない」は「わからない」と答える）。
2. **レポート**で、つまずきの源流・領域ごとの到達・よく出たまちがい方・学習プランを見る。
3. **マップ**で、148 単元の見立てを色で見る（クリックで詳細と「この単元を練習」）。
4. **練習**で、源流から順に取り組む（続けて間違えたら前提にさかのぼる）。
5. 問題の画面の**「気になる」**で、おかしな点・使いにくい点をその場で記録する（→ 一覧・Markdown 書き出し）。
6. **データ**で、記録の書き出し・読み込み・消去ができる。

## しくみ（やさしい説明）

```
 知識グラフ ──► 学習者モデル ──► 診断（次の1問を選ぶ）──► 練習（何をどの難しさで）──► レポート・マップ
 148単元・前提256本   単元ごとの4段階の状態     期待情報量が最大の問題        正答率75%を狙う              源流・到達・まちがい方
```

### 1. 知識グラフ（`js/data/graph_def.js`）
単元を点、「これが分かっていないと次に進みにくい」を矢印にした地図です。学習指導要領（公開情報）の並びと授業の経験から**自作**しました。
先生が読める・直せる、このアプリの中核です。前提の追加・削除は `tools/verify.mjs` が循環や学年の逆転を自動で検査します。

### 2. 学習者モデル（`js/core/model.js`）
- 各単元には、本人には見えない 4 段階の状態（未習／基礎／標準／発展）があると考えます。「習熟」＝標準以上。
- 状態が決まれば、問題の正答確率が決まります：`P(正解) = g + (1−g−slip)·σ(1.5·(力 − 問題の難しさ))`。
  `g` は当て推量で、数値入力 2％・複数欄 1％・選択式 30％。「わからない」は当て推量ゼロの不正解として数えます。
- 前提の単元が足りないと、その先の単元の高い状態が出にくくなります（前提が 1 段階足りないごとに 1/4）。
  そのため「下流でつまずいた → 上流のどれかが弱い → 上流の 1 つが弱いと分かれば他の疑いは晴れる」という**原因の切り分け**が、確率の計算として自然に起きます。
- 「全体的にできる子／苦手な子」「この領域が得意／苦手」も隠れた変数として持ち、数問の結果から**まだ出していない単元の見立てまで**傾けます。
- 計算はギブスサンプリング（乱数は固定 seed）。保存するのは**解答ログだけ**で、モデルは毎回ログから作り直します（パラメータを調整しても記録が生きます）。
- 時間がたつと証拠が薄まります（半減期 45 日。仮の値）。

### 3. 診断（`js/core/diagnose.js`）
全単元の「習熟しているか」のあいまいさを、**1 問でいちばん減らせる問題**（期待情報量が最大）を毎回選びます。
同じ単元の連続、難しすぎる問題、学年よりずっと上の単元は減点します。あいまいさが十分小さくなるか 30 問で終了します。

### 4. 練習（`js/core/practice.js`）
前提がそろっていて、まだ習熟していない単元（下流に苦手を多く抱える源流を優先）から出します。
難しさは期待正答率が 75％ 前後になるレベル。同じ単元で 2 回続けて間違えたら前提へさかのぼり、ときどき見直しを混ぜ、何度やっても進まない単元は保留にして先生への相談に回します。

### 5. 問題の作り方（`js/data/tpl/`）
テンプレートは `make(r, level)` という関数で、乱数から数値を選び、**答えを別の方法でも計算し直して確かめ**（数値微分・全数探索・展開して比較など）、
誤答の選択肢／誤答の値には「まちがいパターン（MC-…）」を付けます。
このため、間違えたときに「何が原因か」を返せ、モデルはそのパターンが指す前提単元にも証拠を送ります（`js/data/misconceptions.js`、583 件）。

## 検査（このリポジトリで自動でできること）

| コマンド | 内容 |
|---|---|
| `node adaptive/tools/verify.mjs --seeds 60 [--grouped]` | 全テンプレ×3難易度×種：KaTeX（strict）で描けるか、NaN/undefined がないか、正解が正解と判定され誤答が正解と混ざらないか、MC が辞書にあるか、問題のバリエーション |
| `node adaptive/tools/sweep.mjs --seeds 1200` | 乱数の種を大量に試して、問題の生成が例外で落ちないか（97 万回で失敗 0） |
| `node adaptive/tools/sample.mjs <単元ID…> --n 2` | 問題・選択肢・誤答・解説を文字で並べて、目で読んで確かめる |
| `node adaptive/tools/test-core.mjs` | 有理数・多項式・採点・乱数・学習者モデル（サンプリングと全列挙の一致）の単体テスト |
| `node adaptive/tools/simulate.mjs` / `simulate-practice.mjs` | 合成生徒での診断・練習の性能評価 |
| `node adaptive/tools/e2e.mjs` | 実ブラウザ（Playwright）で診断→レポート→マップ→練習→気になる→データを一通り操作（PC・スマホ・ダークモード） |
| `node adaptive/tools/render-audit.mjs` | 全テンプレを実ブラウザでスマホ幅に描いて、はみ出し・KaTeX エラーを探す |

### 合成生徒でのシミュレーション（`tools/simulate.mjs`、60 人、診断 30 問）
「習っていない穴があり、穴の下流は崩れやすい」仮想の生徒を、モデルの仮定とは別に書いて作り、
明らかに習熟／明らかに未習得の単元だけで集計しています（境界は除く）。

| 出題方法 | 分類の正解率 | つまずきの発見率 | 誤警報率（できている単元を弱いと判定） | Brier |
|---|---|---|---|---|
| 学年だけで見立てる（0 問） | 65％ | 86％ | 48％ | .226 |
| 単元をランダムに出す | 80％ | 77％ | 26％ | .145 |
| **このアプリの出題（期待情報量）** | **85％** | **84％** | **20％** | **.117** |

「源流」の再現率は 45％（ランダム出題 20％）、適合率は 53％（同 35％）でした。
**注意：これは仮想の生徒での数字で、実際の生徒での精度を保証するものではありません（仮想の生徒はモデルより素直に振る舞う分、楽観的になりがちです）。** 実データでの検証はこれからです（`docs/アダプティブ診断_気になる点.md`）。

## 単元・問題を足すには
1. `js/data/graph_def.js` に 1 行足す（ID・名前・領域・学年・前提・ポイント）。
2. `js/data/tpl/` にテンプレを書き、`tpl/index.js` に 1 行足す。`t("num" | "choice" | "fields", (r, level) => …, { id, db, finite })`。
   - 数式は `$…$`（KaTeX）。数式の中の日本語は `\text{}`。改行は `\n`。
   - 誤答には必ず MC を付け、辞書（`misconceptions.js`）に足す。`blame` は原因になる前提単元の ID（なければ null）。
   - 答えは別の経路でも検算する（`assert` / `nearly` / 全数チェック）。作れない組み合わせは `until` で作り直す（例外にしない）。
3. `verify.mjs` → `sweep.mjs` → `sample.mjs` で確かめる。

## 著作権・出典の方針（法的助言ではありません）
- 問題文・数値・図・解説は、このリポジトリのコードが生成するオリジナルです。教科書・問題集・入試問題・他社の教材や画面の文章・図は転載していません。
- 単元の体系と前提のつながりは、学習指導要領（公開情報）と授業の経験から自作しました。他社サービスの単元体系・データは使っていません。
- 数学の公式・定理は著作物ではありませんが、**言い回しや図の見せ方**が似ないよう、すべて自作の文面にしています。
- 公開・配布・有償化する場合は、念のため専門家に確認してください。

## ファイル構成
```
adaptive/
  index.html            画面の入口（KaTeX は vendor/ に同梱）
  css/app.css           スタイル（明暗・スマホ対応）
  js/app.js             ルーター・共有の状態
  js/core/              有理数・多項式・乱数・採点(items)・学習者モデル(model)・診断・練習・レポート・保存(store)
  js/data/              知識グラフ(graph_def)・まちがいパターン辞書・問題テンプレ(tpl/)
  js/ui/                画面（home / session / map / report / concerns / data）と表示部品(render, dom)
  tools/                検査・シミュレーション・ブラウザ確認・1 枚 HTML の生成
  vendor/katex/         KaTeX 0.16.11（MIT）
```
