# 数学小テスト・振り返り（1年4章 比例と反比例／QR配布・Supabase集計）

生徒が先生のQRコードから小テストを開いて解答し、結果がサーバー（Supabase）に
アカウントIDごとに蓄積されるツール。氏名は一切保存しない。ログイン後のホーム画面から、
その日の授業の理解度・意欲・小テストの点数・自由記入の「振り返り」も記録できる。

問題は数研出版1年4章「比例と反比例」の全7回（4-1〜4-7）。記述式は数式パーサで同値判定
（`2/5` と `0.4` のような表記ゆれも正解扱い）、方眼上の作図・双曲線のドラッグ入力にも対応。

## アカウント（ログイン方式）

学校名を一切保存・表示しないための「合言葉＋パスワード」方式。

- **ID の形式**：`E-101236` のように、**学校コード**（例 `E-10`＝先生が生徒に口頭・紙で伝える合言葉。
  アルファベット1文字＋数字1〜100を先生が決める）と、**出席番号4桁**（例 `1236`＝1年2組36番）を
  連結したもの。**学校名そのものはコード・コメント・Obsidianを含めどこにも書かない**（下記「運用上の注意」参照）。
- 初回は「新規登録」で 学校コード＋出席番号＋パスワード（4文字以上・確認欄あり）を設定。
  パスワードは Supabase 側で `pgcrypto` によりハッシュ化して保存（平文は保存しない）。
- 「この端末にパスワードを保存する」にチェックすると、次回から自動でログインする。
  チェックしなかった場合も **ID だけはこの端末に残る**（次回はIDが入力済みでパスワードだけ聞かれる）。
- パスワードはあくまで「この生徒がこの端末から使っている」ことをゆるく確認するためのもの
  （Supabase Authは使わず、ログイン確認RPCを1回叩くだけの軽量方式）。既存の「4桁を選ぶだけ」の頃と
  同様、なりすまし対策としての強度は高くない前提——低リスクな教具として割り切った設計。

## しくみ

- **生徒** `index.html`
  - 初回は「新規登録」→ 次回以降は保存されたIDでログイン（パスワードも保存していれば自動ログイン）
  - **小テストは、教師が「配布」を押したものしか見えない・受けられない**。ホーム画面には配布中のテストだけが並び、
    QRコード（`?quiz=M1-04-2` のようなURL）を読むとそのテストへ直接入る。配布前は「先生が開始するのを待っています…」
    と表示され、配布された瞬間に自動で始まる（4秒おきに確認）
  - 採点はブラウザ内で行い、結果だけをサーバーに送信する（問題データ自体はアプリに同梱されているため、
    正答を事前に隠す設計ではない。配布ロックの目的は「勝手に先の単元を進めさせない」こと）
  - **同じ小テストは日本時間で1日1回まで**。日付が変われば再挑戦できる（DBのユニーク制約で二重防止）
  - 別のテストのQRを読んでも、ログイン状態はこの端末で自動的に引き継がれる
  - **小テストの配布と「授業を開始」（振り返り受付）は完全に独立**：小テストを配布しても振り返りボタンは
    出ない。振り返りボタンが出るのは、先生が「授業を開始」（旧・振り返りだけ実施カード）でその回を
    ONにしたときだけ。小テストだけ配布中で授業が未開始のときは、小テストのボタンだけが押せる。
    授業は開始済みだが小テスト未配布のときは、小テストの場所に「小テストは未配布」という灰色の
    プレースホルダーが出て、振り返りボタンだけが押せる（`ACTIVE`/`REFLECT_ACTIVE`を別々に判定）
  - **振り返り**：「今日の気分」ではなく**その授業の振り返り**。「授業の理解度」「意欲・態度」
    （各4段階のボタン）「今日の小テストの点数」（任意）「振り返り記入欄」（質問や困っていることも
    書いてよい旨を明記・任意）を記入して保存。同じ授業・同じ日にもう一度書くと上書き
    （reflection-sheet/ と同じ、書き直しOKの方針）。**「授業を開始」が停止されると、その振り返りも
    新規記入・上書きができなくなる**（サーバー側の `quiz_reflection_submit` が配布状態を見て拒否する）
  - **記録**：ログイン後、ホーム画面下部の「📋 今までの記録を見る」から、授業（小テストの回）ごとに
    「小テストの結果」と「その回の振り返り」をまとめて見られる。**満点でない小テストにだけ**
    「🔁 もう一度挑戦する」ボタンが出る（満点なら出ない）。配布中かどうかは関係なく挑戦でき、
    **結果はサーバーに送信・記録されない**（教師の集計や1日1回の制限に影響しない、生徒個人の練習）
  - **振り返りの評価（reflection-sheet/ と同じ仕組み）**：保存時にブラウザ内の簡易ルールで6観点
    チェック（具体性・つまづきの自覚・次の一手・問いの発生・前回との接続・学び方の工夫）を行い、
    ⚠要フォロー（SOS・空回りの兆候）／⭐得意サイン／📋コピー使い回しの疑いを判定。保存後すぐに
    問い返し（💬）を1つ本人に返し、「記録」画面でも過去の振り返りと一緒に確認できる
    （`reflAnalyze()`。判定はクライアント側で計算し結果だけをサーバーに保存する）
  - **振り返り送信後のお祝い演出**：「入力できました！」＋励ましの一言（ランダム）＋絵文字が
    浮かび上がるCSSアニメーション（`celebrateBurstHTML()`）
  - **授業が開始されると出る「暇な時間カード」**：教師が「授業を開始」を押した回は、生徒のホームに
    「🎉 授業が開始されました」というカードが出る（小テストの配布状態とは無関係——小テストが
    未配布でも出る。`idleCardHTML()`）。①今日の学習時間を5/10/15/20/30分ボタン（右に「その他」欄が
    並ぶ）で選ぶか自由入力し、**家庭学習で頑張ったこと（任意の自由記述）**もあわせて1つの
    「記録する」ボタンで送信（`quiz_study_time_submit`、`quiz_study_time`テーブルに`note`列として保存）
    ②**応用チャレンジ**（`applied/`、別デプロイ）のその回の問題セットへ直接リンク（同じ回番号
    M1-04-xを共有）③「記録」画面（自分の過去の結果・振り返り）へのショートカット④**確認問題5問**：
    数学ラボ2「はいちモード」の確認問題と同じ発想（5問すべて正解で合格）。**開始された回に関係する
    類似問題**を、応用チャレンジのデータ（`appliedProblems.js`＝`applied/problems.js`のコピー、
    入試・実力レベルの類似問題）から優先的に出題し、無ければその回のquiz本体の問題も混ぜる
    （`confirmQuizPool()`）。図が必要な問題は文章だけでは意味が通らないため除外。1問ずつ即採点・
    自動で次へ進み、サーバーには送らないその場の腕試し用（`renderConfirmQuiz()`、既存の`gradeSub()`
    採点ロジックを流用）⑤**60秒計算チャレンジ**：自分（🧑）は左端に固定、敵（😈💣）は右側から現れ、
    時間が経つとじわじわ左（自分側）に迫ってくる。正解すると答えた速さに応じて敵をドンと右へ
    押し返し（💥エフェクト＋弾む演出）、右端まで押し出すと撃退＝新しい敵が上から降ってきてまた
    押してくる、という押し合いのアニメーション（`renderMiniGame()`）。サーバーには送らない気分転換用
- **教師** `teacher.html`
  - PIN でログイン →「小テストの配布管理」で7回分の配布ON/OFFとQR表示 → 結果ダッシュボード
    （テスト一覧／生徒別／問題別／未提出／**振り返り**、いずれもクリックでドリルダウン）→ Excel出力／投影モード
  - **ボーナス（★応用）問題の正答率**：ボーナス問題は配点を増やさない設計（`max_score`が常に0）のため、
    素の`score/max`計算だと必ず0%になってしまう。集計は`qPct()`で「正解した人数の割合」に自動で
    切り替わる（問題別タブ・Excel出力の問題別シート）。投影モードの「正答率の低かった問題」は
    ボーナス問題自体を対象外にしている（配点目的が違うため）
  - **操作するクラスを選ぶ（重要）**：ログイン後、一番上の「操作するクラスを選ぶ」カードで
    学校コード（例 `E-10`）と学年・組を選んでから操作する。**配布・授業開始・制限時間の変更は、
    ここで選んだクラスだけに効く**（以前は学校・クラスに関係なく全員に配信されていた点を修正）。
    「最近使ったクラス」に履歴（最大6件）が残り、次回はワンクリックで選び直せる（localStorage保存）。
    クラス未選択のうちは、配布管理の中に「↑クラスを選んでください」という案内が出る
    （カード自体は常に表示。以前はカードごと非表示にしていて分かりにくかったため変更）
  - **「授業を開始」ボタン（配布管理の各行、制限時間の左）**：小テストの「配布」ボタンとは別の
    トグルで、押すとその回の振り返り・学習時間記録・確認問題5問が選んだクラスの生徒に開放される
    （小テスト本体の配布状態とは独立。行には「小テスト 配布中/停止中」「授業 開始中/未開始」の
    2つのバッジが並ぶ）。小テストも受けさせたい回は、隣の「配布」ボタンも別途押す
    （`quiz_set_reflection_active`）
  - **配布管理の制限時間**：各回の「配布」ボタンの隣に「制限時間 ◯分」の入力欄がある。値を変えると
    配布中でもその場で反映され（`quiz_set_active`のp_time_limit_sec）、生徒が「はじめる」を押した瞬間の
    設定が使われる。何も変更しなければquizdata.jsの既定値（分単位に換算して表示）のまま
  - **今日の学習時間（ランキング）**：「小テストの配布管理」カードの上部にある
    「📊 今日の学習時間を見る」ボタンで、選んだクラスの今日の学習時間まとめ（平均・ベスト3・
    生徒ごとの記録一覧・家庭学習で頑張ったことのメモ）を表示。投影してその場でフィードバックできる
    （`quiz_study_time_summary`）
  - **配布管理から振り返りへ**：各回の「振り返りを見る」ボタンを押すと、「振り返り」タブへ移動し、
    自動でその回（テスト）に絞り込まれる（「振り返り」タブの一覧・フィルタも授業＝quiz_id 単位）
  - ダッシュボードの生徒一覧・詳細は、IDから出席番号部分だけを取り出して「1年2組3番」のように表示する
    （`accountLabel()`。学校コード部分は画面には出さない）
  - **絞り込みフィルタ**：学校コード（例 `E-10`）・クラス・テスト（授業の回）の3段階で絞り込める。
    複数の学校が同じサイトを共有しても、教師は自分の学校コードを選べば自校のデータだけに絞れる
    （`schoolOf()`）。「振り返り」タブでも同じフィルタで**授業ごとに**絞り込める
  - **振り返りタブ**：理解度が「１　全くわからない（ヘルプ！）」だった生徒は、今日の分が上部に名前付きで
    ピックアップされ、一覧の行も赤く強調される（`vReflections()`）。⚠要フォロー／⭐得意サイン／
    📋コピー使い回しの疑いのバッジと、生徒に返した問い返しもコメント欄に表示される。各行に**削除ボタン**
    があり、生徒の入力ミスの申告を受けたときに1件だけ消せる（`quiz_reflection_delete`、確認ダイアログあり）。
    クイック絞り込み（すべて／⚠要フォロー／⭐得意／📋コピー疑い）と、列見出しクリックでの並び替え
    （日付・授業・生徒・理解度・意欲・点数）にも対応
  - **投影モード**：得点の集計に加えて「今日の振り返り」も表示（理解度・意欲の平均と、4〜1段階ごとの
    人数の内訳）。個人名やコメントは出さず、集計のみ（現在のフィルタ＝学校・クラス・テストに連動）
  - **パスワードを忘れた生徒の救済**：「小テストの配布管理」の下にあるカードにIDを入力してリセットすると、
    そのアカウント（ID×パスワード）だけが削除される。本人は同じIDで「新規登録」からやり直せば元通り
    使える。**成績・振り返りの記録は消えない**（`quiz_accounts`と`quiz_attempts`/`quiz_reflections`は
    account_idで緩く結びついているだけで外部キー制約が無いため）
- **サーバー** Supabase
  - テーブルは RLS で全面ロック。読み書きはすべて `security definer` の RPC 経由
  - anon key は公開前提のキーなので config.js に直書きしてよい

## 運用上の注意（重要・学校名を出さないための唯一の弱点）

**「学校コード（例 `E-10`）が、実際にどの学校を指すか」という対応表だけは、このリポジトリにもObsidianの
共有可能なノートにも絶対に書かないこと。** 覚えておくか、リポジトリに含めない私用メモにだけ残す。
これが漏れると、コードの意味そのものが特定されてしまい、匿名化の意味がなくなる。

## 相乗り構成について（重要）

このツールは **math-labo-second（数学ラボ2）の既存Supabaseプロジェクトに相乗り**する前提で作ってあります
（無料枠のプロジェクト数上限のため新規作成できなかった経緯）。既存の `attempts` / `feedback` /
`player_state` / `students` と衝突しないよう、小テスト用のテーブル・関数はすべて **`quiz_` 接頭辞**で
隔離しています（`quiz_state` / `quiz_attempts` / `quiz_attempt_rows` / `quiz_settings`、関数は `quiz_*`）。
専用スキーマではなく `public` に接頭辞で置いているため、Supabaseのスキーマ公開設定は不要です。

小テスト側が保存するのは番号のみですが、同じDB内に数学ラボ2の氏名データ（`students.name` 等）が
共存する点は認識しておいてください（テーブルは別・RLSも別なので相互に読めません）。

## 授業での使い方

1. 先生: `teacher.html` を開き PIN でログイン →「操作するクラスを選ぶ」で学校コード・学年・組を選ぶ
   （2回目以降は「最近使ったクラス」から1クリックで選べる）
2. 先生:「小テストの配布管理」で、その回の「授業を開始」を押す（振り返り・学習時間記録・確認問題5問が
   開放される）。小テストも受けさせたいときは、隣の「配布」も別途押す
3. 「QR表示」でプロジェクター等に投影
4. 生徒: QR を読む →（初回のみ「新規登録」でID・パスワードを設定／2回目以降はログイン）→ 解答 → その場で採点結果が見える
5. 先生: ダッシュボードの各タブで結果を確認。授業後は「停止」しておくと同じQRからは入れなくなる
6. 入力ミス等で本人から申告があれば、Supabase の SQL Editor から
   `select quiz_allow_retry('PIN','M1-04-2','E-101203');` のようにIDを渡すと当日分だけ再挑戦を許可できる

## 問題の追加・変更

問題データ・採点ロジック・図形描画はすべて `quizdata.js` の `CH` 配列にある
（生徒ページ・教師ページの両方から読み込まれる共通ファイル）。新しい章を追加する場合は
`CH` に要素を追記するだけでよく、DB側の変更は不要（配布管理画面に自動で行が増える）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 生徒用ページ（出題・採点・結果表示） |
| `teacher.html` | 教師用ページ（配布管理・QR・結果ダッシュボード・Excel出力） |
| `quizdata.js` | 問題データ・数式パーサ・採点ロジック・図形描画（両ページ共通） |
| `appliedProblems.js` | `applied/problems.js` のコピー。「確認問題5問」の類似問題データ（`window.SETS`） |
| `common.js` | Supabase RPC 呼び出しヘルパー（`window.Quiz`） |
| `config.js` | Supabase 接続情報（要書き換え） |
| `schema.sql` | DB初期化スクリプト（SQL Editor に貼る） |
